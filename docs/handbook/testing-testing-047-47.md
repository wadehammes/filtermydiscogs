
### Jotai state in components

- **Read** filter/view slices via [`useFilterAtoms.hook.ts`](../../src/hooks/useFilterAtoms.hook.ts) and [`useViewAtoms.hook.ts`](../../src/hooks/useViewAtoms.hook.ts)—not **`useFilters()`** / **`useView()`** in new app code (Biome guardrail; context modules and tests exempt).
- **Write** filter actions via **`useFiltersDispatch()`**; view changes via **`useViewDispatch()`**.
- **Release list**: read **`useAllReleases()`** from filter atoms; only **`useCollectionData`** (and **`useCollectionReset`**) should dispatch **`SetAllReleases`**. **`useCollectionData`** uses raw **`filtersDispatchAtom`** so collection pagination does not PATCH account preferences.
- **PO mocks**: when asserting dispatch in isolation, mock **`src/hooks/useFilterAtoms.hook`** (see `SearchBar.po.tsx`, `ReleaseCard.po.tsx`) rather than **`useFilters()`**.

### Test data and factories

See **[factories.md](factories.md)** for the full factory pattern (`BaseFactory`, `KeysMatch`, `nullish`, nested factories, one file per factory).

**Required in hook specs, feature tests, and E2E:** any Discogs release, track, collection item, crate payload, or API JSON body in a spec or **`e2e/helpers/`** MSW stub should come from a factory or shared E2E builder ([`e2eCollectionData`](../../src/tests/msw/e2eCollectionData.ts), [`e2eReleaseDetailData`](../../src/tests/msw/e2eReleaseDetailData.ts), [`e2eReleaseHandlers`](../../src/tests/msw/e2eReleaseHandlers.ts)) unless you are asserting on a one-field edge case—and even then, start from `.build()` and override that field. Inline object literals for domain types are a review failure. [`handbookTestRules.ts`](../../src/tests/utils/handbookTestRules.ts) scans **`src/**`** feature tests and **`e2e/helpers/*.ts`** / **`e2e/*.spec.ts`** for inline **`DiscogsVideo`** / **`DiscogsTrack`** literals.
- **E2E track position alignment:** Playlist / **`UserTrack`** MSW rows that playback resolves via **`GET /api/release/:id`** must use the same Discogs **`track.position`** strings as [`buildE2eReleaseDetailByDiscogsId`](../../src/tests/msw/e2eReleaseDetailData.ts) — import **`E2E_RELEASE_TRACK_POSITION`** (not ad hoc **`A1`** vs **`A`**) in [`handlers/publicPlaylist.ts`](../../src/tests/msw/handlers/publicPlaylist.ts), [`e2eTrackRowTitle`](../../src/tests/msw/e2eReleaseDetailData.ts), and related E2E specs ([`public-playlist.spec.ts`](../../e2e/public-playlist.spec.ts) uses **`formatTrackPositionTitle(E2E_RELEASE_TRACK_POSITION, …)`**). Playlist batch hydrate E2E: [`handlers/publicPlaylist.spec.ts`](../../src/tests/msw/handlers/publicPlaylist.spec.ts) locks **`buildE2eDemoPublicPlaylistResponseWithoutDisplayArt`**; [`discogsReleaseBatchResilience.ts`](../../e2e/helpers/discogsReleaseBatchResilience.ts) + [`e2eReleaseHandlers.ts`](../../src/tests/msw/e2eReleaseHandlers.ts) partial-batch MSW — assert remainder refetch with **`waitForRequest`** body predicates (multi-id vs single-id **`ids`**), not assumed POST ordering when hydration overlaps.
- Factories live only under **[`src/tests/factories/`](../../src/tests/factories/)**.
- Import singletons by path (e.g. `releaseFactory` from `src/tests/factories/Release.factory`).
- Override with `.build({ field: "literal" })` for values the spec asserts on.
- **Always use factories** in tests and POs—domain entities, API response shapes, and nested objects come from **`src/tests/factories/`**, not inline object literals.
- **Nested release detail rows:** build **`DiscogsVideo`** with **`discogsVideoFactory.youtube({ … })`** (or **`nonYoutube()`**), **`DiscogsTrack`** with **`discogsTrackFactory.build({ … })`**, and per-track **`artists`** with **`artistFactory.build({ … })`**—compose into **`discogsReleaseJsonFactory.withTracklistAndVideos({ … })`**, **`setupFetchDiscogsReleaseMock`** payloads, or hook/provider harness params. Override only fields the test asserts on (title, **`uri`**, position, etc.).
- Use **preset methods** on factories for common test shapes (e.g. `releaseFactory.withDisplayDefaults()`, `discogsReleaseJsonFactory.withTracklistAndVideos()`, `cratesResponseFactory.empty()`) instead of ad-hoc PO builder methods or repeated inline `.build({ ... })` blocks.
- **Prisma select-shaped mocks** (`findMany` / `findUnique` with **`select`**, **`update`** / **`upsert`** return rows): build payloads with **`Prisma.*GetPayload`** row factories in [`src/tests/factories/`](../../src/tests/factories/) (e.g. **`crateIdRowFactory`**, **`crateReleaseFactory.crateIdFindManyRow`**, **`userTrackPrismaFactory`**) and assign via [`mockPrismaDelegate`](../../src/tests/helpers/mockPrismaDelegate.ts) — do not cast partial rows with **`as never`**. **`validateReleaseDataForStorage`** successes in route specs use **`releaseValidationResultFactory.success(release)`**. External SDK stubs (Stripe checkout) use **`stripeCheckoutClientStubFactory`** + **`asStripeClient`** ([factories.md](factories.md)).
- **`releaseFactory`**: pass partial **`basic_information`** on **`.build()`** / presets; do not spread another release’s **`basic_information`** — merge via **`basicInformationFactory`** ([factories.md → `releaseFactory` overrides](factories.md#releasefactory-overrides)).
