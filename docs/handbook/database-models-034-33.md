**`PlaylistReleaseSnapshot`** — per-playlist **`release_data` JSON** keyed by collection **`instance_id`** (same validation shape as **`CrateRelease`**). Rows and owner **`crate_releases`** snapshots parse through **`toValidatedPublicPlaylistRelease`** in [`release-data-validation.ts`](../../src/lib/release-data-validation.ts) (**`validateReleaseDataForStorage`** + **`toPublicPlaylistReleaseSnapshot`**). **`persistPlaylistReleaseSnapshots`** upserts validated releases via **`toPrismaInputJsonValue`** ([`toPrismaJsonValue.ts`](../../src/utils/toPrismaJsonValue.ts)) — same **`InputJsonValue`** cast as crate release routes ([`crates/[id]/releases`](../../src/app/api/crates/[id]/releases/route.ts), membership PUT). [`loadPlaylistReleaseSnapshots`](../../src/lib/playlist-release-snapshot.server.ts) merges with crate rows in [`loadPublicPlaylist`](../../src/lib/public-playlist-load.server.ts): for each **`instance_id`**, a playlist snapshot **replaces** an owner crate snapshot in the merged map. **`persistPlaylistReleaseSnapshots`** runs on **`POST /api/playlists/[id]/tracks`** when the client sends optional **`release_snapshot`** ([`buildAddPlaylistTrackBody`](../../src/utils/buildAddPlaylistTrackBody.ts)) or when [`ensurePlaylistReleaseSnapshotOnTrackAdd`](../../src/lib/ensure-playlist-release-snapshot-on-add.server.ts) loads art from the owner’s **`crate_releases`** row, and on **`discogsHydration: "full"`** (public API / full loader) after **`hydratePublicPlaylistReleases`**. That keeps cached page/OG **`snapshotsOnly`** loads from needing client **`POST /api/release/batch`** for cover art. Public **`snapshotsOnly`** loads may also warm missing thumbs via **[`backfillMissingDisplayArtInSnapshotMap`](../../src/lib/public-playlist-discogs.server.ts)** (capped — see [Public playlists](#public-playlists)). Persist failures on add use **`reportInfrastructureFailure("public_playlist", …, { operation: "ensure_playlist_release_snapshot_on_add" })`**; full-load backfill uses **`public_playlist` / `persist_playlist_release_snapshots`** — not **`console.error`** alone.

Adding the same track twice: **dedupe** by **`track_key`** per playlist (reject or no-op on second add).

**API / UI stack:** migration → playlist CRUD routes → **`api.*`** + React Query → **`ReleaseTrackRowMenu`** “Add to playlist” → **`/collection`** side panel (**`CollectionSidePanelToggle`**, **`PlaylistDrawer`** with **`useReorderPlaylistTracksMutation`**). Optional later: **`PlaybackQueueDrawer`** “Save queue as playlist”.

Hydration uses **`useAllReleases()`** + [`playlistPlayback.ts`](../../src/utils/playlistPlayback.ts) (**`collectPlayablePlaylistEntries`**). DnD reorder can sync upcoming via **`syncPlaylistQueueToTrackOrder`**. Release **Add all to queue** appends without clearing upcoming unless the listener already cleared it ([patterns.md → Release playback queue](patterns.md#release-playback-queue)).
