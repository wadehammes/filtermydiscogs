**Request validation:** Zod schemas live under [`src/lib/validation/`](../../src/lib/validation/). [`configureBrowserZod`](../../src/lib/validation/configureBrowserZod.client.ts) runs from [`instrumentation-client.ts`](../../src/instrumentation-client.ts) and sets **`jitless: true`** so client parses never probe **`Function("")`** under production CSP; server schemas keep JIT. API routes use [`parseRequestBody`](../../src/lib/validation/parseRequestBody.ts) where applicable. Schemas cover crate CRUD/layout/sync/migrate (**`crateLegacyMigrateBodySchema`**), playlist CRUD + tracks ([**`playlist.schemas.ts`**](../../src/lib/validation/playlist.schemas.ts)), membership PUT (**`setReleaseCrateMembershipBodySchema`**), release batch (**`releaseBatchBodySchema`** in [`release.schemas.ts`](../../src/lib/validation/release.schemas.ts)), user preferences (**`userPreferencesPatchSchema`**), user contact (**`userContactPatchSchema`** in [`userContact.schemas.ts`](../../src/lib/validation/userContact.schemas.ts)), collection note/rating writes, crate release snapshots, admin user lookup (form + route username check), YouTube oEmbed query (**`youtubeOembedQuerySchema`** / **`youtubeVideoIdSchema`** in [`youtube.schemas.ts`](../../src/lib/validation/youtube.schemas.ts)), and form inputs. **React Hook Form** + **`@hookform/resolvers/zod`** back crate create/rename, release-notes editors/scratchpads, crate set notes, collection search, crate layout marker labels, admin user lookup (**`adminUserLookupFormSchema`**), admin YouTube embed test (**`adminYoutubeEmbedFormSchema`** in [`adminYoutubeEmbed.schemas.ts`](../../src/lib/validation/adminYoutubeEmbed.schemas.ts)), and **`TrackYoutubeOverrideDialog`** (**`trackYoutubeOverrideFormSchema`** in [`userTrack.schemas.ts`](../../src/lib/validation/userTrack.schemas.ts)). Client form schemas must **`tsc:ci`** with **`useForm<z.infer<typeof schema>>`** — see [conventions.md → RHF + Zod typing (non-negotiable)](conventions.md#react-hook-form--zod-typing-non-negotiable) (no **`z.coerce.*`** on RHF-bound fields). Prefer extending those schemas (and route/form specs) over ad-hoc validation—keep forgiving parsers for stored/read paths (e.g. **`parseUserPreferences`**, localStorage filters).

**Pagination:** Crate list/detail/public GET handlers accept **`?all=true`**. [`getPaginationParams(request, { allMaxTake })`](../../src/lib/api-helpers.ts) and [`wantsAllResults`](../../src/lib/api-helpers.ts) return a single page capped by **`CRATE_LIST_ALL_MAX`** / **`CRATE_DETAIL_ALL_MAX`**; client helpers in [`src/api/endpoints/crates.ts`](../../src/api/endpoints/crates.ts) use **`?all=true`** instead of client-side pagination loops.
