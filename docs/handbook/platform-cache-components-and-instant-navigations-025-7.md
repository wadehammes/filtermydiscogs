**E2E YouTube embed mock** (when **`NEXT_PUBLIC_E2E_MOCK_YOUTUBE_EMBED=1`**, set by **`pnpm build:e2e`** and Playwright **`webServer`**): [`buildYoutubeEmbedUrl`](../../src/utils/releasePlayback.ts) serves **`/e2e/youtube-embed-mock.html`** instead of **`youtube.com`**. **`shouldUseE2eMockYoutubeEmbedForVideo`** also routes reserved harness ids from [`e2eEmbedMock.constants.ts`](../../src/constants/e2eEmbedMock.constants.ts) (including MSW default **`e2eNorm0001`**) to the mock page even without the global flag (so Playwright can reuse a local **`next dev`** server). With the flag set, any video id can be mocked via **`buildYoutubeEmbedUrl`**. Reserved ids in [`e2eEmbedMock.constants.ts`](../../src/constants/e2eEmbedMock.constants.ts) are **exactly 11 characters** (same as real YouTube ids — longer ids are truncated during extraction and lose **`mode`**). The mock page exposes **E2E simulate YouTube pause** ( **`infoDelivery`** with **`playerState: PAUSED`** and **`currentTime > 0`** ) and mirrors **`pauseVideo`** / **`playVideo`** commands, updates **`currentTime`** on **`seekTo`**, and ignores **`setVolume`** / **`mute`** / **`unMute`** (dock volume is exercised via **`localStorage`**, not the mock). While **`transportPaused`**, embed sync commands (**`getPlayerState`**, **`getCurrentTime`**, …) do **not** re-arm the ~350ms **PLAYING** interval — only **`playVideo`** clears pause (avoids racing **PAUSED** vs **PLAYING** in [`authenticated-playback-transport-sync.spec.ts`](../../e2e/authenticated-playback-transport-sync.spec.ts)). They map to query **`mode`**: **`normal`** (default postMessage **`PLAYING`**), **`silent`** (no iframe messages — baseline for embed-unavailable watchdog skip copy), **`error`** (**`onError` 100** → private/removed skip), **`delayed`** (**`PLAYING`** after **`delayMs`**, default **`E2E_EMBED_MOCK_DELAYED_PLAYING_MS`** — must stay above the fastest embed watchdog, locked in [`e2eEmbedMock.constants.spec.ts`](../../src/constants/e2eEmbedMock.constants.spec.ts); full-suite **no-skip** waits use **`e2eWatchdogNoSkipWaitMs()`** / **`e2eWatchdogDelayedNoSkipWaitMs()`** (~17s desktop-fast budget, not slow-network **`e2eWatchdogSkipVisibleTimeoutMs()`** used when asserting skip copy appears)). The **silent embed contract** in [`releasePlayback.context.spec.tsx`](../../src/context/releasePlayback.context.spec.tsx) (watchdog skip when the iframe never posts player messages) pairs with E2E **`mode=silent`** wiring + unavailable skip copy ([`authenticated-embed-watchdog.spec.ts`](../../e2e/authenticated-embed-watchdog.spec.ts)); **`notifyPlaybackVideoPresentationReady`** clears loading UI and runs **`confirmEmbedPlaybackIfAudible`** only (same-video iframe re-sync must not blind-**`confirmEmbedPlayback`** on silent mocks — see [patterns.md → Watchdog and same-upload advance](patterns.md#release-playback-queue)). **`e2eWatchdogSkipVisibleTimeoutMs()`** in [`embedWatchdog.ts`](../../e2e/helpers/embedWatchdog.ts) budgets slow-tier watchdog arms, loading re-arms, **`PLAYBACK_EMBED_INITIAL_PRESENTATION_WATCHDOG_GRACE_MS`**, sync-probe recheck, and after-skip bonus when asserting skip copy appears.
