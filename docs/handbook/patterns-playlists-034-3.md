- **Playback**: [`usePlaylistPlayback`](../../src/hooks/usePlaylistPlayback.hook.ts) + [`playlistPlayback.ts`](../../src/utils/playlistPlayback.ts) with **`useAllReleases()`**. Playable rows hydrate via **`collectPlayablePlaylistEntries`** / **`planPlaylistPlaybackStart`**. **`PlaylistDrawerTracks`** holds the single hook instance and passes **`onPlayTrack`** into rows. **Play** (footer) and **row play** **`orderPlaylistTracks`**, then **`planPlaylistPlaybackStart`** → **`clearQueue()`**, **`startPlayback`** with **`upcomingQueue`** for later rows (**`rebuildAlbumQueue: false`**, **`startPaused: false`**) in playlist order (not album order). **Queue** (footer **`addPlaylistToQueue`**) never clears or replaces upcoming: when transport is active it **`addToQueue`**s each playable row; otherwise it mirrors release **Add all to queue** (**`startPlayback`** on the first row, then **`addToQueue`** for the rest). Skipped-not-in-collection rows use **[`showPlaylistSkippedNotInCollectionToast`](../../src/utils/playlistToast.ts)** (copy from [`playlistPlaybackCopy.constants.ts`](../../src/constants/playlistPlaybackCopy.constants.ts) — governed in [`userFacingCopy.registry.ts`](../../src/constants/userFacingCopy.registry.ts)); success uses **`showPlaybackQueueSuccessToast`**. After DnD reorder, **`syncPlaylistQueueToTrackOrder`** rebuilds upcoming when the session already follows playlist order (**`shouldSyncUpcomingQueueToPlaylistOrder`**). Spec: [`usePlaylistPlayback.hook.spec.ts`](../../src/hooks/usePlaylistPlayback.hook.spec.ts) (including skipped-track toast copy). Same **`PlaybackQueueItem`** rules as release queueing ([Release playback queue](#release-playback-queue)).
