## Rate limits and errors

Discogs may return **429** (rate limit) or **5xx** (upstream errors). Read proxies map upstream **5xx** to **502** with a shared user-facing message ([`mapDiscogsUpstreamToProxyStatus`](../../src/lib/discogs-api-error.ts)); clients treat **502** / **503** / **429** as transient for release/collection retries where configured. Discogs read proxy **`catch`** blocks should build JSON via [`buildDiscogsProxyErrorPayload`](../../src/lib/discogs-api-error.ts) (`{ error, fallbackMessage }` — 429 copy, upstream **502** message, dev **`details`**, optional **`Retry-After`**) — used by **`GET /api/collection`**, **`GET /api/collection/fields`**, **`GET /api/collection/value`**, **`GET /api/release/[id]`**, and collection write proxies such as **rating** and **instance field** routes; **`DiscogsThrottleQueueError`** (queue wait exceeded) maps to **503** with **`Retry-After`** via **`buildDiscogsProxyErrorPayload`** for every Discogs read proxy (**`GET /api/collection`**, release batch, etc.) — not reported to Sentry as a **500**. Route handlers should return appropriate status codes and messages; clients surface errors via React Query / context error state.

**OAuth identity lookups** (`getVerifiedUserFromRequest` in [`src/lib/auth-request.ts`](../../src/lib/auth-request.ts)) are cached in memory for a short TTL ([`src/lib/identity-cache.ts`](../../src/lib/identity-cache.ts)) so `/api/auth/check` and crate routes do not call `oauth/identity` on every request. The in-memory Map is keyed by the current OAuth token pair (process-local only; entries hold verified user id/username, not password hashes). Concurrent lookups for the same token pair share one in-flight request via [`coalesceInFlightIdentityRequest`](../../src/lib/identity-cache.ts). **`getOptionalVerifiedUserFromRequest`** (public crate / playlist viewer) uses display cookies when present, then read-only verification with **`reportVerificationFailures: false`** — failures return **`null`**, not **401**. **`getVerifiedUserFromStoredTokens`** (token reuse on **`GET /api/auth/discogs`**, reconnect username on **`/api/auth/check`**) also skips verification Sentry. Discogs **401** / **403** on **`oauth/identity`** ([**`isDiscogsInvalidTokenStatus`**](../../src/lib/discogsApiError.ts)) clear the in-memory identity entry for that token pair and are not logged or reported — callers get **401**, then login routes start a fresh OAuth flow or return **`isAuthenticated: false`**. Coalesced in-flight identity fetches attach **`.catch(() => undefined)`** before **`finally`** so a shared rejection does not emit **`unhandledRejection`**. Discogs fetch **`TimeoutError`** / **`AbortError`** map to **504** for stale-cache fallback on required verification; those timeouts are not reported to Sentry (**[`resolveDiscogsVerificationFailureStatus`](../../src/lib/discogsApiError.ts)**). On Discogs **429** or upstream **5xx** (outage / maintenance page), data routes reuse only a recently cached identity keyed to the current OAuth token pair; they **never** fall back to `discogs_user_id` / `discogs_username` cookies. With no cached identity, **429** returns **503** (rate limit) and **5xx** returns **502** with **`DISCOGS_UPSTREAM_UNAVAILABLE_MESSAGE`** — never **401**, so an outage is not treated as a signed-out session. **`isDiscogsVerificationUnavailable`** (**502** / **503**) is the shared check: **`/api/auth/check`** returns a display-only identity from those cookies with **`rateLimited: true`** (the client blocks collection and crate fetches and re-checks every 60s until verification succeeds) and **`discogsUnavailable: true`** only for **502** (drives **`DiscogsOutageToast`** — see [patterns.md](patterns.md)), and **`/api/auth/discogs`** redirects to **`/collection`** instead of starting a new OAuth flow. Non-JSON Discogs error bodies become **`Discogs API error: {status}`** (short plain text is kept; HTML is never used as an error message).

**Read-only Discogs proxies** (`GET /api/collection`, `/api/collection/fields`, `/api/collection/value`, `/api/search`, authenticated `/api/release/[id]`, **`POST /api/release/batch`**) use **`requireReadOnlyDiscogsUser`** / **`getReadOnlyVerifiedUserFromRequest`** so a verified identity cached within the stale window (default 30 minutes) is reused during long collection pagination without re-calling `oauth/identity` on every page. When the in-memory cache is cold (new serverless instance), read-only routes may reuse **`discogs_user_id`** / **`discogs_username`** session cookies set at login so pagination stays one Discogs call per page; cookie-derived identity is **not** written into the OAuth token cache. OAuth tokens are still required and Discogs validates them on the data request. Write routes and `/api/auth/check` keep the default fresh verification policy and never authorize from display cookies alone.
