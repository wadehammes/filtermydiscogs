# Database

Prisma schema, crate persistence, and related API routes.

## Stack

- **ORM**: Prisma 7 with **`prisma-client-js`** (production). **Prisma 8** (`prisma@8` RC) is for staging/preview validation only until **`8.0.0` GA** — do not deploy RC builds to production.
- **Database**: PostgreSQL (Vercel Postgres in production)
- **Client**: [`src/lib/db.ts`](../../src/lib/db.ts) — singleton Prisma client for route handlers (lazy init on first **`prisma`** access so public pages and Playwright can boot without a configured DB URL). Connection string from [`readRuntimeDatabaseUrlFromEnv`](../../src/lib/databaseUrlEnv.ts): **request/runtime** — usable **`DATABASE_URL_POOLED`**, else **`DATABASE_URL`** with **`db.prisma.io` → `pooled.db.prisma.io`** (ignores **`[SENSITIVE]`** / non-URL placeholders from **`vercel env pull`**); **`next build`** (**`NEXT_PHASE=phase-production-build`**) — same URL order as migrate (**`DIRECT_URL` → `POSTGRES_URL` → `DATABASE_URL`**) so build-time SSG (e.g. public crate **`generateStaticParams`**) uses direct Prisma Postgres, not the pooler. [`sanitizePostgresConnectionStringForPg`](../../src/lib/databaseUrlEnv.ts) normalizes SSL query params; **does not** set URL or pg-pool **`statement_timeout`** on **`pooled.db.prisma.io`** (Prisma Postgres pooler rejects it — upstream connection errors). Direct hosts still get **`statement_timeout`**. Caps pg **`max`** at **1** during build.

Schema: [`prisma/schema.prisma`](../../prisma/schema.prisma). Datasource URL: [`prisma.config.ts`](../../prisma.config.ts) (Prisma 7).

| Field                       | Notes                                                                                                                                                                                    |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `discogs_user_id`           | Primary key — Discogs user ID from **verified OAuth identity**                                                                                                                           |
| `username`                  | Discogs username (updated on login)                                                                                                                                                      |
| `preferences`               | JSON blob for account settings (see below)                                                                                                                                               |
| `login_count`               | Completed OAuth logins (incremented in [`recordDiscogsLogin`](../../src/lib/user.server.ts))                                                                                             |
| `support_toast_dismissed`   | When `true`, the support-project action toast is never shown again                                                                                                                       |
| `support_toast_pending`     | One-shot flag set on login when `login_count` reaches the threshold and the toast was not dismissed; consumed by **`GET /api/auth/check`**                                               |
| `last_seen_at`              | Last authenticated activity timestamp; set on every login and throttled updates from **`GET /api/auth/check`** ([`touchUserLastSeen`](../../src/lib/user.server.ts), 15-minute interval) |
| `created_at` / `updated_at` | Row timestamps                                                                                                                                                                           |

One row per Discogs account. **`Crate.user_id`** references **`User.discogs_user_id`** with **`ON DELETE CASCADE`**. Rows are created/updated on OAuth login via [`recordDiscogsLogin`](../../src/lib/user.server.ts) in the auth callback and token-reuse paths.

**`preferences`** (versioned JSON, typed as [`UserPreferencesJson`](../../src/types/userPreferences.types.ts), parsed by [`user-preferences.server.ts`](../../src/lib/user-preferences.server.ts); Prisma field typing via [`prisma-json-types-generator`](https://www.prisma.io/docs/orm/prisma-client/special-fields-and-types/working-with-json-fields) + [`src/types/prisma-json.d.ts`](../../src/types/prisma-json.d.ts)):

| Field                            | Default                                         | Purpose                                                                                                                                                            |
| -------------------------------- | ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `persistFilters`                 | `true`                                          | When `false`, filter/sort selections are not restored on the next visit                                                                                            |
| `autoPlayOnQueueAdd`             | `true`                                          | When `true`, the first track added to an empty queue starts playback immediately and opens the video panel                                                         |
| `extendQueueWithSimilarReleases` | `false`                                         | When `true`, playback appends one related collection track at a time when up next runs low                                                                         |
| `defaultCollectionSidePanel`     | `"crates"`                                      | Which Releases side panel (`crates` or `playlists`) is selected on load; applied once per login via [`useCrateProvider`](../../src/hooks/useCrateProvider.hook.ts) |
| `theme`                          | `"system"`                                      | App color theme (`amber`, `codex`, `dark`, `dim`, `discogs`, `forest`, `futuristic`, `high-contrast`, `light`, `midnight`, `sepia`, `slate`, `wine`, or `system`)  |
| `view`                           | `{ currentView: "card", previousView: "card" }` | Default releases view (`card`, `list`, or `random`)                                                                                                                |
| `filters`                        | Default empty filter state                      | Saved filter selections when `persistFilters` is `true` (styles, years, formats, sort, style/format/year match mode, search query)                                 |
| `filterViews`                    | `[]`                                            | Named saved filter snapshots (search, facets, sort) synced across browsers; up to 20 entries                                                                       |
| `analyticsConsent`               | unset                                           | Optional boolean mirror of the analytics cookie choice when set from Settings                                                                                      |

Client reads/writes via **`GET`** / **`PATCH`** [`/api/user/preferences`](../../src/app/api/user/preferences/route.ts). **`GET`** is read-only: it **`findUnique`**s the authenticated **`User`** row and returns defaults when missing (user rows are created on OAuth login or the first **`PATCH`**). [`useUserPreferencesSync`](../../src/hooks/useUserPreferencesSync.hook.ts) (mounted from [`Providers.tsx`](../../src/components/Providers.tsx)) resets **`theme`** to **`system`** while logged out (guest default). On first login it **seeds local → server only when the server field is still at its default** (e.g. filters saved on preview/staging hydrate into a fresh local browser instead of being overwritten by empty **`localStorage`**); local **`system`** theme is **not** seeded (guest placeholder only). Otherwise it applies server prefs via **`setTheme`**, **`viewStateAtom`**, and **`persistedFiltersAtom`**. Authenticated **`PATCH`** calls go through [`usePersistUserPreferences`](../../src/hooks/usePersistUserPreferences.hook.ts) and [`userPreferencesPersistQueue.ts`](../../src/utils/userPreferencesPersistQueue.ts) (debounced filter writes, merged patches)—from [`ThemeSwitcher`](../../src/components/ThemeSwitcher/ThemeSwitcher.component.tsx), [`useViewDispatch`](../../src/hooks/useViewAtoms.hook.ts), [`useFiltersDispatch`](../../src/hooks/useFilterAtoms.hook.ts), [`SettingsClient`](../../src/components/Settings/SettingsClient.component.tsx), and the sync hook’s first-login seed. **`PATCH`** upserts preferences in one Prisma round trip.

### `CrateRelease`

Stores a release snapshot as **`release_data` JSON** keyed by Discogs **`instance_id`**. Optional **`found_at`** timestamp marks albums **packed for a gig** (owner-only; not exposed on public crate routes). **`sort_order`** controls display order within a crate (ascending; spaced by 1000; backfilled from **`added_at DESC`** on migration).

Composite primary key: **`[user_id, crate_id, instance_id]`**. Cascades on crate delete.

### `CrateSetMarker`

Owner-only section labels within a crate layout (e.g. “Peak hour”, nested “Deep House” under “Early Set”). Composite primary key: **`[user_id, crate_id, id]`** (UUID). **`sort_order`** interleaves with releases in the unified layout. Optional **`parent_id`** (self-FK, max depth 2) for nested groups; optional **`accent_key`** (curated palette → `--crate-section-accent-*` in [`base.css`](../../src/styles/themes/base.css)). Not returned on public crate routes.

**`CrateRelease.section_id`** (nullable FK → marker) stores explicit group membership for layout saves. On the owner crate page, only releases with **`section_id`** set count as section members (styled inside the group); other rows in the same structural block keep a neutral background. Dragging directly under a section header (or below another member) assigns membership; inserting **above** the first unsectioned release below a member run does **not** join the group. Dragging out clears it. On save, stale **`section_id`** values are cleared when the marker is missing, the release sits above its marker, or an unsectioned row appears between earlier members and the release (legacy “everything below the marker” data). **`CrateLayoutList`** wraps each marker’s structural block in a **`sectionGroup`** element (header [`CrateSetMarkerRow`](../../src/components/Crates/CrateSetMarkerRow.component.tsx) plus **`.sectionBody`**). When a group has no member releases, the body sets **`data-section-empty`** and reuses the **Add section** insert row (**`section-empty:{markerId}`** droppable id via **`getCrateLayoutSectionEmptyDropId`**) so clicking **+** or dropping a release both target the slot under the header; the portaled line indicator stays off over that zone (only above/below sortable rows elsewhere). When the body has members, a dashed **Drop release here** footer (**`section-end:{markerId}`** via **`getCrateLayoutSectionMemberEndDropId`**) mounts an **absolute** bottom hit target while dragging a release or section marker (dashed accent **`color-mix`** chrome only on **`isOver`**) and inserts after the last member (before unsectioned rows in the same structural block). Nested subsections that are the last body segment set **`suppressMemberEndDrop`** so only the parent footer shows; **`shouldShowCrateLayoutInsertZoneAtSectionBodyTail`** adds an **Add section** row below the nested card when needed. Nested **`.sectionGroupNested`** cards inside **`.sectionBody`** use inset **`border-radius`**, border, background, and **`overflow: hidden`**. **`moveCrateLayoutSectionBeforeSortableId`** accepts **`section-end:*`** when moving a descendant subgroup onto the parent footer. No duplicate insert row renders below an empty group. When **`accent_key`** is set, the group **`li`** also gets **`data-section-accent`** and defines **`--crate-section-inner-border*`** tokens so inner chrome (header rule, row dividers, notes inputs, marker label/add-group controls, section and member drag handles, empty drop, outer border) **`color-mix`**es the palette accent instead of plain **`--border`**. **Horizontal row chrome:** **`sectionGroup`** **`margin-inline`** matches top-level **`layoutReleaseRow`** insets so grouped and loose releases share drag-handle and action-column alignment; member rows use the same **`CrateReleaseList`** **`.row`** padding as ungrouped rows (no extra section-only horizontal padding). **`--crate-layout-drag-handle-width`** on **`CrateLayoutList`** / **`CrateReleaseList`** **`.row`** keeps the mobile notes disclosure indent aligned with the grip column. **`--crate-layout-row-padding-inline`** ( **`--space-4`**, **`--space-5`** at **`>=1024px`**) on **`CrateLayoutList`** sets shared row **`padding-inline`** for release rows, packed rows, and full-width section marker heads so action buttons share the same inset inside **`sectionGroup`** borders and on loose rows. Section-head corner radius in [`CrateLayoutList.module.css`](../../src/components/Crates/CrateLayoutList.module.css) keys off **`data-section-empty`** (**`.sectionGroup:has(> .sectionBody[data-section-empty])`**) rather than marker-only **`:has()`** in [`CrateSetMarkerRow.module.css`](../../src/components/Crates/CrateSetMarkerRow.module.css). When more layout rows follow a group, **`buildCrateLayoutRenderSegments`** sets **`showInsertAfter`** / **`insertAfterIndex`** on section segments so the **Add section** split control renders **below** the group border (including before unsectioned releases that still sit in the structural block). In-section member rows only show inline splits before another member or nested subsection, not before rows rendered outside the chrome. Existing markers backfill with **`parent_id` null**; the section-tree migration backfilled **`section_id`** once from layout order.

**Layout lib (owner DnD):** [`crate-layout.ts`](../../src/lib/crate-layout.ts) builds the merged release/marker list, filters **visible** rows when **hide packed** is on (`getVisibleCrateLayoutItems`, `countVisibleCrateReleases`), merges a **visible-only reorder** back into the full list without moving hidden packed rows (`mergeReorderedVisibleCrateLayout`), normalizes sort orders for PUT payloads, and reorders with **`reorderCrateLayoutItems`** (insert before/after the **`over`** row from pointer **Y** vs the row midpoint, matching the portaled line). List-level **Add section** slots expose release droppable ids **`layout-insert:{visibleIndex}`** via **`getCrateLayoutListInsertDropId`** / **`getCrateLayoutListInsertIndexFromDropId`**; **`reorderCrateLayoutReleaseToVisibleInsertIndex`** moves the dragged release to that visible index. On **`CrateDetailClient`**, toolbar **+** mounts are portaled outside the **`<ul>`**; **`layout-insert:0`** registers on the top mount only while dragging a release that is not already first (portaled line shows the insert edge—no dashed head zone in the list). The bottom **`layout-insert:{n}`** droppable still renders as a zero-height tail overlay ([`CrateLayoutListHeadInsert.module.css`](../../src/components/Crates/CrateLayoutListHeadInsert.module.css)) with a dashed hit target when dragging a non-last release. **`CrateLayoutList`** uses **`MeasuringStrategy.Always`**, **`over ?? collisions[0]`** on **`onDragOver`**, and a portaled **`.layoutDropIndicator`**; sibling rows keep **`transform: none`** during drag. **`topInsertMount`** / **`bottomInsertMount`** portal toolbar chrome outside the **`<ul>`**. [`crate-section-layout.ts`](../../src/lib/crate-section-layout.ts) renders section segments, drop indicators, and section-id resolution; **`buildCrateLayoutRenderSegments`** and **`shouldShowCrateLayoutInsertZoneAfterLooseInLayout`** place **Add section** splits (see **`showInsertAfter`** / **`insertAfterIndex`** on section segments above). It treats **`section-empty:*`** ids like marker ids when reordering visible items; **`section-end:*`** drops append after the section member run via **`reorderCrateLayoutReleaseOverSectionMemberEnd`**. **`resolveCrateLayoutDropIndicatorForDrag`** returns **`null`** over **`section-empty:*`** and **`section-end:*`** (those targets use inline dashed zones), draws on **`layout-insert:*`**, and elsewhere **`CrateLayoutList`** shows a portaled **primary** line (2px) aligned to the insert edge from **`resolveCrateLayoutDropIndicator`**. **`getCrateLayoutSectionBlock`** for nested markers (**`parent_id` set**) ends before sibling member releases in the parent body ( **`section_id`** not equal to the subsection and not a descendant marker id), so subgroup drags do not swallow parent-level members; **`moveCrateLayoutSectionBeforeSortableId`** re-infers **`parent_id`** on moved markers and accepts parent-member release targets when the active marker belongs to that parent block. **`filterCrateLayoutMarkerDragCollisions`** still blocks cross-group member targets for unrelated section drags. **`applyResolvedCrateLayoutSectionIds`** sets **`forcedSectionId`** on the moved release when the drop target is **`section-empty:*`** or **`section-end:*`** (position-only inference cannot distinguish that slot from inserting above the first unsectioned row below members); otherwise it **`inferCrateLayoutSectionIdForReleaseIndex`** for the moved row. **`applyCrateLayoutListDragReorder`** is the drag-end orchestrator (release reorders merge visible changes back into the full list; **section-marker** drags move the section block on the **full** layout so hidden packed rows stay with their group). It then runs **`applyResolvedCrateLayoutSectionIds`**. **`CrateLayoutList`** calls that helper on **`onDragEnd`**, updates local state, then debounces **`updateCrateLayout`** (~300ms) through **`CrateProvider`**. Owner **Delete section** opens **`ConfirmDialog`** for every marker (including unsaved **`temp-marker-*`** rows), then runs **`reparentCrateLayoutMarkersAfterDelete`**, then the same PUT path (**`crateLayoutItemsToPutRequest`** → **`PUT /api/crates/[id]/layout`**). Server parsing lives in [`crate-layout.server.ts`](../../src/lib/crate-layout.server.ts): **`buildCrateLayoutUpdate`** validates the payload and resolves **`section_id`**; **`applyCrateLayoutUpdate`** updates release order, runs **`clearCrateLayoutMarkerReferencesBeforeDelete`** (null **`section_id`** / **`parent_id`** pointing at removed markers — required because section FKs use **`ON DELETE RESTRICT`**), then **`crateSetMarker.deleteMany`** for ids not in **`markerIdsToKeep`** (an empty keep list deletes every marker row for that crate), then upserts kept markers. Deleting the last section group must accept a releases-only payload with **`markersToUpsert: []`** and **`markerIdsToKeep: []`**, clearing release **`section_id`** via **`resolveCrateLayoutSectionIds`**. Regression coverage: [`crate-layout.spec.ts`](../../src/lib/crate-layout.spec.ts), [`crate-section-layout.spec.ts`](../../src/lib/crate-section-layout.spec.ts) (including empty-section drops), [`crate-layout.edge-cases.spec.ts`](../../src/lib/crate-layout.edge-cases.spec.ts) (single flat **`describe("crateLayoutEdgeCases")`**, including **`layout-insert:0`** with no groups), [`crate-layout.server.spec.ts`](../../src/lib/crate-layout.server.spec.ts) (single flat **`describe("crateLayoutServer")`**: **`buildCrateLayoutUpdate`**, **`clearCrateLayoutMarkerReferencesBeforeDelete`**, **`applyCrateLayoutUpdate`**, including group-delete save), and pointer DnD wiring in [`CrateLayoutList.spec.tsx`](../../src/components/Crates/CrateLayoutList.spec.tsx) (row reorder, edge-mount top insert drop, section-delete confirm).

### `UserTrack`

Per-user playback stats for collection tracks (same identity as the playback queue: **`track_key`** = `` `${instance_id}:${track_position}` ``). User-owned data (not product analytics); rows cascade when **`User`** is deleted.

| Field                                          | Notes                                                                                                                                                                                          |
| ---------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `track_key`                                    | Composite playback key (part of primary key with `user_id`)                                                                                                                                    |
| `youtube_id`                                   | User’s preferred YouTube embed id for this track (optional). Set via **`PATCH /api/tracks/youtube`**, updated on play record when playback starts, and returned on **`GET /api/tracks/stats`** |
| `track_title`, `track_position`, `instance_id` | Denormalized for display                                                                                                                                                                       |
| `discogs_release_id`                           | Discogs catalog **release** id (not collection **`instance_id`**). Set when adding to a playlist via [`buildUserTrackMetadataBody`](../../src/utils/buildUserTrackMetadataBody.ts). Public playlists hydrate art through **`/api/release/:id`**, which requires this column (or a crate snapshot id). Backfill: migration **`20261025150000_backfill_user_track_discogs_release_id`**, crate snapshots in [`backfillDiscogsReleaseIdsForPlaylistTracks`](../../src/lib/backfill-user-track-discogs-release-id.server.ts), then Discogs search on **`artist` + `release_title`** in [`backfillDiscogsReleaseIdsFromDiscogsSearch`](../../src/lib/backfill-user-track-discogs-release-id-search.server.ts) when **`loadPublicPlaylist`** runs. |
| `artist`, `release_title`                      | Optional display metadata                                                                                                                                                                      |
| `play_count`                                   | User started playback (row click, queue, skip, auto-advance) — once per active track session                                                                                                   |
| `listen_count`                                 | ≥ **30s** continuous playback in one session, or embed ended before 30s (short tracks)                                                                                                         |
| `first_played_at`                              | Set on first **`play`** or override upsert when the row is created                                                                                                                             |
| `last_played_at` / `last_listened_at`          | Updated when the matching counter increments                                                                                                                                                   |

Admin override counts use **`userTrackHasYoutubeOverrideWhere`** in [`user-track.server.ts`](../../src/lib/user-track.server.ts) (aligned with **`btrim(youtube_id) <> ''`** in admin SQL).

Client writes via **`POST /api/tracks/record`** (`event`: **`play`** \| **`listen`**) and **`PATCH /api/tracks/youtube`** (explicit embed override — upserts row metadata + **`youtube_id`** without incrementing counters; send **`youtube_id: null`** to clear an override; Zod in [`userTrack.schemas.ts`](../../src/lib/validation/userTrack.schemas.ts)); reads via **`GET /api/tracks/stats?keys=`** (comma-separated **`track_key`** list, max 100; each row includes **`play_count`**, **`listen_count`**, **`youtube_id`**) — release modal via **`useTrackStatsQuery`** in [`useReleaseModalPlayback.hook.ts`](../../src/components/ReleaseModal/useReleaseModalPlayback.hook.ts); global queue embed resolution via **`usePlaybackTrackYoutubeOverrides`** (stats keys = **upcoming queue** rows plus the **currently playing** track — the active row is not stored in **`session.queue`**) + [`useTrackStatsQuery`](../../src/hooks/queries/useTrackStatsQuery.ts). Override saves use **`useSaveTrackYoutubeOverrideMutation`** ([`useTrackStatsMutations.ts`](../../src/hooks/mutations/useTrackStatsMutations.ts)) with **`meta.invalidates`** → **`TrackStatsQueryKeys`**. Dashboard leaderboards: **`GET /api/dashboard/top-tracks?limit=`** ( **`fetchTopUserTracks`** in [`user-track.server.ts`](../../src/lib/user-track.server.ts) — parallel **`play_count`** / **`listen_count`** queries; each row includes optional **`release_thumb`** from a single batched **`crate_releases`** lookup for all distinct **`instance_id`** values on both leaderboards). Admin platform playback aggregates: [`fetchAdminUserTrackStats`](../../src/lib/admin-user-track-stats.server.ts) (see [patterns.md → Admin dashboard](patterns.md#admin-dashboard)). UI may still prefer live collection art via **`useAllReleases()`**. Playback wiring: [`userTrackRecording.ts`](../../src/utils/userTrackRecording.ts) + [`TrackStatsRecorder`](../../src/components/TrackStatsRecorder/TrackStatsRecorder.component.tsx) (binds **`useRecordTrackEventMutation`**). Constants **`TRACK_LISTEN_MIN_MS`** (30_000) and **`USER_TRACK_STATS_KEYS_MAX`** (100) in [`userTrack.ts`](../../src/utils/userTrack.ts); client requests cap via **`normalizeTrackStatsKeys`** (optional **`prioritizeKeys`** when capping) in [`useTrackStatsQuery`](../../src/hooks/queries/useTrackStatsQuery.ts). Override-only upserts (no prior play/listen) are covered by [`user-track.server.spec.ts`](../../src/lib/user-track.server.spec.ts) and [`src/app/api/tracks/youtube/route.spec.ts`](../../src/app/api/tracks/youtube/route.spec.ts); modal **`track_key`** wiring by [`useReleaseModalPlayback.hook.spec.tsx`](../../src/components/ReleaseModal/useReleaseModalPlayback.hook.spec.tsx).

### `ProductAnalyticsEvent`

First-party product analytics when the visitor opts in (same consent gate as GTM). No FK to **`User`** — optional **`user_id`** for signed-in events.

| Field                                     | Notes                                                             |
| ----------------------------------------- | ----------------------------------------------------------------- |
| `event` / `category` / `action` / `label` | Event metadata (mirrors GTM-style payloads)                       |
| `value`                                   | Optional string value                                             |
| `page_path`                               | App route path when recorded                                      |
| `user_id`                                 | Discogs user ID when signed in; nullable for anonymous page views |
| `created_at`                              | Insert timestamp                                                  |

Indexed on **`user_id`** for **`POST /api/auth/clear-data`** deletes and other per-user maintenance.

Ingest: **`POST /api/usage/events`** ([`PRODUCT_ANALYTICS_INGEST_PATH`](../../src/types/productAnalytics.types.ts), handler [`src/app/api/usage/events/route.ts`](../../src/app/api/usage/events/route.ts), logic [`product-analytics.server.ts`](../../src/lib/product-analytics.server.ts)). Batches capped at **`PRODUCT_ANALYTICS_MAX_BATCH_SIZE`** (20) in [`productAnalytics.types.ts`](../../src/types/productAnalytics.types.ts); client queue uses the same limit ([`productAnalyticsClient.ts`](../../src/analytics/productAnalyticsClient.ts)). Optional signed-in **`user_id`** comes from [`getOptionalVerifiedUserFromRequest`](../../src/lib/auth-request.ts): no app session → **`null`**; with session, prefer **`discogs_user_id`** / **`discogs_username`** display cookies (no **`oauth/identity`** call); otherwise **`getVerifiedUserFromRequest`** with **`allowStale: true`** and **`reportVerificationFailures: false`** — expired tokens, Discogs **401**, or fetch timeouts resolve to **`null`** and ingest still returns **`{ ok: true }`** (never **401** / unhandled rejection on this route). Cleared on **`POST /api/auth/clear-data`** for the authenticated **`user_id`**. Raw rows are kept for **90 days**; older detail is rolled up then deleted (see **`ProductAnalyticsDailyRollup`**).

### `ProductAnalyticsDailyRollup`

Daily aggregates preserved after raw event retention. Composite primary key: **`[date, dimension_type, dimension_key]`** (UTC calendar date).

| Field            | Notes                                                            |
| ---------------- | ---------------------------------------------------------------- |
| `date`           | UTC day bucket (`DATE`)                                          |
| `dimension_type` | `page_path` (page views) or `event` (non–page-view interactions) |
| `dimension_key`  | Path or event name                                               |
| `event_count`    | Total events that day for that dimension                         |

Populated by **`GET /api/cron/product-analytics`** ([`product-analytics-maintenance.server.ts`](../../src/lib/product-analytics-maintenance.server.ts)) — Vercel Cron daily at 04:00 UTC ([`vercel.json`](../../vercel.json)). Requires **`CRON_SECRET`**. Rollups are **incremental**: each run starts the day after the latest stored rollup (or the oldest raw event on first run), catches up through **yesterday** (UTC), and **always re-rolls yesterday** so late-arriving events update that day. Rows are written with a bulk **`INSERT … ON CONFLICT`** per dimension/day. UTC day boundaries use [`startOfUtcDay`](../../src/utils/dateHelpers.ts) / [`addUtcDays`](../../src/utils/dateHelpers.ts) (shared with [`collectionRhythm.ts`](../../src/utils/collectionRhythm.ts)).

**Goal:** Saved **track lists** distinct from **crates** (release-level) and the **session playback queue** (in-memory + **`localStorage`**). Identity matches playback everywhere: **`track_key`** = `` `${instance_id}:${track_position}` `` ([`userTrack.ts`](../../src/utils/userTrack.ts), [`PlaybackQueueItem`](../../src/types/playbackQueue.types.ts)).

**Canonical track row:** existing **`UserTrack`** ([`user_tracks`](../../prisma/schema.prisma)) — metadata (**`instance_id`**, **`track_position`**, **`track_title`**, **`artist`**, **`release_title`**, **`youtube_id`**) plus **`play_count`** / **`listen_count`**. Do **not** add a parallel **`tracks`** table. **`PlaylistTrack`** FKs **`(user_id, track_key)` → `UserTrack`**.

**Before adding to a playlist:** upsert **`UserTrack`** with metadata and **`play_count` / `listen_count` = 0** when the row does not exist yet — same pattern as [`saveUserTrackYoutubeOverride`](../../src/lib/user-track.server.ts) (playlist add can reuse that helper or a thin **`ensureUserTrackMetadata`** wrapper with the same Zod metadata fields).

**`Playlist`** — user-owned named list (same scoping pattern as **`Crate`**: composite **`@@id([user_id, id])`**, UUID **`id`**, **`name`**, timestamps, optional **`username`** on public shares). When **`private: false`**, **`public_view_count`** and **`public_play_count`** track anonymous and signed-in visitor engagement on **`/playlist/[id]`** (owner views/plays are excluded — [`playlist-engagement.server.ts`](../../src/lib/playlist-engagement.server.ts)).

**`PlaylistTrack`** — junction only (no duplicated track columns):

| Field                                 | Notes                                                                      |
| ------------------------------------- | -------------------------------------------------------------------------- |
| `user_id`, `playlist_id`, `track_key` | Composite PK; **`track_key`** FK → **`UserTrack`** **`ON DELETE CASCADE`** |
| `sort_order`                          | Order within the playlist (DnD in **`PlaylistDrawerTracks`**)              |

Adding the same track twice: **dedupe** by **`track_key`** per playlist (reject or no-op on second add).

**API / UI stack:** migration → playlist CRUD routes → **`api.*`** + React Query → **`ReleaseTrackRowMenu`** “Add to playlist” → **`/releases`** side panel (**`CollectionSidePanelToggle`**, **`PlaylistDrawer`** with **`useReorderPlaylistTracksMutation`**). Optional later: **`PlaybackQueueDrawer`** “Save queue as playlist”.

**Playback:** **Play** / row play replace upcoming via **`planPlaylistPlaybackStart`** (**`clearQueue`**, **`startPlayback`** + **`upcomingQueue`**) in playlist order; footer **Queue** uses **`addPlaylistToQueue`** to append rows without clearing transport ([`usePlaylistPlayback.hook.ts`](../../src/hooks/usePlaylistPlayback.hook.ts), [patterns.md → Playlists](patterns.md#playlists)). Hydration uses **`useAllReleases()`** + [`playlistPlayback.ts`](../../src/utils/playlistPlayback.ts) (**`collectPlayablePlaylistEntries`**). DnD reorder can sync upcoming via **`syncPlaylistQueueToTrackOrder`**. Release **Add all to queue** appends without clearing upcoming unless the listener already cleared it ([patterns.md → Release playback queue](patterns.md#release-playback-queue)).

## Migrations

```bash
pnpm db:migrate        # dev: create/apply migrations (.env.local)
pnpm db:pull:staging   # pull staging/preview DATABASE_URL into .env.local (Vercel CLI)
pnpm db:migrate:staging # apply pending migrations to staging (.env.local)
pnpm db:pull:prod      # pull production DATABASE_URL into .env.local
pnpm db:migrate:prod   # apply pending migrations to production (.env.local)
pnpm db:push           # prototype schema push (script loads env)
pnpm db:studio         # Prisma Studio
pnpm db:generate       # regenerate client (also runs on build/postinstall)
pnpm db:diff:migrations # migrations folder vs schema (needs shadow DB; see below)
```

**Migrate / CLI database URL precedence:** **`DIRECT_URL`**, then **`POSTGRES_URL`**, then **`DATABASE_URL`** — shared by [`prisma.config.ts`](../../prisma.config.ts), [`scripts/migrate-deploy.sh`](../../scripts/migrate-deploy.sh) via [`scripts/resolve-migrate-database-url.ts`](../../scripts/resolve-migrate-database-url.ts) → [`readMainDatabaseUrlFromEnv`](../../src/lib/databaseUrlEnv.ts) (`MIGRATE_DATABASE_URL_ENV_KEYS`), and **Prisma during `next build`** (see [`readRuntimeDatabaseUrlFromEnv`](../../src/lib/databaseUrlEnv.ts) when **`NEXT_PHASE=phase-production-build`**). **Deployed request handlers** use pooled resolution via [`db.ts`](../../src/lib/db.ts) — serverless concurrency must not hit the direct integration string; Prisma Console **`DATABASE_URL_POOLED`** (`pooled.db.prisma.io`) is the preferred explicit pooled var ([Prisma Vercel guide](https://www.prisma.io/docs/guides/postgres/vercel)).

**Shadow database (`SHADOW_DATABASE_URL`):** Used by **`prisma migrate dev`** and **`pnpm db:diff:migrations`** to apply migrations into a disposable database for drift checks. Set **`SHADOW_DATABASE_URL`** in **`.env.local`** when **`DATABASE_URL`** is remote (e.g. Prisma Postgres / staging pull). For **localhost** URLs, [`prisma.config.ts`](../../prisma.config.ts) auto-derives **`{database}_shadow`** when **`SHADOW_DATABASE_URL`** is unset — create that empty database locally first. Never point shadow at production or shared staging data.

Vercel exposes **`DATABASE_URL`** per deployment target: **Preview/Development** share the non-prod Postgres (use this for local work against staging); **Production** is separate. There is no fourth “staging” env in Vercel—the **`staging`** git branch deploys to **Preview**.

For local dev against the staging database:

```bash
pnpm db:pull:staging    # writes preview DATABASE_URL to .env.local
pnpm db:migrate:staging # apply migrations (e.g. found_at) to that DB
pnpm dev                # app uses .env.local
```

**`db:pull:dev`** pulls the **Development** target (same **`DATABASE_URL`** as Preview on this project). Use **`db:pull:prod`** / **`db:migrate:prod`** only when intentionally touching production.

Generated Prisma client output is **not committed** (`/prisma/node_modules` and root `node_modules/.prisma/client` are gitignored; CI and `postinstall` run `prisma generate`).

**Vercel builds** run **`scripts/migrate-deploy.sh`** before **`next build`** ([`package.json`](../../package.json)) so each Production / Preview deployment applies pending migrations. The script resolves the migrate URL through **`readMainDatabaseUrlFromEnv`** (Prisma Postgres: direct host **`db.prisma.io`** for migrations; pooled **`pooled.db.prisma.io`** for runtime when configured), appends **`connect_timeout=30`** for serverless cold starts, and **retries** transient **`P1001`** connection errors (default 5 attempts, exponential backoff). Override with **`PRISMA_MIGRATE_DEPLOY_ATTEMPTS`** / **`PRISMA_MIGRATE_DEPLOY_RETRY_DELAY_SEC`**. Skips migrate when no database URL is set (local builds without **`.env.local`**). For one-off fixes, still use **`pnpm db:pull:prod`** + **`pnpm db:migrate:prod`** locally. Preview and Production use **separate** Prisma Postgres instances — migrating one does not migrate the other.

Migrations live under [`prisma/migrations/`](../../prisma/migrations/).

CI runs **`pnpm prisma generate`** before typecheck/tests ([`platform.md`](platform.md)).

## Public crates

When **`private: false`**, [`src/lib/public-crate.server.ts`](../../src/lib/public-crate.server.ts) and [`src/lib/public-crate-query.server.ts`](../../src/lib/public-crate-query.server.ts) load crate metadata and releases for SSR/SEO on **`/crate/[id]`**. Remaining public crate URLs still render on demand. When **`readRuntimeDatabaseUrlFromEnv()`** is unset, the query returns no rows, or the query errors, **`getPublicCrateIdsForStaticGeneration`** falls back to **[`LOGIN_DEMO_PUBLIC_CRATE_ID`](../../src/constants/publicCrate.constants.ts)** when **`NEXT_PUBLIC_E2E_MOCK_YOUTUBE_EMBED=1`** (see **`pnpm build:e2e`**) or during **`next build`** (**`NEXT_PHASE=phase-production-build`**) so **`generateStaticParams`** satisfies Next.js Cache Components (at least one param). During **`next build`**, [`db.ts`](../../src/lib/db.ts) caps the pg pool at **1** connection per worker when **`NEXT_PHASE=phase-production-build`**. Public API responses strip private collection fields (`notes`, `rating`, `date_added`) via [`toPublicReleaseSnapshot`](../../src/lib/release-data-validation.ts) before returning `release_data`. OG images: [`src/app/api/og/crate/[id]/route.tsx`](../../src/app/api/og/crate/[id]/route.tsx).

## Public playlists

When **`private: false`**, [`public-playlist-query.server.ts`](../../src/lib/public-playlist-query.server.ts) and [`loadPublicPlaylist`](../../src/lib/public-playlist-load.server.ts) power **`/playlist/[id]`** SSR and **`GET /api/playlists/public/[id]`**. The GET handler calls **`findPublicPlaylistById`** once (owner username backfill, voter attachment) and passes that row into **`loadPublicPlaylist`** via **`LoadPublicPlaylistOptions.playlist`** so the loader does not query the playlist again. Public payloads include **`shareStats`** (**`publicViewCount`**, **`publicPlayCount`**) from **`Playlist`** counters and optional owner **`publicDescription`** (**`Playlist.public_description`**, edited via **`PATCH /api/playlists/[id]`** / **`POST /api/playlists`** **`publicDescription`** and **[`CreatePlaylistDialog`](../../src/components/CreatePlaylistDialog/CreatePlaylistDialog.component.tsx)** (create + rename)). Non-empty descriptions feed **`buildPublicSharePageMetadata`** / Open Graph via **[`resolvePlaylistPublicShareMetaDescription`](../../src/utils/publicPlaylistDescription.ts)** (truncated to **`PLAYLIST_PUBLIC_DESCRIPTION_META_MAX_LENGTH`**); the full text renders on **`PublicPlaylistSummaryHero`**. Per-track **`upCount`** / **`downCount`** live on **`PlaylistTrack`**; anonymous and signed-in **visitors** vote via **`POST /api/playlists/public/[id]/tracks/vote`** (the playlist owner cannot vote and view/play engagement counters exclude the owner — [`playlist-engagement.server.ts`](../../src/lib/playlist-engagement.server.ts), [`playlist-track-vote.server.ts`](../../src/lib/playlist-track-vote.server.ts)) (HttpOnly **`fmd_plvv`** cookie for anonymous visitors — issued on **`GET /api/playlists/public/[id]`** and vote **`POST`** when missing). **`GET /api/playlists/public/[id]`** attaches **`viewerVote`** per track and uses **`Cache-Control: private, no-store`** (responses vary by session/cookie). Successful votes revalidate the public playlist cache tag and patch **[`usePublicPlaylistQuery`](../../src/hooks/queries/usePublicPlaylistQuery.ts)** via **[`usePublicPlaylistTrackVoteMutation`](../../src/hooks/mutations/usePublicPlaylistTrackVoteMutation.ts)** (optimistic + server reconcile). **[`useRecordPublicPlaylistView`](../../src/hooks/useRecordPublicPlaylistView.hook.ts)** fires **[`useRecordPublicPlaylistViewMutation`](../../src/hooks/mutations/usePublicPlaylistEngagementMutations.ts)** at most once per playlist per 24h (**[`publicPlaylistViewDedupe.client.ts`](../../src/utils/publicPlaylistViewDedupe.client.ts)** + in-memory guard); **`POST /view`** sets an HttpOnly **`fmd_plv_{playlistId}`** cookie so reloads do not increment **`public_view_count`**. Successful view/play mutations patch **`shareStats`** on **[`usePublicPlaylistQuery`](../../src/hooks/queries/usePublicPlaylistQuery.ts)** via **[`patchPublicPlaylistShareStatsInQueryCache`](../../src/utils/publicPlaylistShareStatsQueryCache.ts)**. **`usePlaylistPlayback`** with **`publicEngagementPlaylistId`** POSTs **`/play`** when **Play All** or row play starts transport (owner sessions skip increments — [`playlist-engagement.server.ts`](../../src/lib/playlist-engagement.server.ts)). Owner **`GET /api/playlists/[id]`** and **[`PlaylistShareControls`](../../src/components/PlaylistShareControls/PlaylistShareControls.component.tsx)** surface the same totals when the playlist is public. **`getPublicPlaylistMetadataForPage`** / **`getPublicPlaylistForPage`** use **`use cache`** (5‑minute revalidate) for **`generateMetadata`** and the page payload. **`getPublicPlaylistIdsForStaticGeneration()`** (default limit 100) feeds **`/playlist/[id]`** URLs in [`sitemap.ts`](../../src/app/sitemap.ts); build placeholder id is excluded. **`generateStaticParams`** on [`/playlist/[id]/page.tsx`](../../src/app/playlist/[id]/page.tsx) uses **`PUBLIC_PLAYLIST_BUILD_PRERENDER_LIMIT`** (25). Share SEO metadata is built with [`buildPublicSharePageMetadata`](../../src/lib/public-share-metadata.server.ts). ## Prisma Postgres environment contract

Each **Vercel target** (Production, Preview, Development) has its **own** Prisma Postgres instance. Use the integration **`POSTGRES_URL`** username prefix to confirm you are on the right database.

| Variable | Host | Used for |
| -------- | ---- | -------- |
| **`POSTGRES_URL`** | **`db.prisma.io`** (direct) | Migrate, Prisma CLI, **`next build`** DB access |
| **`DATABASE_URL`** | **`db.prisma.io`** (direct, same creds as **`POSTGRES_URL`**) | Tooling parity; runtime fallback when pooled var missing |
| **`DATABASE_URL_POOLED`** | **`pooled.db.prisma.io`** (same creds) | **Deployed** request-time traffic (preferred) |

Runtime resolution lives in [`readRuntimeDatabaseUrlFromEnv`](../../src/lib/databaseUrlEnv.ts): valid **`DATABASE_URL_POOLED`** first; otherwise rewrite direct **`DATABASE_URL`** to the pooler. **`next build`** uses migrate precedence (direct) instead. Do not point serverless traffic at the direct integration string — see [platform.md → Environment variables](platform.md#environment-variables).

**Local:** **`pnpm db:pull:staging`** or **`db:pull:dev`** writes Vercel env to **`.env.local`** (no post-pull rewrite). **`next dev`** can run with integration **`DATABASE_URL`** (direct) only; omit **`DATABASE_URL_POOLED`** locally if you accept in-app rewrite. Avoid **`db:pull:prod`** for day-to-day work.

**Env repair (drift / incidents only):** **`pnpm db:apply-vercel-database-env`** **`production|preview|development`** ([`scripts/apply-vercel-database-env-from-postgres.sh`](../../scripts/apply-vercel-database-env-from-postgres.sh)) sets **`DATABASE_URL`** + **`DATABASE_URL_POOLED`** from each target’s **`POSTGRES_URL`**. **`pnpm db:sync-pooled-url`** does the same for **`.env.local`** ([`scripts/sync-pooled-database-url-from-postgres.ts`](../../scripts/sync-pooled-database-url-from-postgres.ts)). Normal workflow does **not** require these commands.
