- **Resume after refresh**: **`startPlayback`** writes `{ instanceId, trackPosition, queue?, youtubeVideoId? }` to **`localStorage`** via [`releasePlaybackStorage.ts`](../../src/utils/releasePlaybackStorage.ts) (queue rows may include optional **`fromSimilarRelease`** metadata for tail-appended tracks; optional **`youtubeVideoId`** captures the active embed / user override so restore does not wait on **`fetchTrackStats`**); the provider keeps it updated while playback is active, including manual **Add to queue** rows (resolved back to collection releases on restore). Restore passes a saved **`youtubeVideoId`** into **`startPlayback`** as an explicit embed id when present. Restore waits for auth (`isCheckingAuth`), the collection to finish loading (`collection !== null`, not fetching), and any remaining pages (React Query **`hasNextPage`** when collection pages exist; otherwise **`collection.pagination.urls.next`**) before giving up — on any route, not only **`/collection`**. Restore reopens the dock **paused** with the saved upcoming queue — browsers block autoplay without a user gesture, so the listener taps play to resume audio. Per-track **`play`** counts increment on unpaused **`startPlayback`** / queue advances or when the listener **resumes** from the dock (**`togglePlayback`**), not when restore only rehydrates a paused session. Cleared on stop, logout, and **Clear stored data**.
