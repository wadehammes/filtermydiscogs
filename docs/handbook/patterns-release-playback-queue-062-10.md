- **UI**: [`ReleaseMiniPlayer`](../../src/components/ReleaseMiniPlayer/ReleaseMiniPlayer.component.tsx) is a slim background-playback dock (cover, title, prev/play-pause/next — no bar stop control). When **`isPlaybackReady`**, the bar adds **dig controls**: **[`ReleaseMiniPlayerDigScrub`](../../src/components/ReleaseMiniPlayerDigControls/ReleaseMiniPlayerDigScrub.component.tsx)** (**`flex: 1`**) sits **between** release meta and transport (Base UI **[`PlaybackDockSlider`](../../src/components/PlaybackDockSlider/PlaybackDockSlider.component.tsx)**; elapsed/duration **`fmdPlaybackDockTimeLabel`** on all layouts and ±10s skip labels use **`--font-family-meta`** / **`--text-meta-xs`**; skip buttons desktop-only). Below **768px** the scrub is its own row, so [`playback-dock.css`](../../src/styles/global/playback-dock.css) adds **`--release-mini-player-scrub-row`** (slider thumb plus the column gap) to **`--release-mini-player-bar-height`** while **`fmdReleaseMiniPlayerDigScrub`** is mounted — crate, playlist, and filters drawers read **`--release-mini-player-stack-offset`** and sit above that taller bar. From **768px** the scrub stays in the row and **`--release-mini-player-scrub-row`** is **0**; **[`ReleaseMiniPlayerVolumePopover`](../../src/components/ReleaseMiniPlayerDigControls/ReleaseMiniPlayerVolumePopover.component.tsx)** is the leading control in **[`ReleaseMiniPlayerTransportControls`](../../src/components/ReleaseMiniPlayer/ReleaseMiniPlayerTransportControls.component.tsx)** (same centered button row on mobile; vertical volume slider + mute in a Base UI **`Popover`**; level in **`localStorage`** via [`playbackDockVolumeStorage.ts`](../../src/utils/playbackDockVolumeStorage.ts). YouTube **`loadVideoById`** resets embed volume and can start the next upload loud, including when a track change resolves while release data is still loading. Each load mutes the embed first ([`playbackDockVolumeReapply.ts`](../../src/utils/playbackDockVolumeReapply.ts)); later player events keep it muted until the first real playing event for that video, which posts the stored dock level with **`setVolume`** before **`unMute`**. A load of the same upload, or player events that arrive before the embed video id is set, mute again and wait for that playing event. A repeating **`infoDelivery`** playing state waits until the player has left playing, so a leftover message from the previous track does not consume that update; mute UI follows **`isPlaybackDockMuted`** on **`ReleasePlaybackState`**, not local popover-only state). Position/seek flows through **`seekPlayback`** / **`ReleasePlaybackEmbedProgressContext`** (throttled YouTube **`infoDelivery`**; track/prev/next resets publish **`0`** immediately and [`playbackEmbedProgress.ts`](../../src/utils/playbackEmbedProgress.ts) guards reject stale high/low **`currentTime`** while the embed catches up). Dock scrubber state uses a single [`useReleasePlaybackEmbedProgress`](../../src/hooks/useReleasePlaybackEmbedProgress.hook.ts) instance via [`useReleasePlaybackDockEmbedProgress`](../../src/hooks/useReleasePlaybackDockControls.hook.ts) (no derived **upload-key** **`useEffect`** reset — [`resolvePlaybackDockEmbedProgressResetKey`](../../src/hooks/useReleasePlaybackDockControls.hook.ts) remains a pure helper for specs). **`resetDockEmbedProgress`** is imperative from queue transport: **Dock scrubber contract (queue vs iframe):** the YouTube iframe is the source of truth for **`currentTime`** / **`duration`** (`handleInfoDelivery` + visible-tab sync). The queue owns **which track** plays; it does **not** reset the scrubber on **`playQueueItem`**. **`playQueueItem`** snapshots **`priorCommittedUploadVideoId`** via [`resolveCommittedSessionEmbedVideoId`](../../src/utils/releasePlaybackActivePresentation.ts) **before** sync/apply for **`resolveNeedsPlaybackVideoSwitch`** only (upload vs same-upload metadata advance). Same-upload **`settleSameUploadQueueAdvance`** releases stale progress guards, confirms presentation when appropriate, and **`syncEmbedPlaybackState`**. Scrubber **`resetEmbedProgress`** runs on **`stopPlayback`**, **`startReleasePreview`**, and **`notifyPlaybackVideoLoadStarted`** only when the resolved upload id **differs** from the armed watchdog video id (not on same-id presentation retries from **`PersistentYoutubeIframe`**), not on **`playQueueItem`** — **`resetEmbedProgress`** keeps the last **duration** until the iframe updates. **`startReleasePreview`** and **`stopPlayback`** always reset; paused restore / **`startPaused`** skips **`playQueueItem`** reset so the track-reset guard does not block **`infoDelivery`** before play. **`togglePlayback`** resume calls **`releaseStaleEmbedProgressGuard`**, **`syncEmbedPlaybackState`**, and **`requestYoutubeEmbedPlaybackSync`** (plus the **`PLAYBACK_EMBED_PROGRESS_THROTTLE_MS`** poll above after confirm). **`COMPACT_LAYOUT_MEDIA_QUERY`** drives stacked mobile dock + video chrome in **`ReleaseMiniPlayer`** / **`ReleasePlaybackVideoPanel`**; **`DESKTOP_LAYOUT_MEDIA_QUERY`** remains the structural break for modal split and the crate sidebar. Prev/play-pause/next and the **video** toggle stay disabled until **`isPlaybackReady`** (see **`resolveIsPlaybackReady`** above). A **queue** control opens **[`PlaybackQueueDrawer`](../../src/components/PlaybackQueueDrawer/PlaybackQueueDrawer.component.tsx)** (drag-to-reorder, list, play at index, remove row, clear queue).
