## Models

### `User`

| Field                       | Notes                                                                                                                                                                                    |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `discogs_user_id`           | Primary key — Discogs user ID from **verified OAuth identity**                                                                                                                           |
| `username`                  | Discogs username (updated on login)                                                                                                                                                      |
| `preferences`               | JSON blob for account settings (see below)                                                                                                                                               |
| `login_count`               | Completed OAuth logins (incremented in [`recordDiscogsLogin`](../../src/lib/user.server.ts)); analytics only — not used for support-toast eligibility                                                                  |
| `support_toast_dismissed`   | When `true`, the support-project action toast is never shown again                                                                                                                       |
| `support_toast_pending`     | Legacy column (cleared on dismiss); eligibility no longer depends on it — **`GET /api/auth/check`** sets **`showSupportProjectToast`** via **`readSupportProjectToastEligible`** when not dismissed and **`login_count` > 1** (hidden on a user’s first login to reduce first-session toast stacking)         |
| `email`                       | Optional contact email for product and marketing mail. Backfilled from Discogs **`GET /users/{username}`** on OAuth login when empty; overridden or cleared in Settings ([`PATCH /api/user/contact`](../../src/app/api/user/contact/route.ts)). **`email_verified_at`** must be set before welcome or marketing mail sends; user-entered or changed addresses go to **`email_pending`** until **`GET /api/user/email-verification/confirm`** |
| `email_verified_at`         | Set when OAuth backfill stores a Discogs profile email, or when the user confirms **`email_pending`** via the verification link (24h token, hashed in **`email_verification_token_hash`**) |
| `email_pending`             | Address awaiting confirmation; **`GET /api/user/contact`** exposes it as **`pendingEmail`** |
| `marketing_emails_opt_in`   | When `true`, the account may receive occasional marketing/product email at **`email`**; requires a saved email; default **`false`**. Marketing sender: Resend (list unsubscribe handled there when mail ships) |
| `welcome_email_sent`        | When `true`, the one-time welcome email was sent (or claimed for send) at **`email`** via Resend ([`sendWelcomeSignupEmailIfEligible`](../../src/lib/welcomeSignupEmail.server.ts)); default **`false`**. Grandfathered **`true`** on pre-rollout accounts (migration + **`login_count` > 1** or **`created_at`** before [`WELCOME_EMAIL_NEW_ACCOUNT_MIN_CREATED_AT`](../../src/constants/welcomeSignupEmail.constants.ts)). Eligible sends need a trimmed **`email`**, **`welcome_email_sent`** false, and post-cutoff **`created_at`** (triggered after OAuth login side effects and after **`PATCH /api/user/contact`**). Reset to **`false`** if delivery fails (thrown transport errors **and** Resend **`{ error }`** responses that do not throw) so a later login, contact save, or admin queue send can retry |
| `last_seen_at`              | Last authenticated activity timestamp; set on every login and throttled updates from **`GET /api/auth/check`** ([`touchUserLastSeen`](../../src/lib/user.server.ts), 15-minute interval) |
| `created_at` / `updated_at` | Row timestamps                                                                                                                                                                           |

Migration **`20261125180000_user_email_verification`** backfills **`email_verified_at`** from **`created_at`** for existing non-empty **`email`** rows so pre-rollout Settings saves stay eligible for welcome mail without re-verifying.

One row per Discogs account. **`Crate.user_id`** references **`User.discogs_user_id`** with **`ON DELETE CASCADE`**. Rows are created/updated on OAuth login via [`recordDiscogsLogin`](../../src/lib/user.server.ts) in the auth callback and token-reuse paths (**`recordDiscogsLogin`** does not read or write **`email`**). Optional **`email`** backfill uses [`backfillUserEmailFromDiscogsProfileIfEmpty`](../../src/lib/backfillUserEmailFromDiscogsProfile.server.ts) after OAuth via [`runLoginSideEffectsAfterLogin`](../../src/lib/runLoginSideEffectsAfterLogin.server.ts) (auth routes **`await`** [`runLoginSideEffectsAfterLoginWithLoggedFailure`](../../src/lib/runLoginSideEffectsAfterLogin.server.ts) with OAuth token credentials) when the column is still empty (never overwrites a Settings-saved address). [`sendWelcomeSignupEmailIfEligible`](../../src/lib/welcomeSignupEmail.server.ts) also runs after a successful Settings contact save ([`PATCH /api/user/contact`](../../src/app/api/user/contact/route.ts)) so accounts that add **`email`** after first login still receive the one-time welcome. Welcome eligibility constants live in [`welcomeSignupEmail.constants.ts`](../../src/constants/welcomeSignupEmail.constants.ts) (**`welcomeSignupEmailEligibilityWhere`**, **`hasTrimmedUserEmail`**).
