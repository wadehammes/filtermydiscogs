A track-row **`startPlayback`** with no prior manual queue additions still replaces upcoming with the new album tail as before. **`playNext`** / YouTube ended advance by moving the current track to history, playing the first upcoming row, and removing it from upcoming. **`playPrevious`** pops from **`playbackHistory`** and prepends the current track back onto upcoming when needed. **`clearQueue`** (queue drawer **Clear queue**) clears upcoming only but **keeps the active track playing** and suppresses similar tail extension until the listener starts playback again or adds to the queue; removing a **`fromSimilarRelease`** row with the queue drawer **remove** control applies the same suppression; **`stopPlayback`** ends the session entirely (logout, clear stored data, removing the last queue row) with no bar stop control. **`isMiniPlayerVisible`** (`release !== null`) keeps the dock and layout spacers up while a session is active, including when paused. **`reorderQueue`** reorders upcoming rows from the queue drawer (drag handle, `@dnd-kit`; sortable ids **`getQueueItemListId(item, index)`**) and keeps the active track playing. Prev/next and dock transport walk upcoming plus history, not only the current album. When a YouTube embed finishes, **`ReleasePlaybackProvider`** listens for iframe **`onStateChange`** and **`infoDelivery`** ended events (via [`youtubeIframeEvents.ts`](../../src/utils/youtubeIframeEvents.ts); **`PersistentYoutubeIframe`** enables listening on **`load`**) and calls **`playNext`** automatically when another upcoming row exists. **YouTube embed sync**: one handler (**`handleYoutubeEmbedPlayerState`**) processes iframe **`onStateChange`** / **`infoDelivery`** messages. **Ended** runs **`playNext`** when the session is playing and not user-paused, except **`notifyEmbedPlaybackEnded`** ignores **`ENDED`** / **`infoDelivery`** at-or-past-end while a queue **transition target** is set and **`EMBED_TRACK_SWITCH_PAUSE_GRACE_MS`** is still active (stale end signals from the previous upload during cross-release / modal track switches). Embed **paused** during a track switch (**`loadVideoById`**, including when browser PiP closes) does not flip app **`isPaused`** — the handler retries **`playVideo`** only while **`EMBED_TRACK_SWITCH_PAUSE_GRACE_MS`** is active after **`loadAndPlayYoutubeVideo`**. Other embed **PAUSED** events (including PiP while the document is hidden) sync app transport **`PAUSE`**, disarm the embed start watchdog, and do not retry **`playVideo`**. **ENDED** still advances the queue for an active session even when transport is paused (YouTube often emits **PAUSED** immediately before **ENDED** in a background tab). While the session is **active** and the document is **hidden**, a **`setInterval`** (**`HIDDEN_TAB_YOUTUBE_PLAYER_STATE_POLL_MS`**) calls **`requestYoutubeEmbedPlaybackSync`** even when transport is **paused** (background **PAUSED** before **ENDED** must not stop polling — regression: **`when the tab is hidden and transport pauses before end, background polling still advances the queue`**); **`playVideo`** retries during the grace window run only while transport is **playing**. When the tab becomes visible again, **`requestYoutubeEmbedPlaybackSync`** (**`getPlayerState`**, **`getCurrentTime`**, **`getDuration`**), **`refreshYoutubeEmbedPlayerLayout`** (**`setSize`**, twice with a short delay), and **`schedulePlayFromGestureAttempts`** catch up missed **ended** state (including **paused at end** when **`currentTime`** reached **`duration`**), restore YouTube chrome after background **`loadVideoById`**, and resume or advance audio. Queue advance updates **`embedVideoId`** via **`syncEmbedToVideoId`**; once **`PersistentYoutubeIframe`** is mounted, track switches load **once** through the iframe’s **`videoId`** prop (postMessage), not a second imperative **`loadAndPlayYoutubeVideo`** from the provider. When the next queue row maps to the **same YouTube id** as the current track (common for one full-album upload), **`syncEmbedToVideoId`** and **`playQueueItem`** skip **`playVideo`** / gesture retries so playback continues instead of restarting; only the session metadata (track title, bar) updates. After pending resolution, **`resolvePlaybackVideoId`** prefers **`activeVideoId`** over a stale **`embedVideoId`**. **cued** state retriggers **`playVideo`** when autoplay is pending. **`pendingPlayFromGesture`** clears on embed **playing** so listener pauses from the YouTube UI still sync after playback is established.
