| Server-side infra       | [`reportInfrastructureFailure`](../../src/lib/sentry/reportInfrastructureFailure.ts) — DB pool (throttled **60s**), init health check, admin stats, public crate SSR. Transient pool failures (**`ECONNRESET`**, etc., and message-only pg-pool errors such as **`Connection terminated unexpectedly`**) are **not** reported outside **`environment:production`** ([`shouldCaptureInfrastructureFailure`](../../src/lib/sentry/shouldCaptureInfrastructureFailure.ts) via [`isTransientDatabaseConnectionFailure`](../../src/lib/databaseConnectionErrorMessage.ts)).**`resolveSentryEnvironment`** reads **`SENTRY_ENVIRONMENT`**, then **`NEXT_PUBLIC_VERCEL_ENV`**, then **`VERCEL_ENV`**, then **`NODE_ENV`** — specs that set **`VERCEL_ENV=production`** for production-only capture must **`delete`** **`SENTRY_ENVIRONMENT`** and **`NEXT_PUBLIC_VERCEL_ENV`** so the assertion is not overridden ([`shouldCaptureInfrastructureFailure.spec.ts`](../../src/lib/sentry/shouldCaptureInfrastructureFailure.spec.ts)).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |

Browser events use the **`/monitoring`** tunnel ([`tunnelRoute`](../../next.config.ts), forwarded by [`src/app/sentry-tunnel/route.ts`](../../src/app/sentry-tunnel/route.ts) via **`createSentryTunnelRoute`**) so ad blockers and CSP rarely block ingest. The app route caps request size (**`SENTRY_TUNNEL_MAX_BODY_BYTES`**, default **5 MiB**) and sets **`maxDuration = 60`** before forwarding to Sentry (SDK forward timeout remains **30s**). User-initiated sends (**Submit bug report**, skip toast **Report**) call **`deliverSentryClientCapture`** ([`deliverSentryClientCapture.client.ts`](../../src/lib/sentry/deliverSentryClientCapture.client.ts)) — shared **`captureFeedback`** + **`includeReplay: true`** ([`captureSentryUserFeedbackWithReplay.client.ts`](../../src/lib/sentry/captureSentryUserFeedbackWithReplay.client.ts)), then **`Sentry.flush`** — and only show success (**Sent**, thanks toast) when flush succeeds; auto playback skip **Issues** (**`reportPlaybackSkipToSentry`**) still **`captureAppMessage`** without flush. otherwise **`SENTRY_CLIENT_DELIVERY_FAILED_TOAST_MESSAGE`** ([`sentryUserFeedbackForm.constants.ts`](../../src/constants/sentryUserFeedbackForm.constants.ts)). Production builds set Sentry **`bundleSizeOptimizations`** in [`next.config.ts`](../../next.config.ts) (debug logging + Replay iframe/shadow-DOM capture stripped; **tracing stays enabled** for **`tracesSampleRate`** and App Router navigation). Compare client chunks with **`pnpm analyze`** after changing those flags. Product analytics consent (**GTM** / **`trackEvent`**) is separate — Sentry is operational error reporting, not marketing analytics. User-facing disclosure for Session Replay and bug-report attachments is in the Privacy Policy on **`/legal`** ([`LegalPageContent.server.tsx`](../../src/components/Legal/LegalPageContent.server.tsx)).
