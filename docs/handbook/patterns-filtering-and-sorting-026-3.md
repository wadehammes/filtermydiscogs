**Persistence**: User-selected filter inputs (styles, years, formats, primary sort, optional then-by sort, style operator, format operator, year operator, search query) persist in **`localStorage`** under **`filtermydiscogs_filters`** when **`preferences.persistFilters`** is **`true`** (account setting on **`User`**, default on). When enabled and authenticated, the same filter state is also stored on **`User.preferences.filters`** and synced across browsers via **`PATCH /api/user/preferences`** from **`useFiltersDispatch()`** (debounced through [`userPreferencesPersistQueue.ts`](../../src/utils/userPreferencesPersistQueue.ts)). **Saved views** (`filterViews`) are separate named snapshots (search, facets, sort) stored on **`User.preferences`** and synced via the same **`PATCH`** path from **`useFilterViews`**; they are cleared when the **`User`** row is deleted (**Delete account**). When **`false`**, each visit starts with default filters; in-session filtering still works.

Filter UI reads **`sessionFiltersAtom`** (defaults on load). Saved prefs hydrate into **`persistedFiltersAtom`** / server storage but do not populate the UI until the user applies them or changes filters in-session. [`useInitializePendingFiltersRestore`](../../src/hooks/useInitializePendingFiltersRestore.hook.ts) (in **`FiltersProvider`**) copies restorable saved prefs into **`pendingFiltersRestoreAtom`** when persisted filters hydrate and the session is still at defaults. After the collection finishes loading on **`/collection`**, [`useOfferPendingFiltersRestore`](../../src/hooks/useOfferPendingFiltersRestore.hook.ts) shows a bottom-center action toast (“Resume previous session?” with match preview) when no playback-page overlay has the scroll root locked (**`scrollLockCountRef`** via **`usePlaybackPageScrollLockCountRef`** — e.g. crate/filters/menu **`BottomDrawer`** open); the toast appears after those close and is dismissed when leaving **`/collection`**. **Resume** copies pending → session via **`applyPendingFiltersRestoreAtom`**, **Not now** clears pending and resets saved filter prefs (local **`persistedFiltersAtom`** / **`localStorage`**, plus debounced **`PATCH`** when persistence is enabled) so a refresh does not re-offer the toast. Any filter dispatch from the user clears pending and persists the new session state. **`collectionFiltersActiveAtom`** gates whether session inputs affect **`filteredReleases`** during pagination (full collection unfiltered until the last page). Collection data, random-mode pick, and the searching flag are **not** persisted. Cleared on **Clear stored data** (Settings / About / Legal), not on logout—same scope as view mode (one filter state per browser when persistence is enabled). Local filter PATCHes mark pending state in [`userPreferencesSyncState.ts`](../../src/utils/userPreferencesSyncState.ts) so [`useUserPreferencesSync`](../../src/hooks/useUserPreferencesSync.hook.ts) skips one redundant server hydrate when the mutation cache updates; server hydrate updates **`persistedFiltersAtom`** and re-offers pending restore when the session is still default.

**Lint guardrails**: Biome **`noRestrictedImports`** discourages **`useFilters`** / **`useView`** in application code—prefer **`useFilterAtoms`** / **`useViewAtoms`**. Context modules and test files are exempt.

Add filter dimensions by extending filter atoms/helpers and UI—not by filtering ad hoc in leaf components. Release note text is included in search via **`getReleaseNotesSearchText`** in [`releaseNotes.ts`](../../src/utils/releaseNotes.ts). **`SearchBar`** debounces input (300ms) and dispatches filter updates inside **`startTransition`** so typing stays responsive while the grid re-filters.
