- **Session state**: Core playback session fields live in [`playbackSessionState.ts`](../../src/utils/playbackSessionState.ts) as a discriminated union — **`idle`**, **`inactive`** (release visible, transport off), **`active`** (**`playing`** / **`paused`**) — so a release is never paired with impossible transport. **`validatePlaybackSessionState`** guards reducer output; selectors derive **`isPlaying`**, **`isPaused`**, and **`isMiniPlayerVisible`**. Session-derived refs sync via [`syncPlaybackSessionRefs.ts`](../../src/utils/syncPlaybackSessionRefs.ts). [`ReleasePlaybackProvider.component.tsx`](../../src/context/ReleasePlaybackProvider.component.tsx) dispatches session actions and keeps iframe postMessage, React Query, and **`localStorage`** persistence outside the reducer. [`useReleasePlaybackProvider.hook.ts`](../../src/hooks/useReleasePlaybackProvider.hook.ts) re-exports [`useReleasePlaybackProviderImpl.hook.ts`](../../src/hooks/useReleasePlaybackProviderImpl.hook.ts), which composes smaller hooks (dock scrub/volume/seek + throttled embed progress via [`useReleasePlaybackDockControls.hook.ts`](../../src/hooks/useReleasePlaybackDockControls.hook.ts) and [`useReleasePlaybackProviderDock.hook.ts`](../../src/hooks/useReleasePlaybackProviderDock.hook.ts); **`resetDockEmbedProgress`** / **`releaseStaleEmbedProgressGuard`** from that dock embed hook are passed into [`useReleasePlaybackQueueActions.hook.ts`](../../src/hooks/useReleasePlaybackQueueActions.hook.ts) and **`togglePlayback`**); iframe **`onStateChange`** branches: [`releasePlaybackYoutubeEmbedPlayerState.ts`](../../src/utils/releasePlaybackYoutubeEmbedPlayerState.ts) ([`releasePlaybackYoutubeEmbedPlayerState.spec.ts`](../../src/utils/releasePlaybackYoutubeEmbedPlayerState.spec.ts))); queue persist/history/**`setUpcomingQueue`**/tail auto-start sit in [`useReleasePlaybackQueueCoordination.hook.ts`](../../src/hooks/useReleasePlaybackQueueCoordination.hook.ts), with pure helpers [`releasePlaybackActivePresentation.ts`](../../src/utils/releasePlaybackActivePresentation.ts) (active track/video, title, **`resolvePresentationActiveVideoId`** — **user override → committed `embedVideoId` → Discogs match** so a stats-map gap does not snap back to the Discogs upload while an override embed is playing; **`resolvePlaybackVideoId`**, dock readiness via **`resolveIsPlaybackReady`** — **`isPlaybackReady`** when session transport is **`active`** and **`playbackVideoId`** is non-null, including embed-only ids while detail or track matching catches up) and [`releasePlaybackQueueAutoStart.ts`](../../src/utils/releasePlaybackQueueAutoStart.ts) (when to extend upcoming before **`playNext`**). **[`resolveActiveTrackHasYoutubeOverride`](../../src/utils/trackStatsQueryCache.ts)** in [`useReleasePlaybackProvider.hook.ts`](../../src/hooks/useReleasePlaybackProvider.hook.ts) feeds **`activeTrackHasYoutubeOverride`** (resolved override, pending stats, or **`embedVideoId`** ≠ Discogs match). Release detail fetch + tracklist index live in [`useReleasePlaybackReleaseDetail.hook.ts`](../../src/hooks/useReleasePlaybackReleaseDetail.hook.ts). Pending track/preview resolution lives in [`useReleasePlaybackPendingResolution.hook.ts`](../../src/hooks/useReleasePlaybackPendingResolution.hook.ts) with guards in [`releasePlaybackPendingResolution.ts`](../../src/utils/releasePlaybackPendingResolution.ts): **`SET_TRANSPORT_OFF`** runs only after release detail matches the playing release, tracks are loaded, and neither **`activeVideoId`** nor **`embedVideoId`** yields a video (release-preview paths excluded). Deferred album-tail rebuild after **`RESOLVE_PENDING_TRACK`** runs only when **`shouldApplyPendingAlbumQueueRebuild`** passes (**`shouldRebuildAlbumQueueRef`** and not **`queueManuallyExtendedRef`** — set by **`addToQueue`** / **`reorderQueue`**). While stats are pending or an override applies (**`shouldClearTransportForMissingVideo`** + **`activeTrackHasYoutubeOverride`**), transport stays up.
- **Playlists:** **Play playlist** / drawer row play replace the session queue via **`planPlaylistPlaybackStart`** (**`clearQueue`**, **`startPlayback`** + **`upcomingQueue`**) in playlist order ([`usePlaylistPlayback.hook.ts`](../../src/hooks/usePlaylistPlayback.hook.ts)). Each row’s **`track_position`** becomes the queue item’s **`trackPosition`** ([`resolvePlaylistTrackToQueueItem`](../../src/utils/playlistPlayback.ts)) — playback must honor that Discogs side/track, not default to the first track on the release. **Queue** on the playlist drawer footer (**`addPlaylistToQueue`**) appends playable rows without clearing transport (same preserve rules as release **Add to queue** when **`queueManuallyExtendedRef`** is set). DnD reorder can refresh upcoming via **`syncPlaylistQueueToTrackOrder`** when the queue already matches playlist order. **[`PlaylistDrawerFooter`](../../src/components/PlaylistDrawerFooter/PlaylistDrawerFooter.component.tsx)** **More** menu (**Rename** → [`CreatePlaylistDialog`](../../src/components/CreatePlaylistDialog/CreatePlaylistDialog.component.tsx) + **`useUpdatePlaylistMutation`**; **Delete** → **`ConfirmDialog`**) on all breakpoints; **`SegmentedControl`** uses **`allowOverflow`** so menus can portal above the drawer footer.
