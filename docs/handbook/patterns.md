# Patterns

Cross-cutting patterns for auth, global state, data fetching, filtering, and public pages.

## Provider stack

[`src/components/Providers.tsx`](../../src/components/Providers.tsx) nests providers in this order (outer → inner):

1. **QueryClientProvider** — TanStack Query defaults (10 min stale time, limited refetch).
2. **JotaiProvider** — shared Jotai store for client UI state ([`src/atoms/JotaiProvider.tsx`](../../src/atoms/JotaiProvider.tsx)).
3. **ThemeProvider** — palette themes (`light`, `dim`, `sepia`, `slate`, `dark`, `midnight`, `futuristic`, `high-contrast`) plus **`system`** (follows OS light/dark). Token files under [`src/styles/themes/`](../../src/styles/themes/). For PPR, the inner provider (media query + pathname sync) is wrapped in **`<Suspense>`** — see [platform.md](platform.md) (PPR and blocking client hooks).
4. **AuthProvider** — OAuth session state.
5. **CollectionContextProvider** — collection pagination metadata only (not the release list).
6. **FiltersProvider** — scope marker for filter hooks (state lives in [`src/atoms/filters.atoms.ts`](../../src/atoms/filters.atoms.ts)).
7. **CrateProvider** — active crate and crate list.
8. **ViewProvider** — scope marker for view hooks (state in [`src/atoms/view.atoms.ts`](../../src/atoms/view.atoms.ts)).

Inside **ViewProvider**: **`LogoutOverlayWrapper`**, **`AuthCheckingToast`**, and **`CollectionLoadingToast`**. **`CollectionDataSync`** (global [`useCollectionData`](../../src/hooks/useCollectionData.hook.ts) pagination) mounts beside page content under **`FiltersProvider`** so collection pages keep loading after navigation. **`AppToaster`** (Sonner) is a sibling under **ThemeProvider**, outside the auth subtree. Toast styling follows the active palette via CSS variables in [`sonner.css`](../../src/styles/sonner.css); call **`toast.success`**, **`toast.error`**, **`toast.loading`**, etc. from **`sonner`** instead of **`alert()`** for operational feedback (crate sync, logout/clear-data failures, clipboard copy, collection pagination away from **`/releases`**, and mutation errors in **`useCrateMutations`**).

**Jotai** backs **filters** and **view** preference state. Atoms and derived selectors live under [`src/atoms/`](../../src/atoms/); [`src/context/filters.context.tsx`](../../src/context/filters.context.tsx) and [`view.context.tsx`](../../src/context/view.context.tsx) expose scope markers and legacy `useFilters()` / `useView()` for full state. Prefer granular hooks from [`useFilterAtoms.hook.ts`](../../src/hooks/useFilterAtoms.hook.ts) and [`useViewAtoms.hook.ts`](../../src/hooks/useViewAtoms.hook.ts) so components subscribe only to the slice they need (for example `useSelectedStyles()`, `useFacetOptions()`, `useFilteredReleases()`, `useSortedFilteredReleases()`, `useCurrentView()`).

**Auth**, **collection**, **crate**, and **theme** still use React context. When adding a new global concern, use **Jotai** for derived client UI state with many subscribers; use **context + reducer** (or React Query) for session lifecycle, server-backed data, or side-effect-heavy flows.

## Authentication flow

1. **Start OAuth**: client navigates to **`GET /api/auth/discogs`**, which reuses stored OAuth tokens when present (no Discogs authorize screen) or starts a fresh OAuth flow. Pass **`?force=1`** to clear tokens and require a new Discogs authorization (e.g. **Use a different Discogs account** on the landing page).
2. **Callback**: **`GET /api/auth/callback`** exchanges verifier for access token, calls **`getIdentity`**, sets cookies, redirects to **`/releases?auth=success`**.
3. **Session check**: **`useAuthQuery`** ([`src/hooks/queries/useAuthQuery.ts`](../../src/hooks/queries/useAuthQuery.ts)) calls **`checkAuthStatus`** in [`src/services/auth.service.ts`](../../src/services/auth.service.ts) (wraps **`checkAuth`** → **`/api/auth/check`**) with **`refetchOnMount: "always"`**. Fetch/network failures resolve to unauthenticated (the query does not enter error state). **`AuthProvider`** keeps **`isCheckingAuth`** true until that mount revalidation settles (even if a cached authenticated session exists), then derives **`isAuthenticated`**, **`username`**, **`userId`**, and **`rateLimited`**. Collection queries ([`useCollectionData`](../../src/hooks/useCollectionData.hook.ts)) and crate queries stay disabled while **`isCheckingAuth`** or **`rateLimited`**. When Discogs is rate-limited, the check may return cookie-based identity with **`rateLimited: true`**; the query refetches every 60s (and on window focus) until verification succeeds—those later refetches do **not** flip **`isCheckingAuth`**. If a collection page returns **401**, [`useDiscogsCollectionQuery`](../../src/hooks/queries/useDiscogsCollectionQuery.ts) rechecks auth once (`retry: false` on that query): still authenticated → retry the page once; session gone → update the auth query so **`AuthProvider`** runs **`clearUserScopedQueries`** (never **`queryClient.clear()`**, which would wipe the auth query and refetch forever under **`refetchOnMount: "always"`**) and protected routes redirect home instead of showing a stuck “Not authenticated” error under a logged-in header. On OAuth success, **`refetch`** + **`clearUserScopedQueries`** reset cached user data; **`CrateProvider`** waits until **`isCheckingAuth`** is false before enabling crate queries (avoids a race with that cache clear), resets **`activeCrateId`** when **`userId`** changes, calls **`resetDrawer()`** on first login (null → user id) so the crate drawer follows viewport defaults, **`closeDrawer()`** on logout or user switch, and logs out if crate **`user_id`** does not match the session. Context reducer state is UI-only (**`isLoading`**, **`isLoggingOut`**, OAuth URL **`error`**). **`isLoading`** is reserved for an in-flight OAuth redirect after **Connect with Discogs**. The home page renders the landing immediately while **`isCheckingAuth`** runs, shows a subtle Sonner toast (**`AuthCheckingToast`**) while the session is verified, and redirects authenticated users to **`/releases`** when the check completes.
4. **Logout**: **`POST /api/auth/logout`** ends the app session and clears display cookies by default while **preserving OAuth tokens** for quick re-login on the same browser. Pass **`?preserve_tokens=false`** to revoke stored tokens. Client sets the auth query to unauthenticated, runs **`clearUserScopedQueries`**, and shows **`LogoutOverlay`**. **Clear stored data** (Settings, About, Legal) deletes the user's **`User`** row (cascades crates) and wipes OAuth tokens.

Cookie names and security flags: [discogs.md](discogs.md).

## Protected routes

Authenticated app routes use [`useRedirectIfUnauthenticated`](../../src/hooks/useRedirectIfUnauthenticated.hook.ts): while **`isCheckingAuth`**, render nothing briefly; when unauthenticated, **`router.replace("/")`**. **`/releases`** streams paginated collection pages into the grid as they arrive; [`StickyHeaderBar`](../../src/components/StickyHeaderBar/StickyHeaderBar.component.tsx) shows [`FiltersBarSkeleton`](../../src/components/StickyHeaderBar/components/FiltersBarSkeleton.component.tsx) until **`allReleasesLoaded`**, then swaps in the real [`FiltersBar`](../../src/components/StickyHeaderBar/components/FiltersBar.tsx) (skeleton genre/Match slots mirror **`styleFilterGroup`** component wrappers — see [conventions.md → Mobile filter controls](conventions.md#css-and-styling)). Header page navigation stays enabled during pagination — [`CollectionDataSync`](../../src/components/CollectionDataSync/CollectionDataSync.component.tsx) keeps fetching in the background, and [`CollectionLoadingToast`](../../src/components/CollectionLoadingToast/CollectionLoadingToast.component.tsx) shows a Sonner loading toast with the loaded count when the user leaves **`/releases`** before the sync finishes. Persisted filter prefs from **`localStorage`** apply only after the full collection load via **`collectionFiltersActiveAtom`** in [`filters.atoms.ts`](../../src/atoms/filters.atoms.ts) (set by [`useCollectionData`](../../src/hooks/useCollectionData.hook.ts)). **`/dashboard`** and **`/mosaic`** block until the full collection finishes loading via [`useNeedsCollectionLoad`](../../src/hooks/useNeedsCollectionLoad.hook.ts) (`isLoading`, **`hasNextPage`**, or **`isFetchingNextPage`** from [`useCollectionLoadState`](../../src/hooks/useCollectionData.hook.ts)). Dashboard shows [`DashboardSkeleton`](../../src/components/Dashboard/components/DashboardSkeleton.component.tsx) while pages stream in; progress appears in [`CollectionLoadingToast`](../../src/components/CollectionLoadingToast/CollectionLoadingToast.component.tsx) (Sonner + [`Spinner`](../../src/components/Spinner/Spinner.component.tsx)), not an inline status bar.

| Route | While `isCheckingAuth` | When unauthenticated | Collection loading |
|-------|------------------------|----------------------|--------------------|
| `/` | Landing + toast | Landing | — |
| `/releases` | null while checking auth | Redirect to `/` | Stream pages into grid; filter skeleton until done |
| `/dashboard`, `/mosaic` | Header + skeleton/loader until full collection load | Redirect to `/` | Skip when collection pagination is complete |
| `/admin` | Server gate + brief null | Redirect to `/` | — |

Authenticated app routes use segment **`loading.tsx`** with **`AppPageLoading`** ( **`StickyHeaderBar`**, not **`PublicAuthLayout`** ). **`page.tsx`** shells static-import their `*Client` component — avoid **`next/dynamic`** on those imports (Turbopack lazy-chunk bug); same for heavy in-tree splits such as dashboard charts and [`ReleasesTable`](../../src/components/ReleasesTable/ReleasesTable.component.tsx) in [`ReleasesGrid`](../../src/components/ReleasesClient/components/ReleasesGrid.component.tsx). Segment **`error.tsx`** files ([`releases`](../../src/app/releases/error.tsx), [`mosaic`](../../src/app/mosaic/error.tsx)) call **`retry()`** from Next.js 16.3 so recovery re-fetches server content, not just client state; keep them minimal (**`Page`**, message, native retry button in [`error.module.css`](../../src/app/error.module.css) — no **`StickyHeaderBar`**, **`Button`**, or filter/select trees) so Turbopack error-boundary chunks do not pull SVGR icons or the Node **`process`** polyfill in isolated runtimes. Dev-only error details use [`isLocalDevHost()`](../../src/utils/isLocalDevHost.ts), not **`process.env.NODE_ENV`**. Root [`loading.tsx`](../../src/app/loading.tsx) is a provider-free **`PageLoader`** only — Next also mounts it under **`/_global-error`**, which replaces the root layout (no **`Providers`**). Root layout failures use [`global-error.tsx`](../../src/app/global-error.tsx) (own document shell; no **`Providers`** / **`useAuth`**; no **`src/components`** — only [`isLocalDevHost()`](../../src/utils/isLocalDevHost.ts) + [`global-error.module.css`](../../src/app/global-error.module.css)).

## Public pages

Server `page.tsx` files for home, about, legal, and public crates share one client shell:

1. **`PublicAuthLayout`** — header (`PublicAuthHeader` → `PublicPageHeader` or authenticated `StickyHeaderBar`), `<main>`, optional `footer`.
2. **`PageFooter`** (server component) — community stats (`PageFooterStats` / `PageFooterFun`) plus About / Contribute links. Pass as the layout `footer` prop from each `page.tsx`.
3. **Page content** — e.g. [`Login`](../../src/components/Login/Login.component.tsx) on `/`, `AboutClient` / [`LegalPageContent`](../../src/app/legal/LegalPageContent.server.tsx), or public crate client.

Home renders the landing immediately during **`isCheckingAuth`**; authenticated users redirect from **`Login`** via `router.replace("/releases")`. Protected app routes use **`AppPageLoading`** (see Protected routes above), not a blocking auth shell on `/`.

## API layer

Route outbound browser HTTP through **[`src/api/helpers.ts`](../../src/api/helpers.ts)**—the single front door for collection, crates, search, release fetch, auth check/logout/clear-data, and dashboard stats.

- **Do not** call Discogs or `/api/...` with raw **`fetch`** from components or query hook files.
- **Do not** call Discogs directly from the browser; route handlers sign OAuth requests server-side.
- **Adding a new endpoint**: (1) Add a typed helper in `src/api/helpers.ts`. (2) Add or extend a route handler under `src/app/api/`. (3) Add a dedicated hook under `src/hooks/queries/` that calls the helper in `queryFn`.

## React Query

- **Provider**: [`Providers.tsx`](../../src/components/Providers.tsx) creates **`QueryClient`** and wraps the tree.
- **Hooks**: [`src/hooks/queries/`](../../src/hooks/queries/) — one file per query or mutation bundle.
- **Query keys**: [`querykeys.constants.ts`](../../src/hooks/queries/querykeys.constants.ts) — use factories everywhere (hooks, invalidation, optimistic cache keys).

| Hook | Key factory | Purpose |
|------|-------------|---------|
| `useAuthQuery` | `AuthQueryKeys.all` | Session check (`/api/auth/check`) |
| `useDiscogsCollectionQuery` | `DiscogsCollectionQueryKeys.byUsername` | Infinite collection pages |
| `useCollectionFieldsQuery` | `CollectionFieldsQueryKeys.byUsername` | Discogs collection custom-field definitions (notes editor) |
| `useCollectionValueQuery` | `CollectionValueQueryKeys.byUsername` | Collection dollar value |
| `useDiscogsReleaseQuery` | `DiscogsReleaseQueryKeys.byId` | Single release fetch |
| `useCratesQuery` / `useCrateQuery` | `CratesQueryKeys` / `CrateQueryKeys` | Crate list and detail (`useCrateQuery` is exported from [`useCratesQuery.ts`](../../src/hooks/queries/useCratesQuery.ts)) |
| `usePublicCrateQuery` | `PublicCrateQueryKeys.byId` | Public crate page |
| `useMostCratedQuery` | `MostCratedQueryKeys.list` | Dashboard stats |
| `useAdminStatsQuery` | `AdminStatsQueryKeys.all` | Admin dashboard |

Hook rules (single params object, no side effects in hook files): [conventions.md → React Query](conventions.md#react-query).

**`useCollectionData`** composes auth state + collection query + context dispatch for the releases/dashboard pages. Invalidate with **`DiscogsCollectionQueryKeys`** when the username changes ([`useCollectionData.hook.ts`](../../src/hooks/useCollectionData.hook.ts), [`auth.context.tsx`](../../src/context/auth.context.tsx)).

**Mutations**: [`useCrateMutations.ts`](../../src/hooks/queries/useCrateMutations.ts) — optimistic updates use the same **`CrateQueryKeys`** / **`CratesQueryKeys`** as queries.

## Filtering and sorting

1. **`useCollectionData`** auto-chains paginated Discogs pages and dispatches **`FiltersActionTypes.SetAllReleases`** after **each** page so the releases grid fills in incrementally (via raw **`filtersDispatchAtom`**, not **`useFiltersDispatch()`**, so collection hydration never PATCHes prefs). It skips redundant dispatches when the release count and collection metadata are unchanged. The first fetch is a **bootstrap** page of 50; if more remain, pagination restarts at page size 100 (see [discogs.md](discogs.md) → Client-side collection access). **`collectionFiltersActiveAtom`** stays false until pagination finishes, so persisted filter prefs do not winnow the in-progress list. When the last page arrives, **`useCollectionData`** sets **`collectionFiltersActiveAtom`** to true so in-session filter inputs can affect the grid; saved prefs are **not** auto-applied (see **Persistence** below). Collection context keeps pagination metadata (`collection`, `fetchingCollection`, `error`) only—not a duplicate release list.
2. **Filter atoms** ([`filters.atoms.ts`](../../src/atoms/filters.atoms.ts)) derive **`filteredReleases`** and facet dropdown options from filter inputs via:
   - [`computeFilterDerivedState.ts`](../../src/utils/computeFilterDerivedState.ts) — one pass over the collection for both the filtered list and facet options ([`filterReleases.ts`](../../src/utils/filterReleases.ts) and [`computeFacetOptions.ts`](../../src/utils/computeFacetOptions.ts) are thin wrappers for tests and direct callers); [`sortReleases.ts`](../../src/utils/sortReleases.ts) runs on the filtered list in a separate derived atom so sort changes do not re-scan facets
   - **Facet options** — each dropdown’s choices come from releases matching the *other* active filters; e.g. with **Rock** selected, year and format lists only show values present on Rock releases, while the genre/style list still reflects search/year/format constraints so you can add another tag. Genres and styles share the **Genre & Style** filter via [`releaseGenreStyleTags.ts`](../../src/utils/releaseGenreStyleTags.ts). Search text and genre/style/format tags are pre-indexed per release ([`releaseSearchIndex.ts`](../../src/utils/releaseSearchIndex.ts)); `SetAllReleases` calls **`syncReleaseSearchIndex`** so pagination appends and note edits reindex only changed rows instead of rebuilding the whole map. Queries match all whitespace-separated tokens against title, artist, label, catno, notes, and genre/style tags ([`releaseFilterMatchers.ts`](../../src/utils/releaseFilterMatchers.ts)). Shared filter inputs use **`ReleaseFilterCriteria`** and facet shapes use **`FacetOptions`** in [`filters.types.ts`](../../src/types/filters.types.ts).
3. UI components (`FiltersBar`, [`FiltersDrawer`](../../src/components/FiltersDrawer/FiltersDrawer.component.tsx), release cards, [`ReleasesTable`](../../src/components/ReleasesTable/ReleasesTable.component.tsx)) dispatch filter actions through **`useFiltersDispatch()`** and read state via **`useFilterAtoms`** hooks; **`useFilteredReleases()`** drives the visible grid (one random release in random mode, otherwise the sorted filtered list); **`useMemoizedFilteredReleases()`** / **`useSortedFilteredReleases()`** expose the full sorted match set for mosaic input and random re-pick; **`useFacetOptions()`** supplies facet dropdown choices. Dashboard/analytics read the same list via **`useAllReleases()`**. On mobile, filters open from the header filter control into **`FiltersDrawer`** (same filter atoms as desktop **`FiltersBar`**); the drawer title and footer show the applied filter count via **`useAppliedFilterCount()`** / [`getAppliedFilterCount.ts`](../../src/utils/getAppliedFilterCount.ts) (search plus each multi-select dimension: genre/style, year, format — sort is excluded). Multi-select facet filters in the drawer use searchable **`AutocompleteSelect`** (same component as desktop **`FiltersBar`**, with **`showLabel`** and optional **`clearable`** **Clear**); sort/match stay on plain **`Select`**. The mobile header filter icon shows a numeric badge when filters are active and uses **`var(--primary)`** (theme primary) on the icon via **`.active`** / **`.filterIconActive`**, matching the adjacent random-mode control. The drawer footer includes **Clear All**; filter changes apply live (same atoms as desktop **`FiltersBar`**) and closing the drawer does not revert them. The filter control stays hidden until **`allReleasesLoaded`** (same gate as desktop **`FiltersBar`**). **`SearchBar`**, **`Select`**, and **`AutocompleteSelect`** share aligned mobile tap targets (**`--touch-target-min`**) in the drawer. **`SearchBar`** flushes a pending debounced query on unmount so closing the drawer does not drop in-progress search text.

**Persistence**: User-selected filter inputs (styles, years, formats, sort, style operator, search query) persist in **`localStorage`** under **`filtermydiscogs_filters`** when **`preferences.persistFilters`** is **`true`** (account setting on **`User`**, default on). When enabled and authenticated, the same filter state is also stored on **`User.preferences.filters`** and synced across browsers via **`PATCH /api/user/preferences`** from **`useFiltersDispatch()`** (debounced through [`userPreferencesPersistQueue.ts`](../../src/utils/userPreferencesPersistQueue.ts)). When **`false`**, each visit starts with default filters; in-session filtering still works.

Filter UI reads **`sessionFiltersAtom`** (defaults on load). Saved prefs hydrate into **`persistedFiltersAtom`** / server storage but do not populate the UI until the user applies them or changes filters in-session. [`useInitializePendingFiltersRestore`](../../src/hooks/useInitializePendingFiltersRestore.hook.ts) (in **`FiltersProvider`**) copies restorable saved prefs into **`pendingFiltersRestoreAtom`** when persisted filters hydrate and the session is still at defaults. After the collection finishes loading on **`/releases`**, [`useOfferPendingFiltersRestore`](../../src/hooks/useOfferPendingFiltersRestore.hook.ts) shows a Sonner toast (“Resume previous session?” with match preview); **Resume** copies pending → session via **`applyPendingFiltersRestoreAtom`**, **Not now** clears pending. Any filter dispatch from the user clears pending and persists the new session state. **`collectionFiltersActiveAtom`** gates whether session inputs affect **`filteredReleases`** during pagination (full collection unfiltered until the last page). Collection data, random-mode pick, and the searching flag are **not** persisted. Cleared on **Clear stored data** (Settings / About / Legal), not on logout—same scope as view mode (one filter state per browser when persistence is enabled). Local filter PATCHes mark pending state in [`userPreferencesSyncState.ts`](../../src/utils/userPreferencesSyncState.ts) so [`useUserPreferencesSync`](../../src/hooks/useUserPreferencesSync.hook.ts) skips one redundant server hydrate when the mutation cache updates; server hydrate updates **`persistedFiltersAtom`** and re-offers pending restore when the session is still default.

**Lint guardrails**: Biome **`noRestrictedImports`** discourages **`useFilters`** / **`useView`** in application code—prefer **`useFilterAtoms`** / **`useViewAtoms`**. Context modules and test files are exempt.

Add filter dimensions by extending filter atoms/helpers and UI—not by filtering ad hoc in leaf components. Release note text is included in search via **`getReleaseNotesSearchText`** in [`releaseNotes.ts`](../../src/utils/releaseNotes.ts). **`SearchBar`** debounces input (300ms) and dispatches filter updates inside **`startTransition`** so typing stays responsive while the grid re-filters.

## Collection notes (scoped provider)

Release-card notes use a **feature-local provider**, not a global entry in **`Providers.tsx`**:

1. **`ReleaseNotesEditorProvider`** wraps each **`ReleaseCard`** / **`MobileReleaseCard`** (and release modal notes) and calls **`useReleaseNotesEditor(release)`** once; it mounts **`ReleaseNotesEditorDialog`** so overlay icons open **`NoteEditDialog`** even when the card body omits inline notes.
2. **`ReleaseNotesCardAction`** (and **`ReleaseNotes`** on mobile list rows) read **`useReleaseNotesEditorContext()`** to open the same **`NoteEditDialog`**. Grid and mobile release cards show the notes icon on the overlay action strip only—a primary dot badge when notes exist, no inline note preview.
3. Saves go through **`updateCollectionNote`** in [`src/api/helpers.ts`](../../src/api/helpers.ts) → **`POST /api/collection/instances/.../fields/...`** → **`discogsOAuthService.updateCollectionInstanceField`**.

Colocate feature hooks under the component folder ([`useReleaseNotesEditor.hook.ts`](../../src/components/ReleaseNotes/useReleaseNotesEditor.hook.ts)); keep shared React Query hooks in [`src/hooks/queries/`](../../src/hooks/queries/).

## Crates

- **Client**: `CrateProvider` + **`useCrateMutations`** talk to **`/api/crates`** via **`src/api/helpers.ts`**. Components call **`useCrate()`** actions (`updateCrate`, `createCrate`, …) — not mutation hooks directly. Mutation **`onError`** handlers in **`useCrateMutations`** show Sonner toasts and roll back optimistic cache updates; UI handlers only await success and update local dialog state. Crate list (`useCratesQuery`) and active crate releases (`useCrateQuery`) are separate queries — both stay disabled while **`isCheckingAuth`** or **`rateLimited`**; on first login, **`CrateProvider`** invalidates both after **`userId`** arrives, re-selects the default crate, and refetches detail (dropping cached detail first) if list **`releaseCount`** and loaded releases disagree.
- **UI**: [`CrateDrawer`](../../src/components/CrateDrawer/CrateDrawer.component.tsx) sidebar on desktop (≥1024px) and bottom drawer on mobile — a **staging** surface on **`/releases`** only: [`CrateSelector`](../../src/components/CrateSelector/CrateSelector.component.tsx), release list ([`CrateDrawerReleases`](../../src/components/CrateDrawer/CrateDrawerReleases.component.tsx) — cover/title/meta in layout **`sort_order`**, **remove**, and when **`packed_enabled`**: shared [`CrateReleaseListToolbar`](../../src/components/CrateDrawer/CrateReleaseListToolbar.component.tsx) (sticky in the drawer scroll area — from [`CrateDrawerReleases`](../../src/components/CrateDrawer/CrateDrawerReleases.component.tsx); page-header sticky on owner detail; mobile scroll on [`BottomDrawer`](../../src/components/BottomDrawer/BottomDrawer.component.tsx) **`.content`** only — **`mobileContent`** does not scroll; desktop scroll on sidebar **`.content`**; flush scroll **`padding-top`** when **`packedCount > 0`** via **`contentClassName`** / **`.contentFlushTop`**, else **`space-4`** top inset) + per-release packed toggle (**primary outer border** when packed); section markers are omitted), footer [`CrateSetNotesScratchpad`](../../src/components/CrateDrawer/CrateSetNotesScratchpad.component.tsx) (`variant="drawer"` — debounced autosave; toggled via **Notes** in the footer segmented control, hidden by default), then **Open crate** (links to [`/crates/[id]`](../../src/app/crates/[id]/page.tsx)), **Default**, **Empty**, with shared [`CrateShareControls`](../../src/components/CrateDrawer/CrateShareControls.component.tsx) at the bottom (**Public link** switch + inline **Copy link** when on). Each subcomponent owns a co-located **`.module.css`** under [`CrateDrawer/`](../../src/components/CrateDrawer/) (shell, footer, releases, release rows); scratchpad composes shared tokens from [`scratchpad-textarea.module.css`](../../src/styles/scratchpad-textarea.module.css). On mobile, [`ReleasesClient`](../../src/components/ReleasesClient/ReleasesClient.component.tsx) wraps the drawer in **`.sidebar`** with **`display: contents`** so the bottom drawer is not suppressed by **`display: none`**. **`CrateDrawerProvider`** ([`CrateDrawer.context.tsx`](../../src/components/CrateDrawer/CrateDrawer.context.tsx)) wraps the drawer shell and calls **`useCrateDrawerState`** once; the same provider/context also powers owner pages (detail actions menu, set-notes scratchpad, packing toolbar). **Open/closed state** lives in [`useCrateDrawer`](../../src/hooks/useCrateDrawer.hook.ts): `isDrawerOpen = userToggled ?? isDesktop`. Use **`openDrawer()`** / **`closeDrawer()`** for explicit user actions; **`resetDrawer()`** clears `userToggled` back to viewport default. **`addToCrate`** opens the drawer only when **`isDesktop`**. After OAuth login, **`CrateProvider`** calls **`resetDrawer()`**; logout/user switch calls **`closeDrawer()`**. Mobile crate FAB on **`/releases`** offsets above the mini player dock (**.crateFabAboveDock** when playback is active) and hides while the mobile menu, filters drawer, or playback queue (**`data-playback-queue-open`**) is open. ## Release playback queue

- **Scope**: Global playback queue in **`ReleasePlaybackProvider`** — cross-release **`PlaybackQueueItem[]`** with **`queueIndex`**. Clicking a track row calls **`startPlayback`**, which seeds the queue with that track and then rebuilds the remainder of the **playable album queue** (flattened tracks with embeddable YouTube matches from the clicked position onward). **`addToQueue`** appends from the tracklist **Add to queue** control (list-plus icon; deduped by **`instanceId` + `trackPosition`**). **`reorderQueue`** reorders rows from the queue drawer (drag handle, `@dnd-kit`) and keeps the active track playing. Prev/next and dock transport walk the full queue, not only the current album.
- **Placement**: **`ReleasePlaybackProvider`** and **`GlobalPlaybackDock`** live in global **`Providers`** (after **`CollectionContextProvider`** / **`FiltersProvider`**) so playback and the YouTube iframe survive client-side route changes. **`PlaybackReleaseClickProvider`** registers per-page **`onReleaseClick`** handlers (release modal) via **`useRegisterPlaybackReleaseClick`**. **[`PlaybackPageShell`](../../src/components/ReleasePlayback/PlaybackPageShell.component.tsx)** handles page scroll layout only (header / main / overlays). Closing **`ReleaseModal`** does not stop playback.
- **UI**: [`ReleaseMiniPlayer`](../../src/components/ReleasePlayback/ReleaseMiniPlayer.component.tsx) is a slim background-playback dock (cover, title, prev/play-pause/next/stop). A **queue** control opens **[`PlaybackQueueDrawer`](../../src/components/ReleasePlayback/PlaybackQueueDrawer.component.tsx)** (drag-to-reorder, list, play at index, remove row, clear queue). By default the YouTube embed is hidden (audio-only). A **video** control toggles a 16:9 panel ([`ReleasePlaybackVideoPanel`](../../src/components/ReleasePlayback/ReleasePlaybackVideoPanel.component.tsx)). The dock video panel **auto-expands once** the first time playback becomes ready in the bar (tracked in **`localStorage`** via [`playbackVideoIntroStorage.ts`](../../src/utils/playbackVideoIntroStorage.ts)) so listeners discover the control; later sessions still **auto-expand whenever autoplay playback starts** (e.g. a track row click in **`ReleaseModal`**, or prev/next in the dock) unless the listener collapsed the panel with the video control or close bar. Restore-after-refresh playback starts **paused** and keeps the panel collapsed until the listener taps play. On **mobile**, the panel is full viewport width, stacked above the mini-player bar inside **`PlaybackPageShell`**, with a top close bar (no drag/resize). Opening the **filters drawer** auto-collapses the mobile video panel and sizes the drawer to the space above the mini-player bar only; the listener can re-open video from the mini-player while filters stay open ([`useFiltersDrawerOpen`](../../src/hooks/useFiltersDrawerOpen.hook.ts), [`PlaybackPageShell.module.css`](../../src/components/ReleasePlayback/PlaybackPageShell.module.css)). On **desktop** it defaults above the mini-player release metadata, left-aligned at full size as a floating panel — drag the top handle to reposition, drag the bottom-right handle to shrink (not enlarge), and double-click the top handle to reset layout; layout persists for the browser session until the viewport crosses back from mobile to desktop or a stored position no longer fits the viewport, when position and scale reset to that default. Native browser PiP is not used — YouTube iframe embeds do not expose reliable programmatic PiP from app code. Cover/title opens **`ReleaseModal`**. Play/pause sends YouTube iframe commands via **`togglePlayback`**. [`PersistentYoutubeIframe`](../../src/components/ReleasePlayback/PersistentYoutubeIframe.component.tsx) keeps a single embed mounted in the dock; when collapsed it stays off-screen for audio-only playback. Embeds use **`playsinline=1`** for iOS. A track row click in **`ReleaseModal`** calls **`startPlayback`**; closing the modal does not stop playback. **`startPlayback`** schedules **`playVideo`** iframe commands (with retries up to 3s) and **`resumePlaybackFromGesture`** re-fires when the embed becomes visible so mobile track picks can start after the panel opens. Prev/next advance within the global queue (no auto-advance on video end in v1) and keep the video panel open when it was already expanded. Queue utilities: [`playbackQueue.ts`](../../src/utils/playbackQueue.ts); video matching: [`releasePlayback.ts`](../../src/utils/releasePlayback.ts).
- **Resume after refresh**: **`startPlayback`** writes `{ instanceId, trackPosition }` to **`localStorage`** immediately; the provider keeps it updated while playback is active. The **queue is not persisted** — restore re-seeds it as the playable album from the saved track (manually appended cross-release entries are lost). Restore waits for auth (`isCheckingAuth`), the collection to finish loading (`collection !== null`, not fetching), and any remaining pages (`collection.pagination.urls.next`) before giving up — on any route, not only **`/releases`**. Restore reopens the dock **paused** — browsers block autoplay without a user gesture, so the listener taps play to resume audio. Cleared on stop, logout, and **Clear stored data**.
