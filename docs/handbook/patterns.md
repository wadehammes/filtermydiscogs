# Patterns

Cross-cutting patterns for auth, global state, data fetching, filtering, and public pages.

## Provider stack

[`src/components/Providers.tsx`](../../src/components/Providers.tsx) nests providers in this order (outer → inner):

1. **QueryClientProvider** — TanStack Query defaults (10 min stale time, limited refetch).
2. **JotaiProvider** — shared Jotai store for client UI state ([`src/atoms/JotaiProvider.tsx`](../../src/atoms/JotaiProvider.tsx)).
3. **ThemeProvider** — palette themes (`light`, `dim`, `sepia`, `forest`, `amber`, `slate`, `dark`, `midnight`, `codex`, `discogs`, `wine`, `futuristic`, `high-contrast`) plus **`system`** (follows OS light/dark). Token files under [`src/styles/themes/`](../../src/styles/themes/). For PPR, the inner provider (media query + pathname sync) is wrapped in **`<Suspense>`** — see [platform.md](platform.md) (PPR and blocking client hooks).
4. **AuthProvider** — OAuth session state.
5. **CollectionContextProvider** — collection pagination metadata only (not the release list).
6. **FiltersProvider** — scope marker for filter hooks (state lives in [`src/atoms/filters.atoms.ts`](../../src/atoms/filters.atoms.ts)).
7. **CrateProvider** — active crate and crate list.
8. **ViewProvider** — scope marker for view hooks (state in [`src/atoms/view.atoms.ts`](../../src/atoms/view.atoms.ts)).

Inside **ViewProvider**: **`LogoutOverlayWrapper`**, **`AuthCheckingToast`**, **`CollectionLoadingToast`**, and **`DeploymentUpdateToast`**. **`CollectionDataSync`** (global [`useCollectionData`](../../src/hooks/useCollectionData.hook.ts) pagination) mounts beside page content under **`FiltersProvider`** so collection pages keep loading after navigation. **`AppToaster`** (Sonner) is a sibling under **ThemeProvider**, outside the auth subtree. Toast styling follows the active palette via CSS variables in [`global/sonner.css`](../../src/styles/global/sonner.css); call **`toast.success`**, **`toast.error`**, **`toast.loading`**, etc. from **`sonner`** instead of **`alert()`** for operational feedback (crate sync, logout/clear-data failures, clipboard copy, large-collection pagination progress, mutation errors in **`useCrateMutations`**, and production deploy nudges from **`DeploymentUpdateToast`**).

**Jotai** backs **filters** and **view** preference state. Atoms and derived selectors live under [`src/atoms/`](../../src/atoms/); [`src/context/filters.context.tsx`](../../src/context/filters.context.tsx) and [`view.context.tsx`](../../src/context/view.context.tsx) expose scope markers and legacy `useFilters()` / `useView()` for full state. Prefer granular hooks from [`useFilterAtoms.hook.ts`](../../src/hooks/useFilterAtoms.hook.ts) and [`useViewAtoms.hook.ts`](../../src/hooks/useViewAtoms.hook.ts) so components subscribe only to the slice they need (for example `useSelectedStyles()`, `useFacetOptions()`, `useFilteredReleases()`, `useSortedFilteredReleases()`, `useCurrentView()`).

**Auth**, **collection**, **crate**, and **theme** still use React context. When adding a new global concern, use **Jotai** for derived client UI state with many subscribers; use **context + reducer** (or React Query) for session lifecycle, server-backed data, or side-effect-heavy flows.

## Authentication flow

1. **Start OAuth**: client navigates to **`GET /api/auth/discogs`**, which reuses stored OAuth tokens when present (no Discogs authorize screen) or starts a fresh OAuth flow. Pass **`?force=1`** to clear tokens and require a new Discogs authorization (e.g. **Use a different Discogs account** on the landing page).
2. **Callback**: **`GET /api/auth/callback`** exchanges verifier for access token, calls **`getIdentity`**, sets cookies, redirects to **`/releases?auth=success`**.
3. **Session check**: **`useAuthQuery`** ([`src/hooks/queries/useAuthQuery.ts`](../../src/hooks/queries/useAuthQuery.ts)) calls **`checkAuthStatus`** in [`src/services/auth.service.ts`](../../src/services/auth.service.ts) (wraps **`checkAuth`** → **`/api/auth/check`**) with **`refetchOnMount: "always"`**. Fetch/network failures resolve to unauthenticated (the query does not enter error state). **`AuthProvider`** keeps **`isCheckingAuth`** true until that mount revalidation settles (even if a cached authenticated session exists), then derives **`isAuthenticated`**, **`username`**, **`userId`**, and **`rateLimited`**. Collection queries ([`useCollectionData`](../../src/hooks/useCollectionData.hook.ts)) and crate queries stay disabled while **`isCheckingAuth`** or **`rateLimited`**. When Discogs is rate-limited, the check may return cookie-based identity with **`rateLimited: true`**; the query refetches every 60s (and on window focus) until verification succeeds—those later refetches do **not** flip **`isCheckingAuth`**. If a collection page returns **401**, [`useDiscogsCollectionQuery`](../../src/hooks/queries/useDiscogsCollectionQuery.ts) rechecks auth once (`retry: false` on that query): still authenticated → retry the page once; session gone → update the auth query so **`AuthProvider`** runs **`clearUserScopedQueries`** (never **`queryClient.clear()`**, which would wipe the auth query and refetch forever under **`refetchOnMount: "always"`**) and protected routes redirect home instead of showing a stuck “Not authenticated” error under a logged-in header. On OAuth success, **`refetch`** + **`clearUserScopedQueries`** reset cached user data; **`CrateProvider`** waits until **`isCheckingAuth`** is false before enabling crate queries (avoids a race with that cache clear), resets **`activeCrateId`** when **`userId`** changes, calls **`resetDrawer()`** on first login (null → user id) so the crate drawer follows viewport defaults, **`closeDrawer()`** on logout or user switch, and logs out if crate **`user_id`** does not match the session. Context reducer state is UI-only (**`isLoading`**, **`isLoggingOut`**, OAuth URL **`error`**). **`isLoading`** is reserved for an in-flight OAuth redirect after **Connect with Discogs**. The home page renders the landing immediately while **`isCheckingAuth`** runs, shows a subtle Sonner toast (**`AuthCheckingToast`**) while the session is verified, and redirects authenticated users to **`/releases`** when the check completes.
4. **Logout**: **`POST /api/auth/logout`** ends the app session and clears display cookies by default while **preserving OAuth tokens** for quick re-login on the same browser. Pass **`?preserve_tokens=false`** to revoke stored tokens. Client sets the auth query to unauthenticated, runs **`clearUserScopedQueries`**, and shows **`LogoutOverlay`**. **Clear stored data** (Settings, About, Legal) deletes the user's **`User`** row (cascades crates) and wipes OAuth tokens.

Cookie names and security flags: [discogs.md](discogs.md).

## Protected routes

Authenticated app routes use [`useRedirectIfUnauthenticated`](../../src/hooks/useRedirectIfUnauthenticated.hook.ts): while **`isCheckingAuth`**, render nothing briefly; when unauthenticated, **`router.replace("/")`**. **`/releases`** streams paginated collection pages into the grid as they arrive; [`StickyHeaderBar`](../../src/components/StickyHeaderBar/StickyHeaderBar.component.tsx) shows [`FiltersBarSkeleton`](../../src/components/StickyHeaderBar/FiltersBarSkeleton.component.tsx) until **`allReleasesLoaded`**, then swaps in the real [`FiltersBar`](../../src/components/StickyHeaderBar/FiltersBar.tsx) (skeleton mirrors the bar DOM: search, three **`styleFilterGroup`** slots for genre, format, and release year/Match, then sort — see [conventions.md → Mobile filter controls](conventions.md#css-and-styling)). Header page navigation stays enabled during pagination — [`CollectionDataSync`](../../src/components/CollectionDataSync/CollectionDataSync.component.tsx) keeps fetching in the background, and [`CollectionLoadingToast`](../../src/components/CollectionLoadingToast/CollectionLoadingToast.component.tsx) shows a bottom-center Sonner loading toast (with total size from Discogs **`pagination.items`**, or remembered size from **`localStorage`**) when the collection has more than **`COLLECTION_LARGE_MIN_ITEMS` (1000)** releases and pagination is still in progress. Persisted filter prefs from **`localStorage`** apply only after the full collection load via **`collectionFiltersActiveAtom`** in [`filters.atoms.ts`](../../src/atoms/filters.atoms.ts) (set by [`useCollectionData`](../../src/hooks/useCollectionData.hook.ts)). **`/dashboard`** and **`/mosaic`** block until the full collection finishes loading via [`useNeedsCollectionLoad`](../../src/hooks/useNeedsCollectionLoad.hook.ts) (`isLoading`, **`hasNextPage`**, or **`isFetchingNextPage`** from [`useCollectionLoadState`](../../src/hooks/useCollectionData.hook.ts)). Dashboard shows [`DashboardSkeleton`](../../src/components/Dashboard/DashboardSkeleton.component.tsx) while pages stream in; large-collection progress appears in [`CollectionLoadingToast`](../../src/components/CollectionLoadingToast/CollectionLoadingToast.component.tsx) (Sonner + [`Spinner`](../../src/components/Spinner/Spinner.component.tsx)), not an inline status bar.

| Route | While `isCheckingAuth` | When unauthenticated | Collection loading |
|-------|------------------------|----------------------|--------------------|
| `/` | Landing + toast | Landing | — |
| `/releases` | null while checking auth | Redirect to `/` | Stream pages into grid; filter skeleton until done |
| `/dashboard`, `/mosaic` | Header + skeleton/loader until full collection load | Redirect to `/` | Skip when collection pagination is complete |
| `/admin` | Server gate + brief null | Redirect to `/` | — |

Authenticated app routes use segment **`loading.tsx`** with **`AppPageLoading`** ( **`StickyHeaderBar`**, not **`PublicAuthLayout`** ). **`page.tsx`** shells static-import their `*Client` component — avoid **`next/dynamic`** on those imports (Turbopack lazy-chunk bug); same for heavy in-tree splits such as dashboard charts and [`ReleasesTable`](../../src/components/ReleasesTable/ReleasesTable.component.tsx) in [`ReleasesGrid`](../../src/components/ReleasesClient/ReleasesGrid.component.tsx). Segment **`error.tsx`** files ([`releases`](../../src/app/releases/error.tsx), [`mosaic`](../../src/app/mosaic/error.tsx)) call **`retry()`** from Next.js 16.3 so recovery re-fetches server content, not just client state; keep them minimal (self-contained shell from [`error-boundary.module.css`](../../src/styles/modules/error-boundary.module.css), message, native retry button — **no `Page`**, **`StickyHeaderBar`**, **`Button`**, or filter/select trees) so Turbopack error-boundary chunks do not pull shared layout modules, SVGR icons, or the Node **`process`** polyfill in isolated runtimes. Dev-only error details use [`isLocalDevHost()`](../../src/utils/isLocalDevHost.ts), not **`process.env.NODE_ENV`**. Root [`loading.tsx`](../../src/app/loading.tsx) is a provider-free **`PageLoader`** only — Next also mounts it under **`/_global-error`**, which replaces the root layout (no **`Providers`**). Root layout failures use [`global-error.tsx`](../../src/app/global-error.tsx) (own document shell; no **`Providers`** / **`useAuth`**; no **`src/components`** — only [`isLocalDevHost()`](../../src/utils/isLocalDevHost.ts) + [`global-error.module.css`](../../src/app/global-error.module.css)).

## Public pages

Server `page.tsx` files for home, about, legal, and public crates share one client shell:

1. **`PublicAuthLayout`** — header (`PublicAuthHeader` → `PublicPageHeader` or authenticated `StickyHeaderBar`), `<main>`, optional `footer`.
2. **`PageFooter`** (server component) — community stats (`PageFooterStats` / `PageFooterFun`) plus About / Contribute links. Pass as the layout `footer` prop from each `page.tsx`.
3. **Page content** — e.g. [`Login`](../../src/components/Login/Login.component.tsx) on `/`, `AboutClient` / [`LegalPageContent`](../../src/app/legal/LegalPageContent.server.tsx), or public crate client.

Home renders the landing immediately during **`isCheckingAuth`**; authenticated users redirect from **`Login`** via `router.replace("/releases")`. Protected app routes use **`AppPageLoading`** (see Protected routes above), not a blocking auth shell on `/`.

## API layer

Route outbound browser HTTP through the **`api`** object in **[`src/api/urls.ts`](../../src/api/urls.ts)** — the single front door for collection, crates, search, release fetch, auth check/logout/clear-data, dashboard stats, and admin user lookup. Implementation lives in **[`src/api/endpoints/`](../../src/api/endpoints/)** (`collection.ts`, `crates.ts`, `auth.ts`, …); prefer **`fetchOptions`** / **`fetchResponse`** from **[`src/api/helpers.ts`](../../src/api/helpers.ts)** in new endpoint code ([`auth.ts`](../../src/api/endpoints/auth.ts) is the reference). Endpoint-specific param types stay in the endpoint module; **[`src/api/types.ts`](../../src/api/types.ts)** re-exports only types shared across modules (e.g. **`LogoutOptions`** for mutation hooks).

- **Do not** call Discogs or `/api/...` with raw **`fetch`** from components or query hook files.
- **Do not** call Discogs directly from the browser; route handlers sign OAuth requests server-side.
- **Adding a new endpoint**: (1) Implement fetch in the matching `src/api/endpoints/<domain>.ts` (use **`fetchOptions`** / **`fetchResponse`** when the response is JSON). (2) Expose the method on **`api`** in `src/api/urls.ts`. (3) Add or extend a route handler under `src/app/api/`. (4) Add a dedicated **read** hook under `src/hooks/queries/` (`queryFn: api.method`) or **write** hook under `src/hooks/mutations/` (`mutationFn: api.method`).

### Hook audit: when to use React Query

Use **`useQuery` / `useInfiniteQuery`** for server-backed reads; use **`useMutation`** for writes. Feature hooks compose query/mutation hooks — they do not call [`src/api/urls.ts`](../../src/api/urls.ts) directly (the **`api`** object is invoked only from **`src/hooks/queries/`** and **`src/hooks/mutations/`**, or via **`queryClient.fetchQuery` / `prefetchQuery`** for cache-aware prefetch).

| Category | Examples | React Query? |
|----------|----------|--------------|
| Server reads | Collection, crates, release detail, prefs, build version | **Yes** — query hook in `src/hooks/queries/` |
| Server writes | Crate edits, logout, clear data, rating/notes, prefs PATCH | **Yes** — mutation hook in `src/hooks/mutations/`; optimistic cache in mutation; toasts/UI at call site |
| Imperative prefetch | `CrateDetailHeader` nav, playback similar-release tail | **`queryClient.prefetchQuery` / `fetchQuery`** with shared keys |
| Cache hydration | [`collectionCacheSync.ts`](../../src/utils/collectionCacheSync.ts) page-1 validation | **Direct helper** — must not seed the infinite collection cache |
| Client-only UI | `useCrateDrawer`, `useMediaQuery`, filter/view atoms | **No** |
| Derived client data | `useSimilarReleasesInCollection`, `useCollectionAnalytics` | **No** |
| Analytics transport | [`productAnalyticsClient.ts`](../../src/analytics/productAnalyticsClient.ts) | **No** |
| OAuth redirect | `AuthProvider.login` | **No** — full navigation |

**Orchestrators** (wire queries/mutations to context, atoms, or toasts): **`useCollectionData`**, **`useUserPreferencesSync`**, **`useCrateCollectionSync`**, **`DeploymentUpdateToast`**.

**`useCollectionData`** composes auth state + collection query + context dispatch for the releases/dashboard pages. Invalidate with **`DiscogsCollectionQueryKeys`** when the username changes ([`useCollectionData.hook.ts`](../../src/hooks/useCollectionData.hook.ts), [`auth.context.tsx`](../../src/context/auth.context.tsx)).

## Filtering and sorting

1. **`useCollectionData`** auto-chains paginated Discogs pages and dispatches **`FiltersActionTypes.SetAllReleases`** whenever flattened collection pages change (via raw **`filtersDispatchAtom`**, not **`useFiltersDispatch()`**, so collection hydration never PATCHes prefs) so the releases grid fills in incrementally and in-place field updates (e.g. personal **`rating`**) survive refetch without a collection size change. **`dispatchCollection`** still skips when pagination metadata is unchanged. The first fetch is a **bootstrap** page of 50; if more remain, pagination restarts at page size 100 (see [discogs.md](discogs.md) → Client-side collection access). **`collectionFiltersActiveAtom`** stays false until pagination finishes, so persisted filter prefs do not winnow the in-progress list. When the last page arrives, **`useCollectionData`** sets **`collectionFiltersActiveAtom`** to true so in-session filter inputs can affect the grid; saved prefs are **not** auto-applied (see **Persistence** below). Collection context keeps pagination metadata (`collection`, `fetchingCollection`, `error`) only—not a duplicate release list.
2. **Filter atoms** ([`filters.atoms.ts`](../../src/atoms/filters.atoms.ts)) derive **`filteredReleases`** and facet dropdown options from filter inputs via:
   - [`computeFilterDerivedState.ts`](../../src/utils/computeFilterDerivedState.ts) — one pass over the collection for both the filtered list and facet options ([`filterReleases.ts`](../../src/utils/filterReleases.ts) and [`computeFacetOptions.ts`](../../src/utils/computeFacetOptions.ts) are thin wrappers for tests and direct callers); [`sortReleases.ts`](../../src/utils/sortReleases.ts) runs on the filtered list in a separate derived atom so sort changes do not re-scan facets
   - **Facet options** — each dropdown’s choices come from releases matching the *other* active filters; e.g. with **Rock** selected, year and format lists only show values present on Rock releases, while the genre/style list still reflects search/year/format constraints so you can add another tag. Genres and styles share the **Genre & Style** filter via [`releaseGenreStyleTags.ts`](../../src/utils/releaseGenreStyleTags.ts). **Format Type** is a multi-select **`AutocompleteSelect`** on desktop and mobile with **Match** via [`FilterMatchOperatorSelect`](../../src/components/FilterMatchOperatorSelect/FilterMatchOperatorSelect.component.tsx): **ANY** / **NONE** when one format is selected (include vs exclude that tag), **ANY** / **ALL** / **NONE** when two or more are selected (same as genre/style). **Release Year** is a multi-select with **Match** (**ANY** / **NONE** when one or more years are selected; multi-select omits **ALL** because a release has one year) using [`FILTER_ANY_NONE_OPERATOR_OPTIONS`](../../src/constants/filterMatchOperators.ts). Format tags come from media names (Vinyl, CD, …) plus Discogs `formats[].descriptions` in [`formatFilterTags.ts`](../../src/utils/formatFilterTags.ts) — all descriptions except a small denylist (**Album**, **Stereo**, **Remastered**). Known tags map to display casing via **`FORMAT_CANONICAL_TAGS`**; filter matching is case-insensitive. Genre/style and format **Match** logic share [`matchFilterOperator.ts`](../../src/utils/matchFilterOperator.ts) via [`releaseFilterMatchers.ts`](../../src/utils/releaseFilterMatchers.ts). Facet options, card pills, and modal format pills sort **A–Z** via **`sortFormatTags`**. Search text and genre/style/format tags are pre-indexed per release ([`releaseSearchIndex.ts`](../../src/utils/releaseSearchIndex.ts)); `SetAllReleases` calls **`syncReleaseSearchIndex`** so pagination appends and note edits reindex only changed rows instead of rebuilding the whole map. Queries match all whitespace-separated tokens against title, artist, label, catno, notes, and genre/style tags ([`releaseFilterMatchers.ts`](../../src/utils/releaseFilterMatchers.ts)). Shared filter inputs use **`ReleaseFilterCriteria`** and facet shapes use **`FacetOptions`** in [`filters.types.ts`](../../src/types/filters.types.ts).
3. UI components (`FiltersBar`, [`FiltersDrawer`](../../src/components/FiltersDrawer/FiltersDrawer.component.tsx), release cards, [`ReleasesTable`](../../src/components/ReleasesTable/ReleasesTable.component.tsx)) dispatch filter actions through **`useFiltersDispatch()`** and read state via **`useFilterAtoms`** hooks; **`useFilteredReleases()`** drives the visible grid (one random release in random mode, otherwise the sorted filtered list); **`useMemoizedFilteredReleases()`** / **`useSortedFilteredReleases()`** expose the full sorted match set for mosaic input and random re-pick; **`useFacetOptions()`** supplies facet dropdown choices. Dashboard/analytics read the same list via **`useAllReleases()`**. **`FiltersBar`** and **`FiltersDrawer`** share the same filter control order: **Search** → **Genre & Style** (+ **Match** when one or more selected) → **Format Type** (+ **Match**) → **Release Year** (+ **Match**) → **Sort** (drawer splits sort category + order); desktop **`FiltersBar`** and the mobile drawer footer always show **Reset**; it is **disabled** when **`useAppliedFilterCount()`** is zero (or the collection is not loaded) and uses **`var(--foreground)`** border/text styling when filters are active (**.clearAllButtonActive** on the secondary **Reset** button). On mobile, filters open from the header filter control into **`FiltersDrawer`** (same filter atoms as desktop **`FiltersBar`**); the drawer title and footer show the applied filter count via **`useAppliedFilterCount()`** / [`getAppliedFilterCount.ts`](../../src/utils/getAppliedFilterCount.ts) (search plus each multi-select dimension: genre/style, year, format — sort is excluded). Multi-select facet filters in the drawer use searchable **`AutocompleteSelect`** (same component as desktop **`FiltersBar`**, with **`showLabel`** and optional **`clearable`** **Clear**); sort/match stay on plain **`Select`** / **`FilterMatchOperatorSelect`**. The mobile header filter icon shows a numeric badge when filters are active and uses **`var(--primary)`** (theme primary) on the icon via **`.active`** / **`.filterIconActive`**, matching the adjacent random-mode control. Filter changes apply live (same atoms as desktop **`FiltersBar`**) and closing the drawer does not revert them. The filter control stays hidden until **`allReleasesLoaded`** (same gate as desktop **`FiltersBar`**). **`SearchBar`**, **`Select`**, and **`AutocompleteSelect`** share aligned mobile tap targets (**`--touch-target-min`**) in the drawer. **`SearchBar`** flushes a pending debounced query on unmount so closing the drawer does not drop in-progress search text.

**Persistence**: User-selected filter inputs (styles, years, formats, sort, style operator, format operator, year operator, search query) persist in **`localStorage`** under **`filtermydiscogs_filters`** when **`preferences.persistFilters`** is **`true`** (account setting on **`User`**, default on). When enabled and authenticated, the same filter state is also stored on **`User.preferences.filters`** and synced across browsers via **`PATCH /api/user/preferences`** from **`useFiltersDispatch()`** (debounced through [`userPreferencesPersistQueue.ts`](../../src/utils/userPreferencesPersistQueue.ts)). When **`false`**, each visit starts with default filters; in-session filtering still works.

Filter UI reads **`sessionFiltersAtom`** (defaults on load). Saved prefs hydrate into **`persistedFiltersAtom`** / server storage but do not populate the UI until the user applies them or changes filters in-session. [`useInitializePendingFiltersRestore`](../../src/hooks/useInitializePendingFiltersRestore.hook.ts) (in **`FiltersProvider`**) copies restorable saved prefs into **`pendingFiltersRestoreAtom`** when persisted filters hydrate and the session is still at defaults. After the collection finishes loading on **`/releases`**, [`useOfferPendingFiltersRestore`](../../src/hooks/useOfferPendingFiltersRestore.hook.ts) shows a Sonner toast at **`bottom-center`** (“Resume previous session?” with match preview) when no playback-page overlay has the scroll root locked (**`scrollLockCountRef`** via **`usePlaybackPageScrollLockCountRef`** — e.g. crate/filters/menu **`BottomDrawer`** open); the toast appears after those close. **Resume** copies pending → session via **`applyPendingFiltersRestoreAtom`**, **Not now** clears pending. Any filter dispatch from the user clears pending and persists the new session state. **`collectionFiltersActiveAtom`** gates whether session inputs affect **`filteredReleases`** during pagination (full collection unfiltered until the last page). Collection data, random-mode pick, and the searching flag are **not** persisted. Cleared on **Clear stored data** (Settings / About / Legal), not on logout—same scope as view mode (one filter state per browser when persistence is enabled). Local filter PATCHes mark pending state in [`userPreferencesSyncState.ts`](../../src/utils/userPreferencesSyncState.ts) so [`useUserPreferencesSync`](../../src/hooks/useUserPreferencesSync.hook.ts) skips one redundant server hydrate when the mutation cache updates; server hydrate updates **`persistedFiltersAtom`** and re-offers pending restore when the session is still default.

**Lint guardrails**: Biome **`noRestrictedImports`** discourages **`useFilters`** / **`useView`** in application code—prefer **`useFilterAtoms`** / **`useViewAtoms`**. Context modules and test files are exempt.

Add filter dimensions by extending filter atoms/helpers and UI—not by filtering ad hoc in leaf components. Release note text is included in search via **`getReleaseNotesSearchText`** in [`releaseNotes.ts`](../../src/utils/releaseNotes.ts). **`SearchBar`** debounces input (300ms) and dispatches filter updates inside **`startTransition`** so typing stays responsive while the grid re-filters.

## Collection notes (scoped provider)

Release-card notes use a **feature-local provider**, not a global entry in **`Providers.tsx`**:

1. **`ReleaseNotesEditorProvider`** wraps each **`ReleaseCard`** / **`MobileReleaseCard`** (and release modal notes) and calls **`useReleaseNotesEditor(release)`** once; it mounts **`ReleaseNotesEditorDialog`**, which renders **`NoteEditDialog`** only while the overlay dialog is open (even when the card body omits inline notes).
2. **`ReleaseNotesCardAction`** (and **`ReleaseNotes`** on mobile list rows) read **`useReleaseNotesEditorContext()`** to open the same **`NoteEditDialog`**. Grid and mobile release cards show the notes icon on the overlay action strip only—a primary dot badge when notes exist, no inline note preview.

## Release playback queue

- **Scope**: Global playback queue in **`ReleasePlaybackProvider`** — cross-release **`PlaybackQueueItem[]`** for **up next** only (the current track is **not** in the array; it is tracked via **`release`**, **`activeTrackIndex`**, and **`activeTrackPosition`**). **`playbackHistory`** (internal state) holds tracks the listener has already played for **Previous**. Clicking a track row calls **`startPlayback`**, which plays that track and rebuilds upcoming from the remainder of the **playable album queue** (flattened tracks with embeddable YouTube matches after the clicked position via **`upcomingFromAlbumQueue`**). When playback starts from a user gesture (not paused restore), the provider also loads up to **`SIMILAR_RELEASES_LIMIT`** collection matches via [`getSimilarReleases`](../../src/utils/similarReleases.ts), fetches each release detail through React Query, **shuffles** playable tracks from those similar albums, and appends them after the album tail (deduped by **`instanceId` + `trackPosition`**). While playback continues, upcoming **extends automatically** when fewer than three tracks remain: it loads shuffled similar tracks from the **last queued release**, skipping instance ids already in upcoming when possible, and when a track ends on an empty upcoming list it appends more before advancing — so autoplay can continue indefinitely through related collection releases. **`addToQueue`** appends from the tracklist **Add to queue** control (list-plus icon; deduped by **`instanceId` + `trackPosition`**). When the queue is empty and the user preference **`autoPlayOnQueueAdd`** is **`true`** (default), **`addToQueue`** / **`addPreviewToQueue`** call **`startPlayback`** / **`startReleasePreview`** instead so the first add starts immediately with the video panel open; when **`false`**, items are appended silently (same as adding while a session is already active). **Add all to queue** with no active session (**`isMiniPlayerVisible`**) **`startPlayback`** on the first playable track — **`startPaused: true`** when **`autoPlayOnQueueAdd`** is **`false`**, otherwise autoplay with **`rebuildAlbumQueue: false`** — then **`addToQueue`** for the rest. After the listener has used **`addToQueue`** / **`addPreviewToQueue`** (including **Add all to queue**), a later track-row **`startPlayback`** from another release modal **preserves** the curated upcoming list: the clicked track plays now (pushed to **`playbackHistory`** when something was already playing) without rebuilding the album queue or clearing manual entries; if the clicked track was already in upcoming, it is removed from upcoming and played. A track-row **`startPlayback`** with no prior manual queue additions still replaces upcoming with the new album tail as before. **`playNext`** / YouTube ended advance by moving the current track to history, playing the first upcoming row, and removing it from upcoming. **`playPrevious`** pops from **`playbackHistory`** and prepends the current track back onto upcoming when needed. **`clearQueue`** (queue drawer **Clear queue**) clears upcoming only but **keeps the active track playing**; **`stopPlayback`** ends the session entirely (logout, clear stored data, removing the last queue row) with no bar stop control. **`isMiniPlayerVisible`** (`release !== null`) keeps the dock and layout spacers up while a session is active, including when paused. **`reorderQueue`** reorders upcoming rows from the queue drawer (drag handle, `@dnd-kit`) and keeps the active track playing. Prev/next and dock transport walk upcoming plus history, not only the current album. When a YouTube embed finishes, **`ReleasePlaybackProvider`** listens for the iframe **`onStateChange`** ended event (via [`youtubeIframeEvents.ts`](../../src/utils/youtubeIframeEvents.ts); **`PersistentYoutubeIframe`** enables listening on **`load`**) and calls **`playNext`** automatically when another upcoming row exists.
- **Placement**: **`ReleasePlaybackProvider`** and **`GlobalPlaybackDock`** live in global **`Providers`** (after **`CollectionContextProvider`** / **`FiltersProvider`**) so playback and the YouTube iframe survive client-side route changes. The provider exposes split contexts — **`useReleasePlaybackState`**, **`useReleasePlaybackActions`**, **`useIsMiniPlayerVisible`**, **`useReleasePlaybackQueue`**, **`useReleasePlaybackIframeActions`** — so subscribers re-render only when their slice changes; **`useReleasePlayback()`** merges state + actions for callers that need both. Similar-release tail extension batches detail fetches via [`similarReleaseQueue.ts`](../../src/utils/similarReleaseQueue.ts) (deduped React Query prefetch). **`PlaybackReleaseClickProvider`** registers per-page **`onReleaseClick`** handlers (release modal) via **`useRegisterPlaybackReleaseClick`**. **[`PlaybackPageShell`](../../src/components/PlaybackPageShell/PlaybackPageShell.component.tsx)** handles page scroll layout only (header / main / overlays). Closing **`ReleaseModal`** does not stop playback.
- **UI**: [`ReleaseMiniPlayer`](../../src/components/ReleaseMiniPlayer/ReleaseMiniPlayer.component.tsx) is a slim background-playback dock (cover, title, prev/play-pause/next — no bar stop control). A **queue** control opens **[`PlaybackQueueDrawer`](../../src/components/PlaybackQueueDrawer/PlaybackQueueDrawer.component.tsx)** (drag-to-reorder, list, play at index, remove row, clear queue). The dock stays visible while **`isMiniPlayerVisible`** (an active release session), including when paused; layout spacers and **`data-global-playback-dock`** follow the same flag. By default the YouTube embed is hidden (audio-only). A **video** control toggles a 16:9 panel ([`ReleasePlaybackVideoPanel`](../../src/components/ReleasePlaybackVideoPanel/ReleasePlaybackVideoPanel.component.tsx)). The dock video panel **auto-expands once** the first time playback becomes ready in the bar (tracked in **`localStorage`** via [`playbackVideoIntroStorage.ts`](../../src/utils/playbackVideoIntroStorage.ts)) so listeners discover the control; later sessions still **auto-expand whenever autoplay playback starts** (e.g. a track row click in **`ReleaseModal`**, or prev/next in the dock) unless the listener collapsed the panel with the video control or close bar. Restore-after-refresh playback starts **paused** and keeps the panel collapsed until the listener taps play. On **mobile**, the panel is full viewport width, stacked above the mini-player bar inside **`PlaybackPageShell`**, with a top close bar (no drag/resize). Opening the **filters drawer** auto-collapses the mobile video panel and sizes the drawer to the space above the mini-player bar only; the listener can re-open video from the mini-player while filters stay open ([`useFiltersDrawerOpen`](../../src/hooks/useFiltersDrawerOpen.hook.ts), [`PlaybackPageShell.module.css`](../../src/components/PlaybackPageShell/PlaybackPageShell.module.css)). On **desktop** it defaults above the mini-player release metadata, left-aligned at full size as a floating panel — drag the top handle to reposition, drag the bottom-right handle to shrink (not enlarge), and double-click the top handle to reset layout; layout persists for the browser session until the viewport crosses back from mobile to desktop or a stored position no longer fits the viewport, when position and scale reset to that default. Native browser PiP is not used — YouTube iframe embeds do not expose reliable programmatic PiP from app code. Cover/title opens **`ReleaseModal`**. Play/pause sends YouTube iframe commands via **`togglePlayback`**. [`PersistentYoutubeIframe`](../../src/components/PersistentYoutubeIframe/PersistentYoutubeIframe.component.tsx) keeps a single embed mounted in the dock; when collapsed it stays off-screen for audio-only playback. Embeds use **`playsinline=1`** for iOS. A track row click in **`ReleaseModal`** calls **`startPlayback`**; closing the modal does not stop playback. **`startPlayback`** schedules **`playVideo`** iframe commands (with retries up to 3s) and **`resumePlaybackFromGesture`** re-fires when the embed becomes visible so mobile track picks can start after the panel opens. Prev/next advance within the global queue and keep the video panel open when it was already expanded. Queue utilities: [`playbackQueue.ts`](../../src/utils/playbackQueue.ts); release detail queries: [`useDiscogsReleaseQuery`](../../src/hooks/queries/useDiscogsReleaseQuery.ts); video matching: [`releasePlayback.ts`](../../src/utils/releasePlayback.ts).
- **Resume after refresh**: **`startPlayback`** writes `{ instanceId, trackPosition, queue? }` to **`localStorage`** via [`releasePlaybackStorage.ts`](../../src/utils/releasePlaybackStorage.ts); the provider keeps it updated while playback is active, including manual **Add to queue** rows (resolved back to collection releases on restore). Restore waits for auth (`isCheckingAuth`), the collection to finish loading (`collection !== null`, not fetching), and any remaining pages (`collection.pagination.urls.next`) before giving up — on any route, not only **`/releases`**. Restore reopens the dock **paused** with the saved upcoming queue — browsers block autoplay without a user gesture, so the listener taps play to resume audio. Cleared on stop, logout, and **Clear stored data**.
