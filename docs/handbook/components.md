# Components

How UI is organized under `src/components/` and how we test it.

## Folder layout

- **Feature components**: [`src/components/<Name>/`](../../src/components/) — one folder per component or feature area; **no nested `components/` or `shared/` tiers**. Typically:
  - `Name.component.tsx` — main React export (arrow function, typed props)
  - `Name.module.css` — scoped styles
  - Optional `Name.spec.tsx` + `Name.po.tsx` for tested components (see [conventions.md → Testing](conventions.md#testing))
  - Related pieces are **sibling folders** (e.g. [`ReleaseModal/`](../../src/components/ReleaseModal/) shell + [`ReleaseTracklist/`](../../src/components/ReleaseTracklist/) + [`ReleaseSummaryHero/`](../../src/components/ReleaseSummaryHero/) — not nested under one mega-folder)

- **Shared primitives**: same flat layout under **`src/components/`** — [`AppDialog/`](../../src/components/AppDialog/), [`BrowserOnly/`](../../src/components/BrowserOnly/) (React 19.3 **`use(browser())`** + Suspense for client-only subtrees — see [patterns.md → Protected routes](patterns.md#protected-routes)), [`FormDialog/`](../../src/components/FormDialog/), [`IconButton/`](../../src/components/IconButton/) (icon-only controls + hover motion — see [Icon buttons](#icon-buttons)), [`SegmentedControl/`](../../src/components/SegmentedControl/) (fieldset + legend wrapper — see [Segmented controls](#segmented-controls)), [`EmptyState/`](../../src/components/EmptyState/) (page/panel/inline empty copy — see [Empty states](#empty-states)), [`DiscogsExternalLink/`](../../src/components/DiscogsExternalLink/) (View on Discogs toolbar/icon/text links), [`InlinePopoverMenu/`](../../src/components/InlinePopoverMenu/), [`ScrollModal/`](../../src/components/ScrollModal/), [`ModalToolbar/`](../../src/components/ModalToolbar/), [`TanstackChart/`](../../src/components/TanstackChart/), [`ViewTransitionShell/`](../../src/components/ViewTransitionShell/) (stable **`ViewTransition`** wrapper — `mount` / `deferredUpdate`; ## Naming

- Prefer **`.component.tsx`** for the main React export in a feature folder.
- **Client page shells** use **`*Client.tsx`** or **`*Client.component.tsx`** under [`src/components/`](../../src/components/), imported from a server [`page.tsx`](../../src/app/about/page.tsx) in **`src/app/`** (routing only — no co-located components or CSS modules in route folders).
- Keep **one primary component file** per folder unless the feature is large enough to justify split files (hooks, subcomponents).

## CSS Modules

Import as `import styles from "./Name.module.css"` and reference **`styles.className`**. Use **`classNames`** whenever classes are combined or conditional — static lists, object notation for state, and optional `className` props (see [conventions.md → React / JSX](conventions.md#react--jsx)). Do **not** cast module keys with **`as string`** in object notation. Single unconditional module classes may use `className={styles.block}` directly.

## Scaffolding

Run **`pnpm scaffold <ComponentName>`** ([`scripts/scaffold.sh`](../../scripts/scaffold.sh)) to generate:

- `Name.component.tsx` with root **`data-testid="fmd<Name>"`**
- `Name.module.css`
- `Name.spec.tsx` (assertions via **`screen`**; imports PO first)
- `Name.po.tsx` with typed **`renderName(overrides)`**, defaults + `{...overrides}`, and optional private **`*Element()`** helper (see [conventions.md → Testing](conventions.md#testing))

Add factories under **`src/tests/factories/`** when structured test data is needed.

**After scaffold, trim boilerplate you will not use:**

- Delete **`Name.interfaces.ts`** when it would only re-export types already defined on the component or a colocated helper (e.g. [`IconButton`](../../src/components/IconButton/) — props and **`IconButtonVariant`** live on the component / [`iconButtonClasses.ts`](../../src/components/IconButton/iconButtonClasses.ts); no factory).
- Skip / delete the generated factory when the component has no structured domain model to build in tests.
- Do **not** hand-create component folders — always run **`pnpm scaffold`** first, then edit the generated files.

## Icon buttons

Use **[`IconButton`](../../src/components/IconButton/IconButton.component.tsx)** / **[`IconButtonLink`](../../src/components/IconButton/IconButtonLink.component.tsx)** for icon controls (queue, close, crate +/-, segmented toggles, nav links, menu triggers, playback transport, …). Hover motion comes from **[`icon-button.module.css`](../../src/styles/modules/icon-button.module.css)** via **`iconButtonClasses()`** inside the component — do not **`composes`** **`icon-button`** in feature CSS or call **`iconButtonClasses()`** in feature TSX.

| Piece | Role |
|-------|------|
| [`action-icon-hover.module.css`](../../src/styles/modules/action-icon-hover.module.css) | Low-level hover transforms — **`.iconaction`**, **`.iconactionplus`**, **`.iconactionminus`**, **`.iconactionclose`**, **`.iconactionexternal`**, **`.iconactionqueuesubtle`**, **`.iconactionskip`**, **`.icon`**. Base **`.iconaction`** scale pop excludes named variants so **plus** rotate motion is not overridden. **Minus** (remove-from-crate only) uses scale only — no rotate. |
| [`icon-button.module.css`](../../src/styles/modules/icon-button.module.css) | Facade tokens — **`composes`** from **`action-icon-hover`**. **`.button`** is hover-only; layout lives in **`.iconOnly`** (icon-only) or **`.labeled`** (icon + text/addon). Applied via **`iconButtonLayoutClass()`** inside **`IconButton`** / **`IconButtonLink`**. |
| [`iconButtonClasses.ts`](../../src/components/IconButton/iconButtonClasses.ts) | Maps **`variant`** to shared module classes and **`iconButtonLayoutClass(isLabeled)`** for layout mode — internal to **`IconButton`** / **`IconButtonLink`**. |
| **`variant`** | **`default`** (scale pop), **`plus`** (quarter-turn + scale), **`minus`** (scale only — remove-from-crate), **`close`**, **`external`**, **`queue`** (subtle scale only), **`skip`** (no hover — drag handles). |

**Implementation rules:**

- **No `cloneElement`** — wrap the SVG in **`<span className={iconButtonIconClasses(…)} aria-hidden>{children}</span>`** inside the button/link. Shared hover CSS targets **`.icon`** or a direct **`> svg`** child (never both) so rotate motion stays centered.
- Pass layout chrome via **`className`** on **`IconButton`** (e.g. [`ModalToolbar.module.css`](../../src/components/ModalToolbar/ModalToolbar.module.css) **`.actionButton`**, [`segmented-control.module.css`](../../src/styles/modules/segmented-control.module.css) **`.segment`**, [`vertical-action-stack.module.css`](../../src/styles/modules/vertical-action-stack.module.css) **`.overlayAction`**, [`table-row-actions.module.css`](../../src/styles/modules/table-row-actions.module.css) **`.actionButton`** for bare table rows). **`IconButton`** / **`IconButtonLink`** only compose hover motion from **`icon-button.module.css`** — always add surface chrome for standalone **`<button>`** triggers (native grey button styling shows through otherwise).
- **Layout modes** — mutually exclusive classes from **`icon-button.module.css`**, chosen by **`iconButtonLayoutClass()`**:
  - **Icon-only** (**`.iconOnly`**, default): **`display: flex`** centering + **`line-height: 0`** on the icon row; padding, size, and borders come from consumer **`className`** (segment, crate action, overlay slot, …). Do not put layout resets on **`.button`** — they break labeled triggers.
  - **Labeled** (**`.labeled`**, when **`label`** or **`addon`** is set): **`inline-flex`** + **`align-items: center`**, **`line-height: inherit`** — pass **`gap`**, height, padding, and borders via consumer **`className`** ([`FilterViewsMenu.module.css`](../../src/components/FilterViewsMenu/FilterViewsMenu.module.css) **`.menuTrigger`**, theme switcher segments).
- Optional **`internal`** on **`IconButtonLink`** for Next.js **`Link`** routes ([`PageNavigation`](../../src/components/StickyHeaderBar/PageNavigation.tsx)).
- Base UI **`Menu.Trigger`**: use **`render={(props) => <IconButton {...props} … />}`** when the trigger is icon-only or icon+label ([`ReleaseCrateMenu`](../../src/components/ReleaseCard/ReleaseCrateMenu.component.tsx), [`FilterViewsMenu`](../../src/components/FilterViewsMenu/FilterViewsMenu.component.tsx)).

## Segmented controls

Use **[`SegmentedControl`](../../src/components/SegmentedControl/SegmentedControl.component.tsx)** for grouped toggle rows (view mode, chart range, crate drawer actions, release-card overlay actions). It renders a **`<fieldset>`** with a visually hidden **`<legend>`** and applies [`segmented-control.module.css`](../../src/styles/modules/segmented-control.module.css) **`.container`**. Re-export **`segmentedStyles`** from the component for **`.segment`** / **`.active`** on child **`IconButton`** / **`IconButtonLink`** segments — do not hand-wire **`fieldset`** + **`legend`** + **`accessibilityStyles.visuallyHidden`** in feature TSX.

| Prop | Role |
|------|------|
| **`legend`** | Accessible group label (required). |
| **`className`** | Feature layout overrides (e.g. [`ViewToggle.module.css`](../../src/components/ViewToggle/ViewToggle.module.css), [`CrateDrawerFooter.module.css`](../../src/components/CrateDrawerFooter/CrateDrawerFooter.module.css)). |

| **`allowOverflow`** | Keeps first/last corner radii for tooltip overflow ([`ReleaseCardOverlayActions`](../../src/components/ReleaseCard/ReleaseCardOverlayActions.component.tsx)). |

Consumers: [`ViewToggle`](../../src/components/ViewToggle/ViewToggle.component.tsx), [`GrowthChart`](../../src/components/Dashboard/GrowthChart.component.tsx), [`ComparativeGrowthCharts`](../../src/components/Dashboard/ComparativeGrowthCharts.component.tsx), [`CrateDrawerFooter`](../../src/components/CrateDrawerFooter/CrateDrawerFooter.component.tsx), [`ReleaseCardOverlayActions`](../../src/components/ReleaseCard/ReleaseCardOverlayActions.component.tsx).

## Empty states

Use **[`EmptyState`](../../src/components/EmptyState/EmptyState.component.tsx)** for centered “nothing here” copy on collection pages and similar full-width placeholders. Styles live in [`empty-state.module.css`](../../src/styles/modules/empty-state.module.css).

| **`variant`** | Use |
|---------------|-----|
| **`page`** | Full-page empty (dashboard, crates hub, mosaic, releases grid) — large title + description, **`min-height: 50vh`**. |
| **`panel`** | Default — dashed bordered card for in-content panels. |
| **`inline`** | Compact muted copy inside a section (compose with dashboard **`.card`** in CSS when needed). |

Props: **`title`** (required), optional **`description`**, optional **`children`** (CTA links/buttons), optional **`className`**. Consumers: collection page shells, dashboard sections ([`OnThisDay`](../../src/components/Dashboard/OnThisDay.component.tsx), [`MostCrated`](../../src/components/Dashboard/MostCrated.component.tsx), …), crate detail/drawer release lists. Pass **`className`** to compose dashboard **`.card`** chrome when needed; keep local CSS only for CTAs (e.g. **`.emptyStateLink`** pill buttons).

- Discogs release/artist/label URLs: **`getResourceUrl({ resourceUrl, type, id? })`** from [`src/utils/helpers.ts`](../../src/utils/helpers.ts) — parses **`resource_url`**, or falls back to a numeric **`id`** when the collection payload omits URLs.

Inline artist/label/title metadata links stay on **[`ReleaseHeaderLinks`](../../src/components/ReleaseCard/ReleaseHeaderLinks.component.tsx)**.
- **Text actions** (underlined cancel/clear/edit links): import [`text-action.module.css`](../../src/styles/modules/text-action.module.css) in TSX (**`textActionStyles.meta`**, **`.primary`**, **`.muted`**, **`.xsmuted`**, **`.subtlelink`**) for **`<button>`** / **`<a>`** triggers — same pattern as [`DiscogsExternalLink`](../../src/components/DiscogsExternalLink/DiscogsExternalLink.component.tsx). - Cover art: **`next/image`** with Discogs CDN URLs (`i.discogs.com`).

## Test IDs

- Component root: **`data-testid="fmd<ComponentName>"`** (PascalCase component name).
- Page object **`testId`** must match exactly.
- Specs query with **`screen.getByTestId(po.testId)`** after PO render setup.

## Testing

- Colocate specs with the component when adding coverage (`*.spec.tsx`; optional **`*.po.tsx`**).
- Use **`render`** from **`test-utils`** when auth, filters, or crate context is required **without** mocking (default wrapper is **`TestProviders`**). Context-heavy component tests usually mock context in the PO and use **`render`** instead (see [conventions.md → Testing](conventions.md#testing)).
- **Page composition in POs**: When production mounts a component inside a layout plus server footer (e.g. home = `PublicAuthLayout` + `PageFooter` + `Login`), the PO **`render*`** helper should mirror that tree. Put **`jest.mock("src/components/Page/PageFooter.server")`** in the PO and render `<PageFooter />` in the layout’s `footer` prop—do not inline a partial footer that omits links the spec asserts on.

## Exports

Import from the **concrete module path** (e.g. `src/components/ReleaseCard/ReleaseCard.component.tsx`). Avoid new barrel **`index.ts`** files.

## Feature example: ReleaseCard (desktop grid)

[`ReleaseCard`](../../src/components/ReleaseCard/ReleaseCard.component.tsx) and **`PublicReleaseCard`** share [`ReleaseCard.module.css`](../../src/components/ReleaseCard/ReleaseCard.module.css). Body copy lives in [`ReleaseCardContent`](../../src/components/ReleaseCard/ReleaseCardContent.component.tsx).

| Concern | Pattern |
|---------|---------|
| Shell | Inset **`1px`** stroke via **`box-shadow`** on **`--border`** (no physical **`border`** — keeps cover art flush with rounded corners); **`--shadow-sm`** at rest; on **`@media (hover: hover)`**, hover swaps inset stroke to **`--input`**, lifts with **`--shadow-lg`** + **`--background`**-tinted outer shadow, and **`translateY(-2px)`** |
| Cover | **`.imageContainer`** has no corner radius — **`.releaseCard`** **`overflow: hidden`** clips the blurred background; centered thumb (**65%**) keeps its own **`--radius-card`**. Blurred cover backdrop via **`::before`** + **`--release-cover-image`** (hover-capable pointers only) |
| Title | [`ReleaseCardTitle`](../../src/components/ReleaseCard/ReleaseCardTitle.component.tsx) composes shared [`ReleaseHeaderLinks`](../../src/components/ReleaseCard/ReleaseHeaderLinks.component.tsx) (**`ReleaseHeaderArtistLine`**, **`ReleaseHeaderTitle`**) + [`ReleaseCardMeta`](../../src/components/ReleaseCard/ReleaseCardMeta.module.css) — **single-line** ellipsis (artist, title, label/year); **`headerTextStack`** / **`.titleGroup`** / mobile **`.releaseInfo`** use **`gap: var(--space-1)`** to match modal hero **`ReleaseSummaryHero`** **`.detailsText`**; card artist/label use **`--text-meta-sm`** / **`--text-meta-xs`**; title stays bold sans at **`clamp(… cqi …)`** |
| Pills | **`.pillsRow`** wraps **`HorizontalScrollRow`** (**`data-testid="fmdReleaseCardPillsRow"`**) + **`.genresContainer`** — format/style tags in one horizontal row (scroll when overflow); **`.pillsRow`** is **`flex-shrink: 0`** so the row is never collapsed by **`.mainContent { flex: 1 }`** |

| Highlight | **`.highlighted`** — **`2px`** primary inset stroke in **`box-shadow`** (plus highlight glow shadows; composes **`theme-highlighted-surface`**) |

## Feature example: ReleaseModal

[`ReleaseModal/`](../../src/components/ReleaseModal/) is the release detail dialog shell on **`/releases`**, **`/dashboard`**, **`/mosaic`**, and owner **`/crates/[id]`**. Body, hero, tracklist, similar sidebar, and public variants live in sibling folders (see table). Opened when the user clicks cover art or title on a collection card (via **`onReleaseClick`** from [`useSelectedReleaseModal`](../../src/hooks/useSelectedReleaseModal.hook.ts) — [`useReleasesClient`](../../src/hooks/useReleasesClient.hook.ts) on **`/releases`**, dashboard rows on **`/dashboard`**) or a mosaic tile (via [`useLocalSelectedReleaseModal`](../../src/hooks/useSelectedReleaseModal.hook.ts) on **`/mosaic`** — local state only, no **`?instance=`** param).

**URL routing:** Modal open state syncs to **`?instance=<instance_id>`** ([**`RELEASE_MODAL_INSTANCE_PARAM`**](../../src/constants.ts)) on the current page. Every open and similar-sidebar switch **`router.push`**es (preserving other query params) so browser **Back** walks through viewed releases; explicit close (**X**, Escape, backdrop) **`router.replace`**s to the URL captured before the first open in that session; landing on a direct link with **`?instance=`** closes via **`router.replace`** to strip the param. **`useSelectedReleaseModal`** drives optimistic open/close through a **`modalSyncReducer`** so UI does not wait on App Router **`searchParams`** updates — **`selectedReleaseId`** is **`modalSync.optimisticId ?? urlInstanceId`** so a new click wins over a stale **`?instance=`** param until **`router.push`** catches up (mosaic tile switches, similar sidebar, rapid re-open). Every release-open surface spreads **`useReleaseOpenHandler`** **`prefetchPointerProps`** (see **ReleaseCard → Open detail modal**) to warm the modal via [`prefetchReleaseOpenData`](../../src/utils/prefetchReleaseOpenData.ts) on **`onPointerEnter`** (**50ms** delay, **`onPointerLeave`** cancels) / **`onPointerDown`** — **`prefetchReleaseModal`** / [`releaseModalLoader.ts`](../../src/components/ReleaseModal/releaseModalLoader.ts) for the lazy chunk plus **`prefetchQuery`** on **`discogsReleaseQueryOptions`** when that release id is not already cached — so tracklist data is often ready before click; **`handleReleaseClick`** repeats the same helper on open (fallback when hover did not run). **[`ReleaseModalLazyOverlay`](../../src/components/ReleaseModal/ReleaseModalLazyOverlay.component.tsx)** mounts **[`ReleaseModalLazy`](../../src/components/ReleaseModal/ReleaseModalLazy.component.tsx)** with **`key={release.instance_id}`** so hero/tracklist state resets when the open release changes. Tracklist reads use **`useDiscogsReleaseQuery`** while the modal is open — reopening within **`staleTime`** serves cached detail without refetching. Unknown instance ids leave the modal closed. Helpers: [`releaseModalUrl.ts`](../../src/utils/releaseModalUrl.ts). Host pages that call **`useSelectedReleaseModal`** ( **`useSearchParams`** ) wrap the client in **`<Suspense>`** ([**`/releases`**](../../src/app/releases/page.tsx), [**`/dashboard`**](../../src/app/dashboard/page.tsx); crate routes already do). **`/mosaic`** uses **`useLocalSelectedReleaseModal`** and does not need modal **`Suspense`**.

**Collection data:** Personal rating, notes, and hero metadata resolve from the **Discogs collection React Query cache**, not a separate modal copy. [`useSelectedReleaseModal`](../../src/hooks/useSelectedReleaseModal.hook.ts) / [`useLocalSelectedReleaseModal`](../../src/hooks/useSelectedReleaseModal.hook.ts) take **`collectionUsername`** on collection pages, resolve the open release from a memoized **`fallbackReleases`** index first (visible/filtered list for instant open), then [`useCollectionReleaseByInstanceId`](../../src/hooks/queries/useCollectionReleaseByInstanceId.hook.ts) — which prefers **`allReleasesAtom`** and only reads the collection React Query cache (**`enabled: false`**) so a **`?instance=`** URL never starts a parallel collection fetch before IndexedDB hydration. Owner **`/crates/[id]`** and public **`/crate/[id]`** pass crate-scoped **`fallbackReleases`**. Tracklist and community rating come from **`useDiscogsReleaseQuery`**. While the modal is open, **`useReleaseModalPlayback`** enables that query (shared cache with **`ReleaseSummaryHero`**, card queue, and the dock); tracks/videos render only from cached release detail — no dock fallback. Tracklist skeleton only when the modal is open, there is no cached **`releaseDetail`** yet, and the query is actively **`isLoading`** (first fetch in flight — not bare **`isPending`**, which stays true while idle/disabled). **`ensureQueryData`** on open (and after cache removal via query-cache subscription) guarantees a fetch when cache is empty. Rating/notes writes patch the infinite collection cache + IndexedDB ([`collectionCacheSync.ts`](../../src/utils/collectionCacheSync.ts), helpers in [`collectionReleaseLookup.ts`](../../src/utils/collectionReleaseLookup.ts)); [`useCollectionData`](../../src/hooks/useCollectionData.hook.ts) keeps **`allReleasesAtom`** in sync for filters and the grid.

**Similar in your collection:** **`getSimilarReleases`** scores other collection items with weighted tag overlap — **styles** count more than **genres** — plus small boosts for shared **label** (by Discogs **`labels[].id`**, with name fallback) and nearby **year** (±5), and a **same-artist penalty** (by **`artists[].id`**, with name/ANV fallback) so gig-list discovery favors different artists with a similar vibe.
