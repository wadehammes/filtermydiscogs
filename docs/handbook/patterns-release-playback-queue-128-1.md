## Release playback queue

- **Manual queue scenarios** (curation vs pending album rebuild, drawer reorder, E2E matrix): [playback-manual-queue.md](playback-manual-queue.md).
- **Embed refactor stack**: Behavioral checklist and phased migration live in [playback-embed-invariants.md](playback-embed-invariants.md) and [playback-embed-simplification.md](playback-embed-simplification.md). Embed lifecycle source of truth: [`playbackEmbedSession.ts`](../../src/utils/playbackEmbedSession.ts) (reducer + **`tryConfirmPlaybackEmbedFromSignal`** + poll selectors), applied in the provider via [`applyPlaybackEmbedSessionEvent`](../../src/utils/applyPlaybackEmbedSessionEvent.ts) / [`syncPlaybackEmbedSessionRefs`](../../src/utils/syncPlaybackEmbedSessionRefs.ts). **`stopPlayback`** resets embed session; imperative embed load dispatches **`embed/load/started`**. Legacy [`releasePlaybackEmbedConfirm.ts`](../../src/utils/releasePlaybackEmbedConfirm.ts) re-exports confirm helpers and constants for older imports and defines **`resolveEmbedPlaybackIntentActive`** plus **`resolveAudibleEmbedConfirmTransport`** (audible confirm **`transportSessionActive`** follows playback intent, not **`isPlayingRef`** alone) — prefer [`playbackEmbedSession.ts`](../../src/utils/playbackEmbedSession.ts) in new code. Phase 2 wires [`useReleasePlaybackYoutubeEmbed.hook.ts`](../../src/hooks/useReleasePlaybackYoutubeEmbed.hook.ts) **`tryConfirmAudibleEmbedPlayback`** to **`resolveAudibleEmbedConfirmTransport`** for both intent gate and **`transportSessionActive`** passed into **`tryConfirmPlaybackEmbedFromSignal`**.
