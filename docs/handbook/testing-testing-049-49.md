**Mocked dependency handles:** Put **`jest.fn()`** inside the **`jest.mock`** factory—do not close over a top-level **`const mockX = jest.fn()`** passed into the factory (hoisting/TDZ). After **`jest.mock`**, read handles with **[`getMockedExport`](../../src/tests/mocks/getMockedExport.ts)** (typed via **`import type { fn } from "mocked-module"`** + **`typeof fn`**) or **`getMockedModule`** for nested exports—not a static value **`import { fn } from "mocked-module"`** (often the **real** impl in the spec file) and not repeated inline **`jest.requireMock<{ …: jest.Mock }>(…)`** casts (see Sentry specs under **`src/lib/sentry/*.spec.ts`**, [`PersistentYoutubeIframe.spec.tsx`](../../src/components/PersistentYoutubeIframe/PersistentYoutubeIframe.spec.tsx)). When the **module under test** (or a hook) statically imports mocked dependencies, hoisted **`jest.mock`** is usually enough—**statically import** the SUT after mock factories (see [`reportPlaybackSkip.spec.ts`](../../src/lib/sentry/reportPlaybackSkip.spec.ts)). Use **`beforeAll`** or per-test **`await import("…")`** when the spec tests **the mocked module itself** (e.g. [`deliverSentryClientCapture.client.spec.ts`](../../src/lib/sentry/deliverSentryClientCapture.client.spec.ts)), when mock wiring must change before the SUT’s first evaluation, or with **`jest.resetModules()`** + env/module state (e.g. [`discogs-fetch.spec.ts`](../../src/lib/discogs-fetch.spec.ts), [`discogs-request-throttle.spec.ts`](../../src/lib/discogs-request-throttle.spec.ts))—do **not** repeat dynamic import in every **`it`** without reason.

**No `jest.requireActual` in test mocks:** Do not spread **`jest.requireActual(...)`** to pull real implementations into a **`jest.mock`** factory. List each mocked export explicitly (**`jest.fn()`** or a small inline helper). When a component only needs legacy **`useCrate()`** stubs, mock **`useCrate`** alone and render with **`includeCrate: false`**. When it mounts **`ReleaseCrateMenu`**, use the real **`CrateProvider`** with mocked **`api.*`** crate routes (see [`ReleaseListItem.po.tsx`](../../src/components/ReleaseListItem/ReleaseListItem.po.tsx)) or mock **`useCrateState`** + **`useCrateActions`** explicitly with **`includeCrate: false`**. When a route test needs pure helpers from a module that also imports DB code (e.g. **`getPaginationParams`** in [`src/lib/api-helpers.ts`](../../src/lib/api-helpers.ts)), copy the small helper body into the mock factory instead of importing the real module at the top level. When a server module under test imports **`{ Prisma } from "@prisma/client"`** for raw SQL (**`Prisma.sql`** / **`Prisma.join`**, e.g. [`admin-stats.server.ts`](../../src/lib/admin-stats.server.ts)), mock **`src/lib/db`** as usual and also **`jest.mock("@prisma/client")`** with stub **`Prisma.sql`** / **`Prisma.join`** helpers (see [`admin-stats.server.spec.ts`](../../src/lib/admin-stats.server.spec.ts))—otherwise Jest must resolve the generated client, which can break after pnpm dependency-hash changes until **`prisma generate`** runs. When only one side-effect export needs stubbing (e.g. **`postYoutubePlayerCommand`**), keep it in a dedicated module ([`postYoutubePlayerCommand.ts`](../../src/utils/postYoutubePlayerCommand.ts)) and **`jest.mock`** that file only—leave pure helpers on the parent module running for real.

**Exceptions (narrow):**
- Hook tests that use a minimal **`QueryClientProvider`** wrapper only for **auth context** lifecycle (e.g. [`auth.context.spec.tsx`](../../src/context/auth.context.spec.tsx)), not to stub server data.

**Do not add specs under `src/hooks/queries/` or `src/hooks/mutations/`** — cover read/write behavior at the call site (feature hooks, contexts, components) with mocked **`api.*`**, or in route/endpoint tests for HTTP contracts. Collection query edge cases (401 recheck, bootstrap page size, rate-limit retry) live in [`useCollectionData.hook.spec.ts`](../../src/hooks/useCollectionData.hook.spec.ts).
