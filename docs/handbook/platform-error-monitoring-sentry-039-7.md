**Performance / slow endpoints (Trace Explorer):** Weekly report **Total Spans** is much smaller than Trace Explorer **count()** aggregates — the email headline is closer to billable/indexed volume; use **transaction**-level **`p95(span.duration)`** for route triage. Slow **`GET /api/release/[id]`** spans at **~30s** are almost always **`DiscogsThrottleQueueError`** (queue wait), not slow Discogs HTTP — open the trace and compare **`executing api route`** wall time to **`GET api.discogs.com`** child duration; production spans may also carry **`discogs.throttle.caller`**, **`discogs.throttle.queue_wait_ms`**, and **`discogs.throttle.rate_limit_wait_ms`** from [`discogs-request-throttle.ts`](../../src/lib/discogs-request-throttle.ts) (**`public_playlist_hydrate`**, **`api_release`**, **`api_release_batch`**, **`public_release_page`** — [`discogsThrottleCaller.constants.ts`](../../src/constants/discogsThrottleCaller.constants.ts)). Slow **`GET /api/collection`** and **`GET /api/playlists`** on cold instances often combine **auth verification**, **Discogs throttle wait**, and **serverless cold start** (`load app route module`); reducing sequential SSR Discogs work (public playlist hydration + **`playlist_release_snapshots`**) lowers shared-queue contention for those APIs. **`GET /api/tracks/stats`** should use **`getVerifiedUserFromRequestWithRateLimit`** with the **read** rate-limit bucket — using the **write** bucket was a common ~1s+ hit on release modal / dock stats polling. **`GET /`** prerender time often includes footer **[`getPublicCommunityStats`](../../src/lib/public-stats.server.ts)** (**`cacheLife({ revalidate: 60 })`**).

**Agent triage (Cursor):** [`.cursor/mcp.json`](../../.cursor/mcp.json) uses project-scoped Sentry MCP — **`https://mcp.sentry.dev/mcp/filtermydiscogs/javascript-nextjs`**. Use **`search_issues`**, **`get_sentry_resource`**, **`find_dropped_events`**, and **`update_issue`** (resolve / ignore with a reason). Re-run **`find_dropped_events`** when charts look flat or quota is suspected.

**Weekly triage checklist:**
1. **Production backlog** — [`is:unresolved environment:production`](https://filtermydiscogs.sentry.io/issues/?project=javascript-nextjs&query=is%3Aunresolved+environment%3Aproduction) (Sentry MCP **`search_issues`** with the same query). Assign, fix, or close via PR **`Fixes JAVASCRIPT-NEXTJS-*`**.
2. **Regressions / new issues** since last release — filter **`release:`** to the latest production SHA or tag from **`make release`**.
3. **Ignored noise** — confirm still expected; delete stale ignores after grouping fixes ship (**`Module.T`** playback skips, **JAVASCRIPT-NEXTJS-1** extension noise).
4. **Playback embed skips** — auto skips: **Issues** via **`playback.skip_source`** / **`YouTube Embed Error …`**. User skip **Report** (unavailable-embed toast or **Report** on a public playlist/release track row): **User Feedback** (**`feedback_source:playback_skip_report`**) **and** an **Issues** audit event on the same skip fingerprint (**`playback.user_report`**, **`(user report)`** title); public share rows use **`playback.skip_source: public_report`** (**`Public playback video report`** headline). Triage inbox in [**User Feedback**](https://filtermydiscogs.sentry.io/feedback/?project=javascript-nextjs); correlate with embed skip stream in Issues. Header **Submit bug report**: **User Feedback** only (**`feedback_source:user_menu`**). Treat **`user.visible:true`** auto skips with rising users as product bugs, not quota noise.
5. **Discogs upstream** — **`auth/oauth-identity`** and **`/api/release/[id]`** should title **`Discogs API error: {status}`** on HTML/502 bodies (not raw **`<!DOCTYPE html>`**). Re-open if **D** / **F**-style titles regress.
6. **Feedback & bug reports** — [**User Feedback**](https://filtermydiscogs.sentry.io/feedback/?project=javascript-nextjs) inbox (**Submit bug report**, skip toast **Report**). Optional Issues view: [`issue.category:feedback`](https://filtermydiscogs.sentry.io/issues/?project=javascript-nextjs&query=issue.category%3Afeedback). Triage before ignoring — screenshots may attach on bug reports.
7. **Analytics (manual)** — after CWV code changes, confirm consent-granted **`webVital`** events in GTM from **`WebVitalsReporter`** ([#1199](https://github.com/wadehammes/filtermydiscogs/pull/1199)); Sentry does not receive these.

**Suggested alert rules (Alerts → Create Alert → Issues):**
1. **New production issue** — When: _A new issue is created_ · Filter: **`environment:production`** · Action: email or Slack · Name: `FMD production — new issue`.
2. **Production regression** — When: _The issue changes state from resolved to unresolved_ · Filter: **`environment:production`** · Action: same channel · Name: `FMD production — regression`.
3. **Optional spike** — When: _Issue frequency_ · Filter: **`environment:production`**, **`level:error`** · Threshold: e.g. **> 10 events in 1 hour** for the alert set · Tune after a week of baseline.

Wire Slack in **Settings → Integrations → Slack** so alerts land in a low-noise channel; keep preview/dev out of alert filters.
