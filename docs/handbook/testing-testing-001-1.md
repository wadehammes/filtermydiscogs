## Testing

Jest with **jsdom** ([`jest.config.ts`](../../jest.config.ts), [`.jest/setupTests.ts`](../../.jest/setupTests.ts)). Prefer **`screen`** and **`userEvent`** in specs.

### Non-negotiables (substantive work and agents)

**Agents:** read the one-page digest [non-negotiables.md](non-negotiables.md) first, then open the sections below only when you need depth. Do not paste or load this entire chapter up front.

Before you touch production code for a new behavior, regression fix, or extracted hook, confirm all of these:
1. **TDD** — Write or extend a **failing** spec first; run it and see red for the right reason; only then implement the smallest change to green. Do **not** implement hook/provider logic first and add specs at the end of the PR. See [Test-driven development (TDD)](#test-driven-development-tdd).
2. **Factories** — Domain data in specs, POs, **`e2e/helpers/`**, and Playwright MSW stubs comes from **[`src/tests/factories/`](../../src/tests/factories/)** plus shared builders under **[`src/tests/msw/`](../../src/tests/msw/)** (`releaseFactory`, `discogsTrackFactory`, `discogsReleaseJsonFactory`, `collectionFactory`, [`buildE2eCollectionReleases`](../../src/tests/msw/e2eCollectionData.ts), [`createE2eReleaseByIdHandler`](../../src/tests/msw/e2eReleaseHandlers.ts), …)—**not** hand-rolled `{ id: 1, title: "…" }` objects. Override with `.build({ … })` or factory presets only for fields the assertion names. See [Test data and factories](#test-data-and-factories) and **[factories.md](factories.md)**.
3. **Flat hook specs** — **`src/hooks/*.hook.spec.ts(x)`** uses **exactly one** top-level **`describe`** (usually the hook name). **Never nest** **`describe`** blocks; use long, outcome-focused **`it`** strings and module-level helpers (`buildHarness`, `createProps`, …) instead. See [Hook and feature spec checklist](#hook-and-feature-spec-checklist).
4. **Handbook conventions and patterns** — Every line of production and test code in the diff follows this chapter ([TypeScript](#typescript), [React / JSX](#react--jsx), [CSS and styling](#css-and-styling), [Testing](#testing), [Comments](#comments)) and the documented patterns in the routed chapters (e.g. arrow functions for app code, **`src/…`** imports through the module's public entry point such as **`src/lib/discogs-api-error`**, **`classNames`** / **`definedProps`**, factories, **`privateRouteJson`** on private routes). Reuse existing helpers and hooks instead of adding parallel logic, and match the surrounding file only where it does not contradict the handbook. Before finishing, re-read the diff against the routed chapters and fix deviations, including in code you added to files that predate a convention. Run **`pnpm lint:all`** (includes **`pnpm knip:ci`**) on substantive **`src/`** edits before the final reply — PO specs must stay wired (**`<Name>.component.spec.tsx`** imports **`<Name>.po.tsx`**; see [components.md → Testing](components.md#testing) watcher-toast split).
5. **Handbook post-work** — When the session changes **`src/`** behavior, layout helpers, or test conventions, update the matching **`docs/handbook/*.md`** chapter in the **same turn** (route via **[llms.md](llms.md)**). If no doc edit is needed, name the section headings you verified. Cursor **`stop`** runs [`.cursor/hooks/session-stop-checks.sh`](../../.cursor/hooks/session-stop-checks.sh) when git shows code changes without handbook edits (single combined follow-up).
6. **API mocks in POs** — Wire **`src/api/urls`** in **`.po.tsx`** only: default stubs in **`setupMocks()`**, scenario overrides in named PO methods (**`mockApiResponse`**, **`mockPendingApiResponse`**, [`setupFetchDiscogsReleaseMock`](../../src/tests/mocks/setupFetchDiscogsReleaseMock.ts), [`setupDefaultCrateApiMocks`](../../src/tests/mocks/setupDefaultCrateApiMocks.ts), …). **`.spec.tsx`** files call **`po.mock…()`** / **`po.setupMocks()`** — never import **`mockApiResponse`** or configure **`jest.mocked(api.*)`** in the spec. Hook/context specs without a PO still configure **`api.*`** in **`beforeEach`** at the top of the spec file (no PO to own mocks). See [Page object pattern → Mocks in POs](#page-object-pattern).
7. **RHF + Zod resolver types** — New or changed client form schemas must satisfy [React Hook Form + Zod typing (non-negotiable)](#react-hook-form--zod-typing-non-negotiable): **`pnpm tsc:ci`** with **`zodResolver`** and **`useForm<z.infer<typeof schema>>`** — no **`z.coerce.*`** on registered fields, no **`resolver`/`useForm` type casts. Run **`pnpm lint:all`** before finishing substantive form work.
8. **Stacked branches (`st` / gh-stack)** — All substantive work runs on **GitHub CLI stacks** into trunk **`staging`** via the **`st`** wrapper ([platform.md → Stacked pull requests](platform.md#stacked-pull-requests-st)) — not ad-hoc **`git checkout -b`** feature branches that ignore stack metadata. **Plan layers before the first code change** (foundation → consumers → tests/docs). **Single-layer** work: **`st init branch-name`** or **`st create`** on the bottom branch, commit there, **`st sync`**. **Multi-layer** work: commit the bottom concern, then **`st add next-branch`** for each dependent layer (one reviewable concern per branch). **Agents commit with [`scripts/git-commit.sh`](../../scripts/git-commit.sh)** (Cursor blocks raw **`git commit`**). Inspect with **`st view --json`**; rebase with **`st sync`**; open/update PRs with **`st ss --auto`**. Prefer **`st`** over bare **`gh stack`**. When adding work to an existing stack, **`st checkout`** the right layer — do not fork a parallel branch off **`staging`** with overlapping commits. Exempt only trivial drive-bys with no behavior change (obvious typo, comment-only) that land in a single commit without a feature branch.
