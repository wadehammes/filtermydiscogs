**Discogs request pacing:** [`discogs-oauth.service.ts`](../../src/services/discogs-oauth.service.ts) serializes outbound Discogs HTTP through [`discogs-request-throttle.ts`](../../src/lib/discogs-request-throttle.ts). Waiters use a **priority queue**: **`public_playlist_hydrate`**, **`api_release_batch`**, and unknown callers are **background**; **`api_collection`**, **`api_release`**, and **`public_release_page`** are **interactive** and dequeue first — see [`discogsThrottlePriority.constants.ts`](../../src/constants/discogsThrottlePriority.constants.ts). **`GET /api/collection`** sets **`api_collection`** via [`runWithDiscogsThrottleCaller`](../../src/lib/discogs-throttle-caller.ts) so collection pagination is not pinned behind a multi-id batch on the same instance. The throttle is **reentrancy-safe** (nested calls inside an active slot run immediately via **`AsyncLocalStorage`**) and rejects waiters after **`DISCOGS_THROTTLE_QUEUE_TIMEOUT_MS`** (default **30s**) so a stuck slot cannot pin an invocation for the full Fluid timeout — **`GET /api/release/[id]`** maps that **`DiscogsThrottleQueueError`** to **503** with **`Retry-After: 5`**, and **`useDiscogsReleaseQuery`** retries transient **503** / **429** like collection pagination. Colocated **[`discogs-request-throttle.spec.ts`](../../src/lib/discogs-request-throttle.spec.ts)** covers serialization, nested reentrancy, **`DiscogsThrottleQueueError`** on queue wait timeout, and **no`unhandledRejection`** when the timeout wins the slot race (queue wait uses **`Promise.race`** resolve-then-throw — not a rejecting race branch). Concurrent **GET**s for the same Discogs URL on one serverless instance share one in-flight OAuth request (deduped in **`discogs-oauth.service.ts`**); the Map cleanup **`finally`** chain **`.catch(() => undefined)`** so a handled upstream **404** / **5xx** on the shared promise does not also emit **`unhandledRejection`** to Sentry — regression in **[`discogs-oauth.service.spec.ts`](../../src/services/discogs-oauth.service.spec.ts)** (**when a deduped GET fails, does not emit an unhandled rejection from in-flight cleanup**). Prefer a single throttle boundary — do not wrap **`makeAuthenticatedRequest`** / **`makeConsumerRequest`** in another **`runThrottledDiscogsRequest`**. **`getIdentity`** (OAuth callback / session verify) uses **`skipThrottle: true`** so login never waits behind collection pacing. Post-login **`email`** backfill calls **`getUserProfile`** with **`skipThrottle: true`** as well ([`fetchDiscogsProfileEmailForLogin`](../../src/lib/discogs-profile-email.server.ts)); OAuth handlers **`await`** [`runLoginSideEffectsAfterLogin`](../../src/lib/runLoginSideEffectsAfterLogin.server.ts) (backfill, then welcome mail) before the redirect so serverless teardown cannot skip that work—without using the shared throttle queue. Every Discogs HTTP call goes through [`discogsFetch`](../../src/lib/discogs-fetch.ts) with **`AbortSignal.timeout`** (**`DISCOGS_FETCH_TIMEOUT_MS`**, default **20s**). After each Discogs response, [`discogs-rate-limit.ts`](../../src/lib/discogs-rate-limit.ts) reads **`X-Discogs-Ratelimit`**, **`X-Discogs-Ratelimit-Used`**, and **`X-Discogs-Ratelimit-Remaining`** and adjusts spacing before the next call on that serverless instance (faster when quota remains, slower when the window is nearly exhausted). When Discogs omits those headers, pacing falls back to **`DISCOGS_MIN_REQUEST_INTERVAL_MS`** (default **1000** ms; set **0** to disable the fallback floor).

**Collection pagination retries:** [`useDiscogsCollectionQuery`](../../src/hooks/queries/useDiscogsCollectionQuery.ts) retries transient **503** / **429** page fetches (up to 3 attempts) using **`Retry-After`** when present without pausing the infinite query for auth revalidation. [`useCollectionData`](../../src/hooks/useCollectionData.hook.ts) shows **Error loading collection** only after a releases page fetch has settled in failure. While that request is still in flight, [`useCollectionLoadState`](../../src/hooks/useCollectionData.hook.ts) stays loading, so a hard refresh does not flash the error heading for the length of the releases request. **`GET /api/collection`** forwards upstream Discogs **`Retry-After`** on **429** (via [`discogs-api-error.ts`](../../src/lib/discogs-api-error.ts)); when Discogs omits the header, the route falls back to **`DISCOGS_RATE_LIMIT_RETRY_AFTER_SECONDS`** (60).

**Connect with Discogs** reuses stored OAuth tokens when available (typical after logout on the same browser). When tokens remain, the landing page shows **Connect with {username}** and **Use a different Discogs account** (`force=1`) below both connect buttons.

Auth route handlers must not be CDN-cached; see [platform.md](platform.md) (**Private session API responses**) for **`privateRouteJson`**, **`privateRouteRedirect`**, and [`src/proxy.ts`](../../src/proxy.ts).

If collection fetches fail after login, verify OAuth tokens (re-login), consumer app settings, and Discogs API status before assuming an app bug.
