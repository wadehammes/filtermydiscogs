- **Real `QueryClient`**: **`TestProviders`** / [`createTestQueryClient`](../../src/tests/utils/testQueryClient.tsx) supply a real client so query hooks run; **do not** use the client as a test control surface—mock **`api.*`** instead.
- **Do mock**: External dependencies—**`src/api/urls`** via the **canonical mock pattern** above; configure responses with [`mockApiResponse`](../../src/tests/mocks/mockApiResponse.ts). **Endpoint / client HTTP specs** rely on global MSW setup, then **`mockFetchJsonOnce`** / **`mockFetchErrorOnce`** (or **`mockFetchOnce`**) from [`mswFetchTestHelpers`](../../src/tests/msw/mswFetchTestHelpers.ts); compare JSON bodies with **`jsonRoundTrip`** when factories include **`Date`** fields. **UI tests** still mock **`api.*`**, not **`fetch`**. Also mock auth cookies/services, `next/navigation`, **`IntersectionObserver`** (see **Infinite scroll / intersection observer** above), and similar.
- **Release open hover prefetch**: Shared hook behavior lives in [`useReleaseOpenHandler.hook.spec.tsx`](../../src/hooks/useReleaseOpenHandler.hook.spec.tsx). Collection/card surfaces use **`useReleaseCardOpenHandler`** (modal chunk + release query); **`ReleaseSimilarReleaseItem`** uses **`useReleaseOpenHandler`** alone (modal already open). Each card/list/table surface should also have a component spec using [`expectReleaseOpenPrefetchAfterHover`](../../src/tests/utils/expectReleaseOpenPrefetchOnHover.ts) with fake timers — see **`ReleaseCard`**, **`MobileReleaseCard`**, **`PublicReleaseCard`**, **`PublicMobileReleaseCard`**, **`ReleaseListItem`**, **`DashboardReleaseItem`**, **`MosaicItem`**, **`CrateDrawerReleaseItem`**, **`CrateDrawerReleases`**, **`ReleaseSimilarReleaseItem`**, **`CrateLayoutList`**, **`ReleasesTable`** (crate menu portaled out of clipped cells — **`ReleasesTable.spec.tsx`**), and **`ReleasesTableRowActions`**. **`ReleaseMiniPlayer`** uses the card hook—cover it via the hook spec, not by seeding or clearing **`QueryClient`** cache after playback. Row-style surfaces spread **`prefetchPointerProps`** on the row shell—not the inner open **`button`**—so hovering action columns still warms the modal; cover **both** the shell and a non-open target (remove / crate menu / style pill / title link). Pass **`onReleaseClick`** through **`CrateDrawerProvider`** in drawer integration specs ([`renderCrateDrawerTree`](../../src/components/CrateDrawer/crateDrawerTestRender.tsx) accepts optional **`onReleaseClick`**).
- **Authenticated tests + `CrateProvider`**: Default **`TestProviders`** includes **`CrateProvider`**, which runs **`useCratesQuery`** / **`useCrateQuery`** when **`authInitialState`** is authenticated and **`isCheckingAuth`** is false. If the test mocks **`src/api/urls`** but only stubs unrelated endpoints (e.g. collection fields), React Query will still call **`api.crates`** / **`api.crate`**—undefined mocks log **`Query data cannot be undefined`**. Call [`setupDefaultCrateApiMocks`](../../src/tests/mocks/setupDefaultCrateApiMocks.ts) in the PO **`setupMocks()`** or hook test **`beforeEach`** when default empty crate data is enough (also stubs **`api.releaseCrateMembership`** with empty **`crateIds`**, **`api.fetchTrackStats`** with empty **`stats`** for **`useTrackStatsQuery`**, **`api.playlists`** → **`[]`** via [`setupDefaultPlaylistApiMocks`](../../src/tests/mocks/setupDefaultPlaylistApiMocks.ts) for **`usePlaylistsQuery`** / track-key membership; stub **`api.playlist`** with **`mockApiResponse`** or **`mockPendingApiResponse`** when a test mounts **`usePlaylistQuery`** / **`useActivePlaylistDetail`** with an **`activePlaylistId`** ([**`PlaylistShareControls.po.tsx`**](../../src/components/PlaylistShareControls/PlaylistShareControls.po.tsx)), and **`api.discogsRelease`** / **`api.discogsReleaseBatch`** via [`setupFetchDiscogsReleaseMock`](../../src/tests/mocks/setupFetchDiscogsReleaseMock.ts) so **`useReleaseCrateMembershipQuery`**, **`useDiscogsReleaseQuery`**, and playback/modal prefetch do not hit undefined); override **`api.crate`** (see [`CrateSelector.po.tsx`](../../src/components/CrateSelector/CrateSelector.po.tsx)) when the test needs specific crate IDs or release counts—not by seeding **`QueryClient`** cache. Prefer **`jest.clearAllMocks()`** over **`jest.resetAllMocks()`** when re-applying **`setupDefaultCrateApiMocks`** / **`setupFetchDiscogsReleaseMock`** in the same **`beforeEach`**—**`resetAllMocks`** clears mock implementations globally for the shared **`api`** module and can break the next spec's release-detail stubs.
- **Viewport / `matchMedia`**: Layout breakpoints for JS live in [`layoutMediaQueries.ts`](../../src/constants/layoutMediaQueries.ts) — import those constants instead of raw query strings (see [Mobile-first breakpoints → JS layout queries](#mobile-first-breakpoints)). [`.jest/setupTests.ts`](../../.jest/setupTests.ts) calls [`setupMockMatchMedia`](../../src/tests/mocks/mockMatchMedia.mock.ts) each test (defaults to **`390px`** width — **`COMPACT_LAYOUT_MEDIA_QUERY`** matches, **`DESKTOP_LAYOUT_MEDIA_QUERY`** does not). Pass **`{ desktop: true }`** for **1024px** structural desktop (**`useCrateDrawer`**, **`CrateProvider`** login drawer tests); pass **`{ viewportWidthPx: 834 }`** (or another width) to exercise the tablet band without duplicating query strings — evaluation uses [`layoutMatchesMediaQueryAtWidth`](../../src/constants/layoutMediaQueries.ts). [`setupResponsiveDesktopMatchMedia.mock.ts`](../../src/tests/mocks/setupResponsiveDesktopMatchMedia.mock.ts) toggles desktop vs phone width for specs that subscribe to **`matchMedia`** changes. App code: [`useMediaQuery`](../../src/hooks/useMediaQuery.hook.ts) subscribes via **`useSyncExternalStore`** (same pattern as **`useCrateDrawer`**) so client **`matchMedia`** reads stay correct after SSR—do not reimplement with **`useState`** + **`useEffect`**.
