- **Modal / dialog layout** (controlled overlays such as **`ConfirmDialog`**, **`ScrollModal`**, **`NoteEditDialog`**, **`EditCrateDialog`**): portaled dialogs use **[Base UI](https://base-ui.com/react/overview/quick-start)** via **[`AppDialog`](../../src/components/AppDialog/AppDialog.component.tsx)** — **`Dialog.Root`** with **`modal="trap-focus"`** (focus trap only; no Base UI document scroll lock) + **`Dialog.Portal`** / **`Dialog.Backdrop`** / **`Dialog.Popup`**, styled with [`base-ui-portal.module.css`](../../src/styles/modules/base-ui-portal.module.css) and [`modal-dialog.module.css`](../../src/styles/modules/modal-dialog.module.css). **`aboveBottomDrawer`** skips the playback overlay portal and mounts on **`document.body`** (**`.backdropAboveDrawer`** / **`.popupAboveDrawer`**, **`calc(var(--z-10-bottom-drawer) + 2)`** / **`+ 3`**) so the dialog covers mobile bottom drawers — **[`SentryUserFeedbackDialog`](../../src/components/SentryUserFeedbackDialog/SentryUserFeedbackDialog.component.tsx)**. Compact form/confirm dialogs use **[`FormDialog`](../../src/components/FormDialog/FormDialog.component.tsx)** on top of **`AppDialog`**: shared **`.panel`** chrome (**`backdroppanel`**, **`25rem`** default / **`28rem`** via **`panelWidth="md"`**), inner **`.content`** flex column (**`gap: var(--space-6)`** between header, body, footer — required because **`AppDialog`** wraps children in **`OverlayStack`**, so panel-level **`gap`** does not reach sections), **`.header`** groups **`Dialog.Title`** + optional **`Dialog.Description`** (**`gap: var(--space-2)`** — Base UI renders **`Dialog.Description`** as **`<p>`**; pass only phrasing-friendly nodes—**`<span>`** with block/line-clamp in module CSS, not nested **`<p>`** / **`<div>`**, to avoid hydration warnings). **`.body`** for fields (**`gap: var(--space-4)`**), **`.footer`** for actions. Optional **`headerClassName`**, **`descriptionClassName`**, and **`contentClassName`** tighten one-off layouts without changing global **`FormDialog`** spacing (**[`TrackYoutubeOverrideDialog`](../../src/components/TrackYoutubeOverrideDialog/TrackYoutubeOverrideDialog.component.tsx)** stacks release + track lines as **`<span>`** under **`.dialogDescription`**). Use **`FormDialog.Field`**, **`FormDialog.CheckboxField`**, and exported **`formDialogStyles.label`**; do not recompose title/description/panel spacing in feature modules beyond those hooks. Native **`<input>`** / **`<textarea>`** inside **`FormDialog`** use **[`modal-form-field.module.css`](../../src/styles/modules/modal-form-field.module.css)** — see **FormDialog native fields** under **Form validation styling** below. Consumers: **`CreateCrateDialog`**, **`SaveFilterViewDialog`**, **`ConfirmDialog`**, **`EditCrateDialog`**, **`PlaybackSkipReportDialog`**. **`AppDialog`** and **[`BottomDrawer`](../../src/components/BottomDrawer/BottomDrawer.component.tsx)** call **`usePlaybackPageScrollLock`** from **[`PlaybackPageShell.context.tsx`](../../src/components/PlaybackPageShell/PlaybackPageShell.context.tsx)** so the playback-page scroll root is locked while open on **`PlaybackPageShell`** pages (no-op elsewhere). **`.shell`** is the shared **`1px`** panel chrome (background, border, radius) plus **`--shadow-modal`**. **`ScrollModal`** merges **`styles.modal`** into **`panelClassName`** on the popup — width via **`min(calc(100vw - var(--scroll-modal-horizontal-inset, var(--space-8))), var(--scroll-modal-max-width, 42rem))`** (set **`--scroll-modal-max-width`** on extra classes like **`ReleaseModal`** **`modalWide`** (**`68rem`**) only, not on **`.modal`** itself). Popups cap at **`90svh`** on mobile and **`90dvh`** at **`768px+`** ([`ScrollModal.module.css`](../../src/components/ScrollModal/ScrollModal.module.css), [`modal-dialog.module.css`](../../src/styles/modules/modal-dialog.module.css)). When **`AppDialog`** portals into **`[data-playback-overlay-portal]`**, **`popupModalShell`** applies the same width/max-width **`min(calc(100% - …), var(--scroll-modal-max-width))`** on the popup (**`100%`** of the workspace portal, not **`100vw`** — do not use **`width: auto`**) and height caps with **`calc(100% - var(--space-8))`** of the workspace portal (not **`90svh`** / **`90dvh`** — those use the full viewport and clip under the sticky header when the shell is short). Body-portaled **`ScrollModal`** / **`popupModal`** on non-shell routes still use **`90svh`** / **`90dvh`** ([`ScrollModal.module.css`](../../src/components/ScrollModal/ScrollModal.module.css)). Compose **`AppDialog`** with **`Dialog.Title`** / **`Dialog.Description`** for labelled content; pass **`backdropVariant="modal"`** for crate/note editors and release modals. Tests: popup **`data-testid`** is the dialog root; backdrop dismiss uses **`${testId}-backdrop`**. Scrollable card modals use **`ScrollModal`** with one outer **`.shell`** border; **`.header`** gets a single **`border-bottom`** divider (not per-row borders on **[`ModalToolbar`](../../src/components/ModalToolbar/ModalToolbar.component.tsx)** or subheaders). Release heroes pass crate/Discogs actions in the toolbar; duplicates modal passes **`title`** plus description text below the toolbar. Filter dropdowns (**`Select`**, **`AutocompleteSelect`**) and inline menus inside overlays use Base UI **`Portal`** with **`container`** from **`usePortaledOverlayContainer`** (see **`OverlayStack`**). Header/crate action menus use Base UI **`Menu`** (`Menu.Root` / `Trigger` / `Portal` / `Positioner` / `Popup` / `Item` / `LinkItem` / `Separator`) with **`modal={false}`** and **`[data-highlighted]`** on items — see **Inline popover menus** below.
