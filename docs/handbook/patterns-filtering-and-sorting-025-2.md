UI components (`FiltersBar`, [`FiltersDrawer`](../../src/components/FiltersDrawer/FiltersDrawer.component.tsx), release cards, [`ReleasesTable`](../../src/components/ReleasesTable/ReleasesTable.component.tsx)) dispatch filter actions through **`useFiltersDispatch()`** and read state via **`useFilterAtoms`** hooks; **`useFilteredReleases()`** drives the visible grid (one random release in random mode, otherwise the sorted filtered list); **`useSortedFilteredReleases()`** exposes the full sorted match set for mosaic input and random re-pick; **`useFacetOptions()`** supplies facet dropdown choices. Dashboard/analytics read the same list via **`useAllReleases()`**. **[`FilterViewsMenu`](../../src/components/FilterViewsMenu/FilterViewsMenu.component.tsx)** leads desktop **`FiltersBar`** and mobile **`FiltersDrawer`**: saved **views** (named filter snapshots in **`User.preferences.filterViews`**), **Save current view…** (disabled when there are no applied filters — search or facet selections, sort alone does not count — or when session filters exactly match an existing saved view), **Manage in Settings**, and **Reset filters** via Base UI **`Menu`**. Saved views in the menu toggle like radio items: pick one to apply its snapshot; click the active view again to clear filters and deselect. The trigger leads with a **bookmark** icon (**outline** by default, **filled** when a saved view matches) on a primary-tinted control with a **left accent stripe** (distinct from facet dropdowns), then **Views** or the matching saved view name when session filters equal a stored snapshot (derived; long names ellipsize with a **`title`** tooltip for the full name). **`variant="bar"`** (desktop) or **`variant="drawer"`** (mobile, full-width trigger); the bar variant closes the portaled menu when the viewport drops below **`1024px`** via **`useCloseMenuWhenFiltersBarHidden`**. **[`SaveFilterViewDialog`](../../src/components/SaveFilterViewDialog/SaveFilterViewDialog.component.tsx)** names views when saving from the menu and when renaming in Settings (**`mode: "save" | "rename"`**). **[`useFilterViews`](../../src/hooks/useFilterViews.hook.ts)** reads **`sessionFiltersAtom`**, derives **`canSaveCurrentView`** / **`matchingView`** via [`filterViews.ts`](../../src/utils/filterViews.ts), and applies snapshots through **`FiltersActionTypes.ApplySessionFilters`**. **`FiltersBar`** and **`FiltersDrawer`** share the same filter control order after the views menu: **Search** → **Genre & Style** (+ **Match** when one or more selected) → **Format Type** (+ **Match**) → **Release Year** (+ **Match**) → **[`CollectionSortControls`](../../src/components/CollectionSortControls/CollectionSortControls.component.tsx)** (segmented **Sort by** + chevron join + **Then by**, secondary defaults to **None** — **Then by** is a tie-breaker when the primary field matches, not a second full sort pass (for **date added** primary sorts with an active **Then by**, ties are releases on the same **UTC calendar day**); [`SORTING_OPTIONS`](../../src/constants/sorting.ts) **`shortName`** on the closed trigger (e.g. **Date Added ↓**), open list **`menuField`** + muted **`menuOrder`** (**`Date Added`** + **`newest`**, grouped sections) with **`aria-label`** on each option from the full label (so assistive tech and Playwright hear **`Date Added newest`**, not concatenated child text), **`name`** in saved-view summaries (**`Date Added · newest`**); [`getThenBySortSelectOptions`](../../src/utils/collectionSortOptions.ts) omits every sort on the same field as the primary (**`menuGroup`** — both directions, e.g. no **Date Added oldest** when primary is **Date Added newest**) and normalizes incompatible picks to **`SortSecondaryValues.None`**). On mobile, filters open from the header filter control into **`FiltersDrawer`** (same filter atoms as desktop **`FiltersBar`**); the drawer title and footer show the applied filter count via **`useAppliedFilterCount()`** / [`getAppliedFilterCount.ts`](../../src/utils/getAppliedFilterCount.ts) (search plus each multi-select dimension: genre/style, year, format — sort is excluded). Multi-select facet filters in the drawer use **`DrawerFacetFilter`** in [`FiltersDrawer.component.tsx`](../../src/components/FiltersDrawer/FiltersDrawer.component.tsx): a visible **`facetLabel`**, then **`AutocompleteSelect`**, **`FilterMatchOperatorSelect`**, and an external **Clear** button on one row (Match before Clear; Clear only when selections exist — see [`FiltersDrawer.module.css`](../../src/components/FiltersDrawer/FiltersDrawer.module.css)); sort uses **`CollectionSortControls`**: desktop **`FiltersBar`** keeps compact triggers inside one bordered **`sortFilterGroup`** (no visible labels); mobile **`FiltersDrawer`** passes **`showLabel`**, which renders **`sortLabelRow`** / **`sortFieldLabel`** (**`field-label.module.css`**) **above** the bordered group (aligned with each half + chevron join), not **`Select`** **`showLabel`** inside the segment — comboboxes still expose **`aria-label`** from the **`label`** prop; match stays on **`FilterMatchOperatorSelect`**. The mobile header filter icon shows a numeric badge when filters are active and uses **`var(--primary)`** (theme primary) on the icon via **`.active`** / **`.filterIconActive`**, matching the adjacent random-mode control. Filter changes apply live (same atoms as desktop **`FiltersBar`**) and closing the drawer does not revert them. The filter control stays hidden until **`allReleasesLoaded`** (same gate as desktop **`FiltersBar`**). **`SearchBar`**, **`Select`**, and **`AutocompleteSelect`** share aligned mobile tap targets (**`--touch-target-min`**) in the drawer. **`SearchBar`** flushes a pending debounced query on unmount so closing the drawer does not drop in-progress search text.
