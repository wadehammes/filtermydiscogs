## Authentication flow

1. **Start OAuth**: client navigates to **`GET /api/auth/discogs`**, which reuses stored OAuth tokens when present (no Discogs authorize screen) or starts a fresh OAuth flow. Pass **`?force=1`** to clear tokens and require a new Discogs authorization (e.g. **Use a different Discogs account** on the landing page).
2. **Callback**: **`GET /api/auth/callback`** exchanges verifier for access token, calls **`getIdentity`**, sets cookies, redirects to **`/collection?auth=success`**.
3. **Session check**: **`authQueryOptions()`** + **`useAuthQuery`** ([`src/hooks/queries/useAuthQuery.ts`](../../src/hooks/queries/useAuthQuery.ts)) call **`checkAuthStatus`** in [`src/services/auth.service.ts`](../../src/services/auth.service.ts) (wraps **`checkAuth`** → **`/api/auth/check`**) with **`refetchOnMount: "always"`**. Fetch/network failures resolve to unauthenticated (the query does not enter error state); when a **`discogs_username`** display cookie is still present, **`checkAuthStatus`** retries **`checkAuth`** once before giving up. **`AuthProvider`** keeps **`isCheckingAuth`** true until the **initial** auth query resolves (first **`isPending`** → false), including OAuth completion and the no-session case. Later **`refetchOnMount`** revalidations usually do **not** block the app, except when a **`discogs_username`** cookie is still present while React Query holds an unauthenticated snapshot (see home toast note below). It then derives **`isAuthenticated`**, **`username`**, **`userId`**, **`avatarUrl`**, and **`rateLimited`**. Collection queries ([`useCollectionData`](../../src/hooks/useCollectionData.hook.ts)) start once auth is ready and IndexedDB prep finishes (**`useCollectionCacheReady`**); they do **not** wait for background auth refetch. A validated cache hit hydrates React Query before the query enables, so refresh reuses cached pages instead of re-fetching the full collection. Crate queries stay disabled while **`isCheckingAuth`** or **`rateLimited`**. When Discogs is rate-limited, the check may return cookie-based identity with **`rateLimited: true`**; [`getAuthQueryRefetchInterval`](../../src/utils/authQueryPolling.ts) refetches every **60s** (and on window focus) until verification succeeds. When **`discogsUnavailable: true`** (upstream **502** on check), **`authCheckRefetchIntervalMs`** / **`authCheckRefetchOnWindowFocus`** in [`authQueryPolling.ts`](../../src/utils/authQueryPolling.ts) refetch every **120s** and skip window-focus refetch until the outage clears—those later refetches do **not** flip **`isCheckingAuth`**. If a collection page returns **401**, [`useDiscogsCollectionQuery`](../../src/hooks/queries/useDiscogsCollectionQuery.ts) rechecks auth once (`retry: false` on that query): still authenticated → retry the page once; session gone → update the auth query so **`AuthProvider`** runs **`clearUserScopedQueries`** ([`user-scoped-queries.ts`](../../src/lib/user-scoped-queries.ts) — drops user/collection/crate cache keys but keeps **`auth`**, **`publicCrate`**, and **`buildVersion`**) (never **`queryClient.clear()`**, which would wipe the auth query and refetch forever under **`refetchOnMount: "always"`**) and protected routes redirect home instead of showing a stuck “Not authenticated” error under a logged-in header. On OAuth success, **`refetch`** runs after **`auth=success`**; **`clearUserScopedQueries`** runs only when the session **`userId`** changes (account switch), not on quick re-login after logout (logout already cleared scoped cache; **`CollectionCachePrepGate`** / [`prepareCollectionQueryFromCache`](../../src/utils/collectionCacheSync.ts) can hydrate IndexedDB into React Query without an immediate wipe). **`/collection`** route **`loading.tsx`**, page **`Suspense`**, and auth-check loading in **`ReleasesClient`** use **[`ReleasesPageLoading`](../../src/components/ReleasesClient/ReleasesPageLoading.component.tsx)** — same **`CollectionPlaybackPageShell`** + **`mainContent`** / **`releases-main`** container as **`ReleasesClient`** so the grid skeleton uses multi-column desktop layout (not a single full-width card), without the full-page **`PageLoader`** spinner; **`CrateProvider`** waits until **`isCheckingAuth`** is false before enabling crate queries (avoids a race with that cache clear), resets **`activeCrateId`** when **`userId`** changes, calls **`resetDrawer()`** on first login (null → user id) so the crate drawer follows viewport defaults, **`closeDrawer()`** on logout or user switch, and logs out if crate **`user_id`** does not match the session (**`clearUserScopedQueries`**, not **`queryClient.clear()`**, before **`logout()`**). Context reducer state is UI-only (**`isLoading`**, **`isLoggingOut`**, OAuth URL **`error`**). **`isLoading`** is reserved for an in-flight OAuth redirect after **Connect with Discogs**. The home page renders the marketing landing during **`isCheckingAuth`** and shows a loading toast on **`/`** via **[`AuthCheckingToast`](../../src/components/AuthCheckingToast/AuthCheckingToast.component.tsx)** (“Checking session…”). When already authenticated, **`Login`** renders a minimal **`aria-busy`** shell until **`router.replace("/collection")`** runs. **`AuthProvider`** snapshots **`discogs_username`** from **`getUsernameFromCookies()`** when an auth refetch starts so **`isCheckingAuth`** can stay true until revalidation finishes when React Query still holds an unauthenticated snapshot—protected routes do not bounce to **`/`** mid-check.
