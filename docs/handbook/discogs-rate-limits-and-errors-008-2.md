**Release detail batching:** **`POST /api/release/batch`** accepts `{ ids: string[] }` (max **`RELEASE_BATCH_MAX_IDS`**, 12), fetches each release from Discogs through **[`fetchDiscogsReleaseRecordsSequential`](../../src/lib/fetchDiscogsReleaseRecordsSequential.server.ts)** (one **`runThrottledDiscogsRequest`** per id with caller **`api_release_batch`** — **background** queue priority so **`GET /api/collection`** can dequeue between ids; stops when **`RELEASE_BATCH_MAX_DURATION_MS`** (90s) elapses and returns partial maps; **`DiscogsThrottleQueueError`** propagates as **503** like single-id GET) (shared with public playlist SSR hydration when a track instance has no **`crate_releases`** or **`playlist_release_snapshots`** row — see **[`hydratePublicPlaylistReleases`](../../src/lib/public-playlist-discogs.server.ts)** and **[`loadPlaylistReleaseSnapshots`](../../src/lib/playlist-release-snapshot.server.ts)**; fetches every missing id in track order, skipping instances that already have snapshots), and returns `{ releases: Record<id, detail> }` (invalid or failed ids are omitted). Client code should hydrate per-release React Query cache via **[`fetchDiscogsReleaseDetailsIntoCache`](../../src/utils/discogsReleaseBatchCache.ts)** (chunks ids, calls **`api.discogsReleaseBatch`**, refetches uncached ids after partial server batches) — **[`useHydrateDiscogsReleaseDetails`](../../src/hooks/useHydrateDiscogsReleaseDetails.hook.ts)** (dashboard Top Tracks, public playlist merge), **[`similarReleaseQueue.ts`](../../src/utils/similarReleaseQueue.ts)**, and similar-release playback wrap that helper with **`discogsTransientProxyShouldRetry`** (same cap as **`useDiscogsReleaseQuery`**) for transient **503** / **429** — not parallel **`useQueries`** of **`GET /api/release/[id]`** for the same id set.

**Auth route rate limits:** [`enforceAuthRouteIpRateLimit`](../../src/lib/auth-route-guards.ts) applies per-IP limits to all **`/api/auth/*`** handlers (default **60** requests / 60s via **`AUTH_ROUTE_RATE_LIMIT_*`**). **`GET /api/crates/public/[id]`** uses **`PUBLIC_CRATE_RATE_LIMIT_*`** (default **120** / 60s). Limits are in-memory per serverless instance; pair with Vercel WAF rules for global abuse if needed.

**App DB rate limits:** Verified-user routes call [`getVerifiedUserFromRequestWithRateLimit`](../../src/lib/api-helpers.ts) with separate read/write buckets ([`rate-limit.ts`](../../src/lib/rate-limit.ts) — **`DB_RATE_LIMIT_*`**, default **60** writes/min). Crate layout saves and gig-packing toggles count as writes; **`useSetReleasePackedInCrateMutation`** and **`useUpdateCrateLayoutMutation`** retry transient **429** using **`Retry-After`** when the API returns [`ApiFetchError`](../../src/api/apiFetchError.ts).
