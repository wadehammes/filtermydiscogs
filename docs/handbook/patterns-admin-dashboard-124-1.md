## Admin dashboard

**`/admin`** is gated by **`ADMIN_USER_ID`** env matching the `discogs_user_id` cookie. Stats come from **`/api/admin/stats`** via **`useAdminStatsQuery`** ([`getAdminStats`](../../src/lib/admin-stats.server.ts) — consolidated SQL + **`use cache`** / **`cacheLife({ revalidate: 60 })`**). User counts and growth charts use **`User.created_at`** (not first-crate heuristics). The dashboard also tracks crate feature adoption: public crates (`private: false`), gig packing (`packed_enabled`, **`found_at`** on releases), crate notes, and set markers (`CrateSetMarker`), with monthly growth for public crates and set markers. **Account contact** aggregates live in **`stats.accountContact`** ([`fetchAdminAccountContactStats`](../../src/lib/admin-stats.server.ts)): non-empty **`User.email`**, **`marketing_emails_opt_in`**, and **`welcome_email_sent`** counts (Postgres columns — not **`preferences`** JSON). The **Usage** section renders them ahead of preference stats.

**Account preferences** aggregates live in **`stats.accountPreferences`** ([`fetchAdminAccountPreferencesStats`](../../src/lib/admin-stats.server.ts)): **`persistFilters`** enabled count (missing key defaults to **`true`**, matching [`parseUserPreferences`](../../src/lib/user-preferences.server.ts)), **`analyticsConsent`** enabled / disabled / unset, theme breakdown (**`preferences.theme`**, invalid values counted as **`light`**), default collection view (**`preferences.view.currentView`**, invalid values counted as **`card`**), default collection side panel (**`preferences.defaultCollectionSidePanel`**, missing or invalid values counted as **`crates`**), and saved filter views (**`preferences.filterViews`**: users with ≥1 view, total saved views, per-user count buckets **0 / 1 / 2–5 / 6+** — primary adoption signal; do not rely on apply/rename/clear analytics events). **Playback defaults** count **`autoPlayOnQueueAdd`** (missing key counts as **`true`**) and **`extendQueueWithSimilarReleases`** (missing key counts as **`false`**).

**Playlists** — **`stats.overview.playlists`** ([`getAdminStats`](../../src/lib/admin-stats.server.ts)): total **`Playlist`** rows, total **`PlaylistTrack`** rows, distinct users with ≥1 playlist, public playlists (**`private: false`**), and sums of **`public_view_count`** / **`public_play_count`**. New playlists in 7d/30d live on **`stats.recentActivity.*.newPlaylists`**. **[`AdminDashboardGate`](../../src/components/AdminDashboard/AdminDashboardGate.server.tsx)** passes **`deployment.playlistsFeatureEnabled`** from [`getPlaylistsFeatureEnabled`](../../src/lib/playlistsFeature.server.ts) into **[`AdminDashboardClient`](../../src/components/AdminDashboard/AdminDashboardClient.component.tsx)** (this deployment’s effective flag, including local overrides). The **Playlists** section shows that on/off state in one line and points at **Lookup** for the username and Discogs user ID used by Vercel Flags (**`user.username`**, **`user.discogsUserId`**, **`user.id`**). **[`AdminHero`](../../src/components/AdminDashboard/AdminHero.component.tsx)** includes platform playlist count in the hero tagline.

**Engagement** aggregates live in **`stats.engagement`** ([`fetchAdminEngagementStats`](../../src/lib/admin-stats.server.ts)): **seen users** (accounts with **`User.last_seen_at`** in the window — login plus the 15-minute touch in [`user.server.ts`](../../src/lib/user.server.ts)), **active users** (distinct accounts with **`Crate.updated_at`** or **`CrateRelease.added_at`** in the window), **returning users** (**`last_seen_at`** in the window and **`created_at`** before it — opened the app again, not a preference save), a **90-day daily time series** of those returning counts for **7d / 30d / 90d windows** ([`returningUsersTimeSeries`](../../src/types/dashboard.types.ts), rendered by **[`ReturningUsersChart`](../../src/components/AdminDashboard/ReturningUsersChart.component.tsx)** with a window **`Select`**), **signup funnel** (accounts with zero crates vs at least one, plus signups in the last 30 days from **`recentActivity`**), **averages** (crates per active user, releases per crate), and **stale accounts** (has crates but no crate/release activity in 90 days). The **People** section also shows power users and monthly new-account growth.

**Playback stats** (**`UserTrack`**) live in **`stats.userTracks`** ([`fetchAdminUserTrackStats`](../../src/lib/admin-user-track-stats.server.ts) → [`FetchAdminUserTrackStatsResult`](../../src/types/dashboard.types.ts)): platform totals (**`play_count`** / **`listen_count`** sums, distinct users with rows, YouTube override counts), monthly growth of new **`user_tracks`** rows, top users by summed plays/listens, and top per-user track rows by **`play_count`** / **`listen_count`**. Window metrics (**new track rows** via **`first_played_at`**, **active playback users** via **`last_played_at`** / **`last_listened_at`**) are returned as **`playbackActivity`** from the fetch helper and merged into **`stats.recentActivity`** only (not duplicated on **`stats.userTracks`**). Override counting uses **`userTrackHasYoutubeOverrideWhere`** ([`user-track.server.ts`](../../src/lib/user-track.server.ts); admin SQL uses **`btrim(youtube_id) <> ''`**). **[`AdminDashboardClient`](../../src/components/AdminDashboard/AdminDashboardClient.component.tsx)** renders a **Listening** section (stat grid + 7d/30d window table + **`renderTopUserLeaderboard`** / **`renderTopUserTrackLeaderboard`** over **`AdminMetricTable`**; track attribution uses **`tableUserLinkInline`** + **`tableTrackAttribution`**, not block **`tableUserLink`**) and a **Playback track rows** growth chart. **Power users** reuses **`renderTopUserLeaderboard`** inside **People**.
