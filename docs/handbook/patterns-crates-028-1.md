## Crates

- **Client**: `CrateProvider` + **`useCrateMutations`** talk to **`/api/crates`** via **`api.*`** in [`src/api/urls.ts`](../../src/api/urls.ts). Write helpers in [`src/api/endpoints/crates.ts`](../../src/api/endpoints/crates.ts) parse error JSON through **`throwCrateApiError`** (**`ApiFetchError`**, including **`POST /api/crates`** **409** duplicate-name bodies). Components call **`useCrate()`** actions (`updateCrate`, `updateCrateLayout`, `createCrate`, …) — not mutation hooks directly (including owner **`CrateLayoutList`** DnD saves). **`useCrateProvider`** stores the user’s crate selection in local state and exposes **`activeCrateId`** as **`resolveActiveCrateId({ crates, activeCrateId })`** (derived from the crate list — no **`useEffect`** sync when the list refetches). Read-only crate state that changes often (active crate release ids) is available on **`useCrateState()`**; stable actions on **`useCrateActions()`** — use the split hooks when a subtree should not re-render on unrelated crate state (e.g. **`ReleasesGrid`** passes **`inActiveCrate`** into memoized release cards). Mutation **`onError`** handlers in **`useCrateMutations`** show toasts via [`src/utils/toast.ts`](../../src/utils/toast.ts) and roll back optimistic cache updates; **`CreateCrateDialog`** submit handlers **`catch`** failed **`mutateAsync`** calls (toast already shown in **`onError`**) so dialogs stay open and rejections are not unhandled — [`CrateSelector`](../../src/components/CrateSelector/CrateSelector.component.tsx) and [`useReleaseCrateMenuController`](../../src/hooks/useReleaseCrateMenuController.hook.ts). **Add/remove** mutations share **`applyAddReleaseToCrateCache`** / **`applyRemoveReleaseFromCrateCache`**: update list **`releaseCount`** optimistically only when the release is not already present (add) or was present (remove); when that crate's detail query is **not** already cached, **invalidate** detail instead of seeding a one-release stub (avoids count vs drawer list mismatch after **`ReleaseCrateMenu`** adds to a non-active crate). When detail **is** cached, prepend/remove rows in place. After the collection finishes loading, **`useCollectionData`** runs **one** automatic **`POST /api/crates/sync`** per username visit (including after a validated IndexedDB cache hit); failures — including **429** rate limits — do **not** retry until the username changes or the user runs manual sync in Settings (**`useCrateCollectionSync`** — blocked **400**s emit consent-gated **`crateSyncBlocked`** via **`trackCrateSyncBlockedFromError`** in [`productAnalyticsEvents.ts`](../../src/analytics/productAnalyticsEvents.ts), not Sentry). Crate list (`useCratesQuery`) and active crate releases (`useCrateQuery`) are separate queries — both stay disabled while **`isCheckingAuth`** or **`rateLimited`**; on first login, **`CrateProvider`** invalidates both after **`userId`** arrives, re-selects the default crate, and **`invalidateQueries`** active crate detail when list **`releaseCount`** and loaded release rows **disagree** (skipping while crate detail is loading/fetching or add/remove/membership mutations are pending).
